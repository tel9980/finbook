# v1.8.31 —— 发版别再等 40 分钟

这一版没有新功能，只改一件事：**变异测试从串行跑改成 4 片并行**。

## 为什么值得单独发一版

变异测试（逐条把代码改坏、要求对应测试必须报红）是这个仓库最贵的一道门禁。58 条串行
跑一遍要 **35–40 分钟**，每次发版都得等这一趟，`timeout` 也已经贴到 60 分钟边缘 ——
再往上加几条就会变成「超时即失败」，而超时和真失败混在一起最难查。

现在切成 4 片：

```
Mutation shard 1/4   15 条
Mutation shard 2/4   15 条
Mutation shard 3/4   14 条
Mutation shard 4/4   14 条
```

单 job 约 10 分钟，四片同时跑，**发版等待从 ~40 分钟降到 ~11 分钟**。

## 切法：按下标取模

`node tools/mutate-rust.js --shard 2/4` 取 `MUT.filter((_, k) => k % N === i - 1)`。

好处是这三条性质**自动成立**，不用人工维护分组表：

- 交集为空（每个下标只落一片）
- 并集为全（每个下标必落一片）
- 以后加减变异不用重新分组

实测覆盖：`15 + 15 + 14 + 14 = 58`，`覆盖完整: True`（不是均分，58÷4 本来就余 2）。
按「⑤ 开头归第 1 片」那种分法是错的：改个名字就漏。

## 分片引入的三个新坑（都做了防护）

| 坑 | 后果 | 防护 |
|----|------|------|
| 空分片 | `for` 一次不跑 → 打印「全部 0 个变异都被拦下」→ exit 0，**一片绿但一条没跑** | `RUN.length === 0` 直接 exit 2 |
| 片数与分母写在两处 | `matrix.shard: [1,2,3,4]` 与 `--shard ${{ matrix.shard }}/4` 只改一处 → 某些变异静默不跑，CI 照样绿 | `check-ci.js` 核对两处一致 |
| `--list` 混进标题行 | 分片时脚本打印「分片 2/4：…」，而 `check-ci.js` 用 `--list` 做 `JSON.parse` → 解析失败 | `--list` 时不打标题，且 `--list --shard i/N` 输出该分片清单 |

第三条顺带变成一个能力：「分片是否覆盖全、是否互斥」现在可以**机械验证**，不用肉眼看取模。

## 这两条防护自己也验过

- 把 `/4` 改成 `/5` → `FAIL 分片数不一致：matrix.shard 有 4 片（1,2,3,4），但 run 里写的是 /5`
- 把 `[1,2,3,4]` 改成 `[1,2,3]` → `FAIL 分片数不一致：matrix.shard 有 3 片，但 run 里写的是 /4`
- 本机实跑 `--shard 3/4`：14 条全部拦下，源码自动还原（`git status` 无残留）

## 分片之后立刻暴露：三条「假守卫」

分片第一次跑，四片里有三片红。原因不是分片本身——而是**三条变异一直指向请求根本
走不到的代码**：

| 变异 | 它改的那行 | 为什么拦不住 |
|------|-----------|--------------|
| ⑧ 提示改成原来那句「损益发生额均为零」 | 引擎里「净发生额均为 0」的话术 | handlers 在**调用引擎之前**已经查过本期结转凭证，直接返回「已结转过」，那句话永远执行不到 |
| ⑧ 恢复「导入数据有误」万能前缀 | `impl From<FinError> for AppError` | 记账/结转的校验都在 handlers 里做完，这条全局转换**没有一条 HTTP 路径走到** |
| 设备绑定不迁移旧库 | `realm` 迁移里的 `let moved: usize = 0` | 它只丢掉了行数，SQL 照样执行；而且原测试用的是全新 realm，旧库形态压根不存在 |

三条都表现为「1 passed —— 测试没在守它该守的」。它们在**串行跑的那版 CI 里曾经红过，
也曾经绿过**——因为其中两条依赖时序或无关路径，绿的时候没人知道它是假的。

这正是这个仓库最忌讳的失效模式：**看着在守，实际没守**。修法是换靶子而不是改判据：

- 结转那条改成把「已结转过」的守卫关掉（`if !carried.is_empty() && …` → `if false`），
  这样请求一定会落到提示上；
- 导入前缀那条改成直接测转换本身：新增 `state::tests::engine_error_keeps_its_own_wording`，
  断言 `FinError` 转成 400 后**保留引擎原话、且不带「导入数据有误」**；
- 设备迁移那条改成让 `SELECT` 一行都选不出来（`WHERE device_id <> ''` → `WHERE 1 = 0`），
  并新增 `realm::tests::legacy_single_column_device_binding_is_migrated`：构造
  「单列有值、集合表空」的旧库，重开必须搬过去，断言 `bound_device_count == 1`
  （只看 `device_allowed` 不行——一台都没绑时它是放行的）。

改完三条本地全部 `PASS 拦下了`。测试总数 969 → **972**，变异仍是 58 条。

## `fail-fast: false` 是有意的

一片红就取消另外三片，会掩盖「到底哪几条没守住」——而变异测试的价值恰恰是看全貌。
宁可多花几分钟，也要一次拿到完整清单。

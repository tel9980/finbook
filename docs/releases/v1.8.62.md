# v1.8.62 —— 多维损益搬上 Web，警告清零

这一版做了三件事：把「多维损益」补到 Web 端（桌面端一直有）、把这张表的两套算法合成一套
顺手修掉「未分配行会凭空消失」的 bug、把积了两百多条的编译警告清到 0。

## 一、桌面端「未分配」行会凭空消失

多维损益原本有两套算法：`findb::mgmt::dim_profit` 出各维度那几行，桌面端
`views/dim_profit.rs` 自己在本地算「未分配」那一行。差别只在一个参数上——前者
`with_exclude_carry(true)`（剔除结转损益凭证），后者忘了。

后果不是数字错位，而是**这一行会消失**：一期结转过，损益科目借贷相抵，未分配金额算成 0，
页面只剩几个部门行。用户只会觉得「上月还有，这月没了」。

现在只有一个函数 `findb::mgmt::dim_profit_report(db, period, dim)`，返回

```rust
DimProfitReport { dim, rows, unallocated, total }
```

三个字段出自同一张快照，恒等式 `total == Σ rows + unallocated` 在测试里钉住。桌面端和
Web 端都调它；桌面端本地的 `unallocated()` 已删除。`dim_profit()` 留成薄壳给老调用点。

「哪类科目算收入/成本/税金」的前缀规则也收到一处（`bucket_of`），原先在 `dim_profit` 和
界面里各写一遍。

## 二、末级科目：快照已经把子科目的钱上卷了

第一版按全表遍历，收入算出来 2000（真值 1000）——余额快照会把子科目金额上卷到父科目，
`6001` 和 `600101` 各来一遍就是双份。现在过滤 `chart.is_leaf(&a.code)`。

## 三、Web 端补上多维损益

```
GET /api/reports/dim-profit?period=202601&dim=dept
```

- `dim` 可用 `dept / project / customer / supplier / employee / item`，缺省 `dept`；
  传别的（如 `cashflow`）返回 **400**，不静默给空表；
- 返回 `rows`（按利润降序）、`unallocated`、`total`，每行含收入/成本/费用/税金/利润/利润率；
- 权限 `fin_report`。

侧栏「账簿报表」新增「多维损益」视图：选期间、切维度、查表、打印预览。

**数据范围怎么落**：这张表是汇总类，按 v1.8.61 定下的口径（明细收窄、汇总不收窄）不整体
收窄；但**部门维度**例外——只授权到 D01 的会计不该看到 D02 那一行。所以只对 `dim=dept`
调 `narrow_to_depts`：只留授权部门，被藏起来的并进「未分配（含未授权部门）」，合计保持
公司口径（利润表上本来就人人看得到）。

踩过的坑：第一版把未分配写成「旧未分配 − 被藏行」，得到 100 而不是 500——旧的未分配里只有
「没挂部门」那部分。正确做法是 `total − Σ(留下的行)`。

## 四、编译警告 262 → 0

- `cargo fix --workspace --all-targets` 处理绝大多数（handler 里没用到的 `State(state)`、
  未用 import、needless mut），60 秒；
- 余下十几条手工收：函数体内误写的 `///`、只在测试里用的 `is_ar`/`is_ap`（补 `#[cfg(test)]`）、
  最后一次自增后没人读的 `param_idx`、与 `tests/common` 重复的助手、`tests/common` 里
  「这个二进制没用到」的助手（按模块 `#![allow(dead_code)]`）。

为什么要清到 0：挂着两百条，新冒出来的那条就混在噪音里没人看见。

## 没动

- 汇总类报表（余额表/试算/三大表）仍不按部门收窄——这是 v1.8.61 定下的口径，见
  `docs/功能参考.md` §4.104；
- 多维损益只做「直接归属」，不做分摊（分摊率每家公司不一样，编一个出来只会把账算歪）；
- 桌面端与 Web 端的界面仍各写一份（数据口径已统一，界面没合并）。

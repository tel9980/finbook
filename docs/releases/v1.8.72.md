# v1.8.72 —— 返工原因分类 + 责任部门：把「哪种返工最费钱」问得出来

## 一、问题

v1.8.71 给了返工单，但原因只有一句自由文本。想问「哪种原因最费钱、哪个班组返工最多」，
把那一列汇总出来是「槽液不好」3 行、「槽液」2 行、「槽液问题」1 行 —— 等于没汇总。

## 二、这一版做了什么

- **原因分类字典**：编码（`SLUG`/`GJ`）+ 中文名，可停用。单据上存编码，自由文本退回备注角色。
  编码被单据用过就不许删（删了历史单据会变成「未分类」），只能停用；改名随时可以。
- **责任部门/班组**：返工单上直接记，按值分组。
- **返工成本分析表**（桌面端 + 网页端 + `/api/rework/analysis`）：按原因、按部门两张汇总，
  每行给张数、返工件数、材料/人工/制造费用/合计与**占比**。
  - 占比分母是**本期返工成本合计**，不是行内金额（否则每行都是 100%）。
  - **未分类 / 未指定单独成桶**，不丢行 —— 丢了各分组合计就不等于总合计，看上去像算错；
    而且「谁都没填」本身是该谁填没填的管理信息。
- 报表行直接带中文分类名（`reason_label`），界面不用自己查字典。

## 三、验证

| 项 | 结果 |
|---|---|
| `cargo test --workspace --locked` | 36 个目标全绿 |
| 新增 findb 单测 | 按原因/按部门分组且不丢未分类；分类被引用不许删只能停用 |
| 新增接口用例 | 建字典 → 三张单（分类/部门/都没填）→ 分析表占比与分组合计 → 被引用分类删不掉、可停用 |
| 变异 ㊺ | 3 条全拦下（不分原因全并一桶、占比分母取行内、未分类被丢掉） |
| fmt / 警告 / clippy | 0 处 / 0 条 / 0 error |
| check-js、check-ci | 通过 |

## 四、没动

- 原因分类不做层级（大类/小类）：小厂的原因清单通常就十来条，两层反而更难维护。
- 责任部门不做惩罚性考核口径（返工率考核涉及产量口径，得先定清楚拿哪个月的产量做分母）。
- 客供料仍不出凭证（v1.8.70 定案）。

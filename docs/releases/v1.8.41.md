# v1.8.41 —— 期初收集表：模板自己长出来，而且能「先试后做」

> 期初数据是这套账唯一的"一次性、不能错"的活。这一版把它从
> 「找一份示例模板改改 → 导入 → 发现不平 → 猜是哪张纸」变成
> 「下载模板（编码已填好）→ 填金额 → 预检 → 导入」。

## 一、模板按当前账套现场生成

以前模板只能靠 `examples/opening_sheet.rs` 跑出来——那是**示例账套**的模板，里面
填着别人的 59 个客户、27 个供应商。工厂拿到它，要么照着改成自己的（编码改错就
整批导不进去），要么回去抄科目编码；而 `112201` 抄成 `112021` 得到的是
「科目不存在」，用户分不清是抄错还是系统没有。

现在 `GET /api/books/opening-sheet/template` 按当前账套生成：

| 那张纸 | 预填 |
|--------|------|
| ① 客户应收 | 每个启用客户一行（编码+名称） |
| ② 供应商应付 | 每个启用供应商一行 |
| ③ 账户余额 | 所有 1xxx / 2xxx 末级科目 |
| ④ 基本资料 | 实收资本、本年利润两行 |

**③ 刻意剔掉 1122 / 2202 与 4xxx**：前者由 ①② 的往来合计生成、后者由 ④ 生成，
在 ③ 里再填一遍就是双计——而双计最坏的地方是借贷两边各多一份、**看起来仍然是
平的**，试算平衡查不出来。

多一张「怎么填」纸：预收/预付填负数、编码名称填一个即可、1122/2202 不用填、
权益只填在 ④、金额一律填正数。

## 二、先预检，再导入

新增 `POST /api/books/opening-sheet/preview`，与导入**同一段代码**，只差不写库：
返回四张纸的行数、金额合计、逐条问题，加 `dry_run: true` 与
`debit_total / credit_total`。不平直接 400，且第一句就说清不平：

```
期初借贷不平：借方合计 50000.00，贷方合计 0.00，差 50000.00。
```

页面上两个按钮：**「先预检一下」**（只看不动账）、**「确认导入」**。
预检结果下面直接显示平衡结论，不平的红色提示旁边就是"再改改表"的说明。

## 三、界面

网页版：`基础资料 → 期初余额` 顶部两个按钮。

- 「下载期初收集表」→ 拿到填好编码的 xlsx
- 选文件 + 「先预检一下」→ 看结论
- 满意了再「确认导入」

## 五、为什么值得单独发一版

期初这件事的特点是：**只做一次，做错了要全部推倒**。而它出错的方式又特别隐蔽——
编码抄错、1122 填了余额、权益填了两遍，全都能"导入成功"。把模板、预检、闭环
测试三件事凑齐，成本不到一天，省的是工厂两天的返工。

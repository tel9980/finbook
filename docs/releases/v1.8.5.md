# FinBook v1.8.5

这一版是**安全与隔离修复**：备份下载不再夹带其他账套的附件，备份列表/恢复不再因账套 key 后缀相同而串套，恢复坏备份会先校验、失败会回滚，删除账套会清理自己的备份；同时堵上了 CSV 公式注入、银行对账页 XSS 和网页端科目编码校验缺口。

**不改记账口径、不改报表算法、不改数据库结构**（仍为 V36），直接覆盖升级即可。

## 这一版修了什么

### 1. 备份下载只打包当前账套的附件

附件目录是所有账套共享的，文件名按内容哈希生成。旧版「下载备份」会把整个附件目录打进 zip，导致：

- 下载的是 A 账套的备份，压缩包里却带着 B 账套的发票、合同等附件；
- 账套越多，备份包越大，且包含与本账套无关的敏感文件。

现在只打包当前账套 `attachment` 表中实际引用的大附件；小附件本来就在 `.fbk` 里，不需要重复打包。

### 2. 备份列表/恢复不再「后缀撞车」

旧版用 `文件名以 _<账套key>.fbk 结尾` 判断备份归属。账套 key 允许下划线，于是：

- `alice_202610` 的备份，会被 key 为 `202610` 的账套当成自己的；
- 后者可以在备份列表里看到它，甚至恢复它，等于跨账套读取全套账。

现在先剥掉固定宽度的时间戳前缀，再要求剩余部分与当前 key **完全相等**。`alice_202610` 与 `202610` 不会再互相认领。

### 3. 恢复备份：先校验，再原子替换，失败自动回滚

旧版恢复直接覆盖当前 `.fbk`，并且把「恢复前自动备份」的失败静默忽略。现在：

- 先以只读方式打开备份，跑 `PRAGMA integrity_check`，并确认包含 `voucher` 表；
- 备份损坏或不是 FinBook 账套时直接拒绝，**当前账套一个字节都不动**；
- 恢复前的自动备份失败就中止，不再出现「以为有退路、其实没有」；
- 先写临时文件，成功后再 rename 替换主库，避免中途失败留下半个文件；
- 新库打不开时，用刚生成的自动备份回滚，并提示手工恢复文件名。

### 4. 删除账套会清理自己的备份，附件只删「没人再用」的

旧版删除账套只删 `.fbk`，备份文件留在共享目录里。若之后又建了同名 key 的账套，新账套能在备份列表里看到并恢复上一个租户的数据。

现在删除账套时会：

- 删除该 key 的手工备份和自动备份；
- 清理该账套引用的大附件，但先扫描其他账套是否仍在引用；任何一个账套扫描失败就整体放弃删除（宁可留下孤儿文件，也不误删别人还在用的附件）。

### 5. 网页端新增/修改科目补齐校验

旧版桌面端有科目编码校验，网页端没有：非数字编码、上级不存在的编码可以直接写进库。后续报表做「按前缀找上级科目」时按字节切分，遇到中文编码会 panic，整个账套的报表都打不开。

现在网页端与桌面端使用同一套校验：编码必须符合级长方案、名称非空、上级科目必须存在。同时把前缀查找改成按 UTF-8 字符边界切分，历史库里的坏数据也不会再把报表打崩。

### 6. CSV 导出防公式注入

科目名、摘要、客户名等用户可控文本以 `= + @` 开头时，Excel/WPS 会把它当公式执行。现在这些单元格会加 `'` 前缀；`-` 只在「不是合法数字」时加前缀，负数金额仍保持数字形态，不影响求和。

### 7. 银行对账页 XSS

「银行已收/企业未记」等差异列表直接把后端摘要拼进 HTML。现在统一做 HTML 转义，摘要里的 `<script>` 只会显示成文字。

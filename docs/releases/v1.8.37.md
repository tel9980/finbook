# v1.8.37 —— 别再为 apt 付 10 分钟；debug 产物要认得出是它

这一版两件小事，都是「数字摆出来之后才发现一直白付的成本」。

## 一、E2E 那 10 分钟不是浏览器下载，是 apt

v1.8.36 的 CI 绿了，但壁钟 **15.2 分钟**，比上一版 7.2 分钟翻倍。逐 job 看：

| job | 耗时 |
|-----|------|
| **Web E2E** | **15.2 min** ← 唯一瓶颈 |
| Test | 7.5 min |
| Mutation shard 1/6 | 5.5 min |
| Coverage | 4.4 min |
| Docker smoke | 3.7 min |

进到 E2E 的步骤里，时间线是这样的：

```
09:28:26  npm ci                        ← 1 秒
09:28:26  npx playwright install --with-deps chromium
09:38:09  ↑ apt 结束                    ← 9.7 分钟
09:38:10  npx playwright test
09:41:56  ↑ 测试结束                    ← 3.8 分钟
```

关键证据在日志里：`Cache hit occurred on the primary key pw-chromium-Linux-…`
—— **浏览器缓存是命中的**，`install chromium` 本来就是空转。9.7 分钟全花在
`--with-deps` 触发的那次 `apt-get`：装 xvfb、一堆字体、libnss3 之类。

很容易误判成「浏览器下载慢」，然后去折腾缓存 key —— 那是白费力气。

改法：去掉 `--with-deps`，只留 `npx playwright install chromium`。

- ubuntu-latest 镜像本身已带 chromium 运行需要的那批库（日志里 `libnss3`、
  `libglib2.0-0t64` 全是 `is already the newest version`），`--with-deps` 装的主要是
  **字体和 xvfb**，跑无头 chromium 用不上。
- 万一哪天真缺库，症状是 playwright 启动浏览器直接报 `missing library`、job 变红 ——
  **看得见的失败**，比每天先烧 10 分钟 apt 好。
- `tools/check-ci.js` 新增 2.47 项盯着这个尾巴：出现 `--with-deps` 报红；把
  `install chromium` 整段删掉也报红（缓存未命中时会变成「找不到浏览器」的假测试失败）。

预期 E2E 从 15.2 分钟落到 **4~5 分钟**，CI 壁钟回到 ≈8 分钟。

## 二、`target/debug` 45 GB，`target/release` 543 MB

实测同一个仓库：

| 目录 | 大小 |
|------|------|
| `target/debug`（连续跑了一周测试之后） | **45 GB**（`incremental` 15 GB + `deps` 27 GB） |
| `target/debug`（清空后重新编译一次） | 8.7 GB（`incremental` 1.5 GB + `deps` 6.2 GB） |
| `target/release` | 543 MB |

两个数字都是实测。要注意的是**它会长**：每改一次代码、跑一次测试，`cargo` 都往
`deps/` 里放一份新的 rlib、往 `incremental/` 里放一版中间态，旧的不删。涨到 45 GB
时里面大部分是没人再用的历史版本 —— 清一次就回到 8.7 GB。

原因不是「编译选项多」，是 `cargo` 为了增量编译，给**每个 crate 的每个 codegen
单元**都存一份带完整调试信息的中间产物；`--release` 默认 `incremental = false`，
中间态用完就扔。

```bash
cargo run --release -p finbook     # 日常用桌面版
cargo run --release -p finweb      # 日常用网页版
cargo clean --profile dev          # 只清 dev，release 产物保留 → 实测回收 47.2 GiB
```

写进 README §7.1，包括三点避免走弯路的补充：

1. **`cargo test` 就用 debug**（dev profile）。测试要的是「改一行、十几秒出结果」，
   release 会让反馈周期变成几分钟。测试留下的 debug 产物是正常成本，定期清就行。
2. **别用 `cargo test --release` 换磁盘** —— 它同样生成一套 release 测试产物，两份更大。
3. **CI 没有这个问题**：每个 job 都是干净环境，`Swatinem/rust-cache` 只缓存依赖。

## 验证

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **978** 全绿（本版无 Rust 逻辑改动） |
| 新增守卫 | `check-ci` 2.47 项，两个方向都实测报红（加回 `--with-deps`；删掉 `install chromium`） |
| 自检 | check-ci / check-js / check-portable / check-design-doc / check-simple-nav 全过 |
| 磁盘 | `cargo clean --profile dev` 回收 47.2 GiB，`/workspace` 从 72G 占用降到 28G |

## 怎么用

- **本地开发**：启动服务用 `cargo run --release -p finweb`（或桌面版 `-p finbook`）。
- **磁盘涨了**：`du -sh target/debug` 看一眼，然后 `cargo clean --profile dev`。
- 不需要改任何配置、不需要装任何工具。

# v1.8.118 慢查询基准扩面 + 快到期的应收待办 + 报价带历史价

## 慢查询基准扩面

原来 `benches/hot_reads.rs` 只有往来、结账、工作台四组，开票、成本结转、存货收发存这些入口没有点测数。本版把 seed 补齐（原来只有 SO/PO/凭证，没有库存流水和发票，导致三个新基准空跑）并新增 4 组点测：

| 基准（seed 500 单） | 耗时 |
| --- | --- |
| `invoice_summary_500`（开票汇总） | ≈ 0.92ms |
| `stock_summary_500`（存货收发存，MonthAverage） | ≈ 2.23ms |
| `period_end_cost_500`（期末成本结转，只算不写） | ≈ 3.21ms |
| `workbench_collect_5000`（5000 单工作台聚合） | ≈ 288.74ms |

## 工作台补「快到期的应收」

工作台原来只有「快到期的应付」，没有对称的应收提醒。本版补上 `ar_due_soon`：30 天内到期的应收单报数，并带「最早到期 {日期}」的紧迫提示（和应付侧同款）。

## 报价单/订单带历史价

报价单开单时只看「按价目表 / 按规则」两个实时算法，看不到这个客户这个物料过去实际成交过多少钱。本版：

- findb 加 `customer_item_price_history(db, customer_code, item_code) -> Option<(Money, Money)>`，从**已确认**销售订单明细（排除草稿、作废）取 `(上次成交价, 历史最低价)`。
- finweb 加 `GET /api/sales/item-price-history?customer=&item=`。
- 前端报价单页客户+物料都填了之后，单价框旁提示「上次 X · 最低 Y / 无成交历史」，纯提示、不拦单。

## 三条规矩

1. **历史价只看成交**：草稿是未定的报价、作废是没成交的单，都不能算「历史成交价」，否则一个占位价（比如 5）会把最低价拉歪。
2. **纯提示不拦单**：历史价只作参考，老客户让价、一次性大单都该由业务员自己拍板，系统不因低于历史价就拦截。
3. **到期提醒对称**：应收/应付都是「30 天窗口 + 最早到期日期」，两端口径一致，不再单侧缺提醒。

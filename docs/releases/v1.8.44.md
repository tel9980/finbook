# v1.8.44 —— 打印预览：点一下、拖一下，当场看到并存住

## 以前的循环

调版式得这样：去「系统设置 → 打印预览」改一个数 → 回来点打印 → 发现还是不对 → 回去再改。
版式对不对，只有**看到那张纸**的时候才知道，所以这个循环一次要绕两分钟，绕三五次人就放弃了，
最后就那么歪着打。

## 现在

打开任何一张报表的打印预览，顶上那条控制条就是编辑器：

| 控件 | 作用 |
|------|------|
| 方向 | 自动（按列数）/ 纵向 / 横向 |
| 字号 | 拖动滑块，9–14 pt，纸上立刻变 |
| 页边距 | 拖动滑块，5–30 mm |
| 编制单位 / 打印时间 / 页码 / 落款 | 勾选框，勾掉立刻消失 |

**改完自动保存到本账套**（右上角显示「保存中… / 已保存 ✓」），下次任何人打印都按这套来。
不用点「保存」按钮 —— 也没有「忘记保存」这个坑。

## 三个不那么显然的决定

**1. 发的是「局部改动」，不是整份设置。**
预览页只认识七个字段。如果照「读出来→改→整个写回」做，它不认识的（凭证纸型
`241×140 连续纸`、账簿纸型、套打偏移）会被默认值冲掉，而且一声不响 —— 要等下次打凭证
才发现纸型变回 A4 了。现在接口收的是 `PrintPatch`（字段全 `Option`），只覆盖请求里带的那几项。

**2. 越界值报错，不悄悄夹回去。**
保存走的是和「系统设置」同一条校验（`Db::set_options` 那一道），超出 9–14 会 400
并把原值带出来：`打印字号应在 9–14 之间，当前是 20`。「悄悄夹成 14 并存住」看着更稳，
实际是「用户填了 20、打出来 14、没有任何提示」，只会让人以为设置没生效。

这里踩了一个自己埋的坑：handlers 里我一开始**又写了一遍** `opts.validate()`，两层校验
看着更保险。结果 CI 的变异测试当场打脸——把外层删掉，测试照样绿（`set_options` 里那道
已经把 20pt 挡回去了），也就是说外层那一层根本没人能证明它在干活。已经删掉外层，
守卫只留一处，变异也改成盯 `set_options`：`1 failed` 是「200 而不是 400」的真断言失败，
不是编译错。

**3. 没权限的人看到的是另一条控制条。**
版式是账套级的，改一次所有人都变，所以保存要「系统设置」权限。没权限的账号打开预览，
控制条只剩「横向/纵向/字大字小」三个临时按钮，并明写：

> 你的账号没有「系统设置」权限：这里的调整只对本次打印生效，不会保存

宁可少一个功能，也不要给一个「点了以为存了、其实没存」的按钮。

## 顺手做的两件小事

- **拖动不刷屏**：手停 400ms 才发请求；并用递增 `seq` 丢掉过期响应 —— 否则快速拖几下，
  先发的慢请求后到会把状态栏刷成「保存失败」，而其实早就存好了。
- **隐藏而不是删掉**：关掉「编制单位」现在是 `display:none` 而不是把节点删掉，
  这样勾选框能当场打开看看。打印时一样不占位置。

## 桌面版说明

桌面版的打印是「导出 HTML 再用浏览器打开」，那个页面没有登录态、发不出保存请求，
所以桌面端的版式仍在「系统设置 → 账套参数 → 打印预览」里改（同一套字段、同一套校验）。

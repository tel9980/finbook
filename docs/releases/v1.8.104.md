# v1.8.104 性能与便捷：收款汇总去 N+1、工作台补逾期应收待办

## 问题

1. **性能**：回款看板 `so_receivable` 和信用占用 `credit_check` 各自在循环里「每跑一张订单就查一次收款表」（N+1）。订单一多就是成百上千次重复打表，纯浪费——SQLite 本身早已调优、索引也齐全，真正的性能浪费就藏在这里。
2. **便捷**：工作台「本月该干的事」的「销售」项只有待审批报价单 / 待确认订单，没有「逾期应收待催收」。老板得跳进销售单据页才知道谁欠着没还。

## 改法

1. **批量汇总（性能）**：新增 `findb::sales::so_payment_sums(db) -> HashMap<i64, Money>`，一次 `SELECT so_id, amount FROM so_payment` 把每张订单的已收金额聚成一张表；`so_receivable_as_of` 与 `credit_check` 都改为「循环前查一次、循环内 `sums.get(&id)` 取值」。N+1 变 1 次全量查询。
2. **工作台待办（便捷）**：`findb::workbench` 的 `collect`（`/api/workbench`）与 `collect_todos`（`/api/notices`）两个待办源都补一条「销售 · 逾期应收待催收」——`so_receivable` 里 `overdue_days > 0` 的张数，点击跳 `so-doc`（销售单据页）。有 `Report` 权限才显示。

## 三条判定

- 汇总表只加不查：`so_payment_sums` 一次全量读出，后续全是内存 HashMap 查值，不碰库。
- 待办口径与看板一致：`so_receivable` 已算好 `overdue_days`，工作台只 `filter(overdue_days > 0).count()`，不再重复算账期。
- 两个待办源同款逻辑：`collect`（工作台页）与 `collect_todos`（右上角通知）各插一份，保证两处看得到同一个数。

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/workbench` | 待办「销售」项新增 `ar_overdue`（逾期应收待催收） |
| `GET /api/notices` | 同上，通知侧同步 |

## 测试与门禁

- findb：`so_payment_sums_aggregates_multiple_payments`（同一单多笔收款累加 / 没收款为 None）、`overdue_receivable_surfaces_as_a_todo`（一张逾期 + 一张没过账期 → count==1）。
- 变异 122（回款汇总只取每单第一笔收款）、123（工作台逾期应收把没过期的也算进来），实跑拦下。
- `check-design-doc.js` 行号引用随 `so_payment_sums` 插入同步更新（`sales.rs` 的 `customer_credit_limit` 1031→1067、`credit_check` 1051→1087）。

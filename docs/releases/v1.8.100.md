# v1.8.100 报价单 vs 实际结算对账：说好 0.28、结算按 0.31，差多少列一张

## 问题

报价单转成销售订单后，订单明细里的单价**仍可再改**——报价 0.28 一件，真正结账时
客户还价、改按 0.31 走。过去这两张单子各看各的，一个月下来谁也说不出「这个月
有多少报价单的成交价和当初说好的不一样、一共差多少钱」。

## 改法

「销售单据」页报价单面板右上加 **报价对账** 按钮（`report` 权限）。后端按当期把
所有「已转订单」的报价单，追到下游销售订单首行，列一张表：

| 单号 | 客户 | 存货 | 数量 | 报价单价 | 实际单价 | 单价差 | 差额 | 订单状态 |

- 实际单价 = 下游订单首行 `unit_price`（转单后还能改，那份才是真卖给客户的价格）；
- 单价差 = 实际单价 − 报价单价；差额 = 订单行金额 − 报价金额；
- 有差价的行情标黄、单价差带 `+`/`-` 号，未转订单的只显示「未转订单 / —」。

## 三条判定

1. **只追「已转订单」的报价单**，且走 doc_link 勾稽（`src_type='quote'`、`dst_type='so'`），
   不是靠订单备注里那行「由报价单 X 转入」的文本——那条可删、可改，勾稽表删不掉。
2. **实际价取订单首行**，报价单是单行结构（一张 = 一个物料），转单后明细仍是那一行；
   订单被改成多行时，对账只认第一行（与转单逻辑一致）。
3. **差价的符号**：正 = 成交比报价贵、负 = 比报价便宜，表里 `+`/`-` 直接标出来。

## 接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/sales/quote/reconcile?period=` | `report` | period 缺省当期；返回 `{"rows": [...]}` |

- 接口：`quotation_reconcile_compares_quoted_vs_settled_price`（转单改价后 rows 1 条、
  四个金额差全对）。
- 变异 110–112（查下游取错单据类型 / 单价差算反 / 金额差误用单价差），清单 244 → 247。
- 前端渲染门禁新增 3 条 `quoReconcileHtml` 用例（有差价 + 未转订单 / 全一致 / 空表）。

# v1.8.20

**官方容器镜像：`docker pull ghcr.io/tel9980/finbook:1.8.20`，Dockge 里粘一段 compose 就能跑。**

这一版没有改业务逻辑，只补了「怎么把 Web 端装起来」这条路的最后一公里。桌面端和 Web 端的代码与 v1.8.19 一致。

## 之前得自己编译

`DEPLOY.md` 里 Docker 那条路一直是这样的：

```bash
docker build -t finbook:latest .
```

在一台小服务器上，这一步要装 Rust 工具链、编译五个 crate，十几分钟起步，中间还得有 1.5GB 空闲内存。工厂里那台机器多半跑不动，或者跑到一半被 OOM 杀掉。

现在镜像在 CI 上编好了，`docker pull` 完事。

## 加了什么

| 文件 | 干什么 |
|---|---|
| `.github/workflows/docker.yml` | 打 tag 时自动构建并推送到 GHCR |
| `deploy/docker-compose.yml` | Dockge / Portainer / `docker compose` 通用的栈定义 |
| `DEPLOY.md` §4.5 | 逐步说明：加栈、改端口、看首次口令、升级、验证数据落盘 |

镜像标签三种：

```
ghcr.io/tel9980/finbook:1.8.20   精确版本，生产钉这个
ghcr.io/tel9980/finbook:1.8      次版本，自动收补丁
ghcr.io/tel9980/finbook:latest   最新正式版
```

`latest` 只在推送正式 tag 时更新；手动重跑 workflow 补发镜像时**不会**覆盖它 —— 否则用旧 tag 重跑一次就能把 `latest` 退回去。

## 一个没有做的决定，和为什么

本来想让 Dockge 上「一键启动」真正一键：给镜像加个入口脚本，启动时自动 `mkdir -p /data/books`。这样用户什么都不用管。

翻到 `DEPLOY.md` §10 才发现这会把一道**故意设的**守卫废掉：

> 卷没挂上时，服务会在**容器可写层**里凭空造一个 `books` 目录。然后一切照常：能登录、能录凭证、备份脚本也照常把 `.fbk` 写进同一层。
> 唯一的征兆是数据在重建后没了，而那时已经无法追溯。

自动建目录正好制造这个场景：挂载失败不再报错，反而被默默修好，账记在随时会消失的地方。

所以改成 compose 里加一个 `init` 服务，**在真正挂上的卷里**建目录、改属主，主服务 `depends_on` 它的完成：

```yaml
init:
  image: ghcr.io/tel9980/finbook:1.8.20
  user: root
  entrypoint: ["/bin/sh","-c","mkdir -p /data/books && chown -R 10001:10001 /data"]
  volumes: ["./data:/data"]
  restart: "no"
```

启动顺序固定，主服务继续以非 root 运行，守卫保持有效 —— 挂载没生效时 `init` 建的也是空卷，`ls ./data/books/` 一看就知道。

## 部署前要知道的一件事

compose 默认 `127.0.0.1:8080:8080` + `FINWEB_SECURE_COOKIE=true`，也就是**前面必须有 HTTPS 反代**（Dockge 只起容器，不管 TLS）。

想局域网直接 `http://192.168.x.x:8080` 试，端口和 Cookie 标记**两行要同时改**：

```yaml
ports:
  - "8080:8080"
environment:
  FINWEB_SECURE_COOKIE: "false"
```

只改端口不改标记的症状很有辨识度：**登录看着成功了，页面立刻退回登录页**。因为浏览器不肯在 HTTP 下回传带 `Secure` 的会话 Cookie。反过来，上了 HTTPS 却留着 `false`，会话就能被中间人窃取。

## 发布流程

镜像发布独立成一个 workflow，而不是塞进 `release.yml`：镜像构建十几分钟，失败原因也完全不同（buildx / 缓存 / 权限）。混在一起时镜像失败会把「Release 已经发出去了」这件事盖掉，排查时先看到的是个红叉，容易误判成整个发布失败。

## 升级

```bash
# Dockge：改 compose 里的 tag → Deploy
# 命令行：
docker compose pull && docker compose up -d
```

数据在 `./data`，容器重建不丢。跨大版本前把 `./data` 整个拷走就是全部数据（`realm.db` + `books/*.fbk`）；热备份用 `deploy/backup.sh`，它走 SQLite 在线备份 API 而不是直接 `cp`。

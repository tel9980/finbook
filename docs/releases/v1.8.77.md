这一版没有花哨功能，做的是「让后面每一次改动都更便宜」的三件事，外加一本照着抄就能用的真账。

## 一、一般纳税人演示账：按真实盘子做的第二本账

原来的 `恒亮氧化加工厂演示账.fbk` 是**小规模 3%** 的入门版（28 张凭证、月收入 18.4 万、
买料不要票也行）。但它对不上大多数加工厂的实际情况：**一般纳税人、70 人、要给客户开 13% 专票、
采购要抵进项**。这一版新增一本对齐真实盘子的账：

| 项 | 数值 |
|---|---|
| 期间 | 2026-11（全月，**未结账**，留给你亲手点结转） |
| 凭证 | **48 张全部已记账**（业务 45 张 + 系统自动生成 3 张） |
| 收入 / 销项 / 进项 | 450,000 / 58,500 / 9,740.34 |
| 应交增值税 | 48,759.66（**税负 10.84%**）+ 附加税 5,851.16 |
| 本月利润 | 17,119.18 |
| 资产负债表 | 资产 412,480 = 负债 72,040.82 + 权益 340,439.18 |
| 发票 | 销项 3 张（13%）、进项 12 张（全部已认证），无票的六项支出**一张都没录** |

覆盖的业务形态都是实际会遇到的：8 种化工料的采购（13% / 3% 两种税率）与领用（数量金额）、
**电卡充值 → 抄表结转**（112301 预付电费）、厂房 + 宿舍租金（无票）、委外加工三种票
（13% 专票 / 3% 征收率 / 无票现付）、承兑汇票收票 → 兑付 → 背书、70 人工资五步
（计提 / 单位社保 / 实发 / 缴社保 / 缴个税）、月末转出未交增值税 + 计提附加税。

以及「收付不一一对应」的三种解法，账里各有一张现成的凭证：

- **代收代付（跨单位互抵）**：C 客户替 B 客户打来 15,000 → 自动出过渡凭证
- **三方抵账**：客户欠我的 ↔ 我欠供应商的，轧差 20,000 → 一张凭证把两头都核销
- **双向抹零**：收款抹零 50（借 660305）、付款抹零 20（贷 660305），差额不进往来余额

配套手册 `docs/氧化加工厂一般纳税人记账手册.md`：10 类业务的分录对照（每条都写了「对照：转-18 / 收-3」这种
凭证号，可逐张点开比对）、月末余额表、税负 10.84% 的进项构成拆解、三层对应与账龄实例。

> **税负 11% 不是税率，是结构。** 工资 + 社保 282,200 不能抵税，能抵的只有化料、电费、委外这些
> 有票支出，进项只占收入 2.2%。所以这本账真正要教会的一句话是：**要票就是省钱**。

## 二、clippy 从 725 条到 0：把「告警不卡构建」改成闸门

**问题**：`cargo clippy` 有 725 条告警，CI 里只 `-A` 掉了五类，也没有 `-D warnings`。
告警不卡构建 → 告警就只是背景噪音 → 真问题淹在里面，谁也不再读。

**做法**：两轮 `cargo clippy --fix` 修掉 492 条 `needless_borrow`、86 条多余 deref 等机械问题
（41 个文件、+1377/−1399 行），再手改 18 处 `--fix` 改不动的（`format!` 套 `format!`、
手写计数器换 `enumerate()`、重复的 `let mut v = v;`、拆模块后遗留的 10 处孤儿文档注释）。
剩下 69 条**全部落在项目既定设计风格的五类**里（`too_many_arguments` / `type_complexity` /
`field_reassign_with_default` / `large_enum_variant` / `should_implement_trait`）——这五类是
有意为之（凭证行构造、报表单元格签名本来就是多参数），继续 `-A` 掉。

**闸门**：`.github/workflows/ci.yml` 两个 clippy step 改成
`cargo clippy … -- -D warnings -A <那五类>`。以后新增一条告警就红。

> 一个真实的副作用值得记下来：`--fix` 会把 `&db` 改成 `db`（`needless_borrow`），
> 于是 3 条 Rust 变异（`tools/mutate-rust.js` 里 `from` 逐字匹配源码的）全部失效。
> 这不是 bug 而是设计：**变异串失效必须报红**，否则「检查悄悄不生效」比「检查失败」更危险。
> 三条已改指向。

## 三、前端拆包：14,314 行 → 16 份

`crates/finweb/static/app.js` 是 14,314 行 / 295 个顶层函数的单文件。改任何一屏都要全文检索，
五个静态检查工具各自硬编码这个文件名，谁都不敢动它。

**拆法**（保守优先）：

- **按原始行序连续切片**，切点取每个文件首个顶层条目，注释/空行一并带上 → 函数与 `const`
  的提升、声明顺序**完全不变**，跨文件不存在 TDZ 风险；
- 仍然用**经典 script**（不是 ES module），顶层 `function`/`const` 天然跨文件共享，
  不动 `import`/`export`，不动任何函数体；
- 唯一需要挪位置的是 `const VIEWS = {…}`（它引用所有视图函数），放到**最后加载**的
  `app-hr.js` 里、boot IIFE 之前，并写了四行注释解释为什么必须最后。

16 份按业务切：`app.js`（HTTP 会话 / 提示弹窗 / 快捷键 / 表格页签 / 设备权限）、`app-auth`、
`app-shell`、`app-dashboard`、`app-vouchers`、`app-invoice-tax`、`app-imports-ledger`、
`app-reports`、`app-admin`、`app-analysis`、`app-ops`、`app-inventory`、`app-docs`、
`app-funds`、`app-master`、`app-hr`。

**验证「没拆坏」的方式不是肉眼**：

| 判据 | 结果 |
|---|---|
| 16 份逐份 `node --check` | 全通过 |
| 与 `git show HEAD:…/app.js` 逐行比对 | 非空行只多 16 行 `//`（每份文件头说明） |
| 顶层函数计数 | 295 个，各出现 1 次 |
| `const`/`let`/`class` 重名 | 61 个，0 重名 |
| 拼接后体积 | 800,921 字节（与原文件一致） |
| 浏览器真跑（Playwright chromium，真账套 + 真服务） | 见下方 §五 |

**工具同步**（这是拆包真正的成本）：新增 `tools/lib-app-src.js`（从 `index.html` 解析脚本顺序、
拼包、缓存），五个工具全部改成走它，谁都不再硬编码文件名：

- `check-js.js`：拼接全部脚本扫重复 DOM id；行号用 `ownerOf[]` 映回「文件名:行号」，
  报错仍然指到真实文件。**nginx sub_filter 锚点故意只查 `app.js`** —— 反代替换的是发出去的
  `/app.js`，锚点跑到别的文件里就等于消失了（注释已写明这是与部署配置的隐形契约）。
- `check-app-render.js` / `check-simple-nav.js`：改为读拼包。
- `mutate-check.js`：每条变异先在所有 `app*.js` 里**定位**（唯一命中才算数，多命中要报歧义），
  再写坏对应文件、跑检查、立刻还原。22 条变异分布 5 个文件，22/22 全被拦下。
- `check-ci.js`：清单校验按「每条变异自带文件」逐条定位。
- `main.rs` 的 `asset_version()`：不再硬编码 `["app.js","style.css","util.js","icons.js"]`，
  改成从 `index.html` 扫出所有带 `?v=` 的资源（漏项=那个文件永远拿旧缓存，`icons.js` 就漏过）。
- `index.html`：16 个 `<script src="/app*.js?v={{V}}">`，顺序即原声明顺序。

## 七、四件给小厂的新东西

### 7.1 电费台账（schema v47）：充值不是费用

充值只动 `112301 预付电费`，抄表只登记，结转才进 `510103` 并按 13% / 9% 拆进项，
结转与记账在同一事务里完成、凭证号回写台账行。已结转的行不许改、不许删——
要改先作废凭证。`GET/POST /api/meter`、`POST /api/meter/close`，
Web 端资金管理页新增「电费台账」页签（充了多少 / 用了多少 / 卡里还剩多少 / 还有多少没结转）。

### 7.2 收款认领：一笔钱认给多个客户

`crates/findb/src/claim.rs`：列出「钱到了还没认」的收款和「还挂着没收到」的单，
先建议「同一客户优先」，落库时同客户走普通核销、跨客户自动出过渡凭证
「借 [收款记的那个人] / 贷 [真正要清的那个人]」并当场记账。往来核销页新增认领面板。

### 7.3 委外加工三种票：同样的钱，三种成本

`crates/findb/src/outsource.rs` 把「13% 专票 / 3% 征收率 / 无票」做成一个纯算术模块：
含税 10,000 元 → 进成本 8,849.56 / 9,708.74 / 10,000.00，进项 1,150.44 / 291.26 / 0。
确认加工费的弹窗先选票种再填价税合计，旁边一张三票对比小表。
旧签名 `outsource_fee` 保留并委派到新函数（等价无票），老调用点不用改。

### 7.4 增值税申报前体检

`precheck(db, period)` 查十件事（票面勾稽、税率可识别、未认证票、跨期票、作废票、
转出未交增值税、附加税计提、进销项账票不符、留抵、申报表自带 warning），
每条带级别 + 编码 + 人话 + 金额，`GET /api/tax/precheck` 独立成端点。
**只举手不动手**：体检不改账、不认证票、不替你决定。
判"账票不符"用本期发生额而不是期末余额——期末余额已被转出未交增值税踢平，拿它比等于没查。

顺带修了一个 E2E 断言（`e2e/tests/taxdecl.spec.js`）：原来断言「整页文字里不许出现 65.00」，
而体检面板会明确写出「有 65.00 的进项票还没认证」——那是提醒，不是抵扣。
现在给四张卡片加了 `#tx-cards`，断言只看申报表本身：提醒可以提，抵扣口径不能松。

### 7.5 演示账里现在点得开

四件事不是"做了但看不到"：`docs/恒亮氧化加工厂一般纳税人演示账.fbk` 重新生成过，
分别是——电费台账里躺着一行 11-30 的抄表（15,000 度，已结转，凭证 记-1，卡里剩 6,000）；
**故意留了一笔 20,000 的微信收款没认领**（11-27 宏远，收-5），打开往来核销 → 收款认领
就能拿它练手，账龄里也看得到"钱到了、还没落到单上"；委外三张凭证对应 13% 专票 /
3% 征收率 / 无票；申报页顶部体检结果是 0 错误、1 待确认、可以申报。
演示账的 48 张凭证改成以台账结转和认领工作台生成凭证（手写的那张电费凭证删掉了），
`oxide_vat_demo` 也加了第 4 个测试，专门钉住"四个功能在账套里都摸得到实物"。

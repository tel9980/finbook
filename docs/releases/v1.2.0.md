# FinBook v1.2.0

v1.1.0 解决了「下载 → 双击 → 用起来」。这一版解决接下来的一公里：**建账和录入**——把余额表和客户名单从 Excel 粘进来，期初不平时告诉你改哪一行。

---

## 下载

| 平台 | 文件 | 大小 |
|------|------|------|
| **Windows 10/11** | `finbook-1.2.0-windows-x86_64.zip` | ~7 MB |
| Linux x64 | `finbook-1.2.0-linux-x86_64.tar.gz` | ~10 MB |

解压后得到三个文件：

```
finbook(.exe)          主程序，双击即用，无需安装
新手使用说明.txt        4 步走通的大白话说明（这一版更新过）
示例账套.fbk           一家小商贸公司的完整账，可先打开看效果
```

账套就是一个 `.fbk` 文件（标准 SQLite），**备份只需复制这个文件**。

附件里还有服务器版（`finweb-1.2.0-linux-x86_64.tar.gz`，自部署 Web 端用）与校验和（`SHA256SUMS`）。

## 建议的第一步：先打开示例账套看看

和上版一样，包里附了一份示例账套——一家小商贸公司 2026 年 1 月的账，已经记好 9 笔业务（采购付货款 / 赊销开票 / 收货款 / 发工资 / 付房租 / 结转成本 / 缴税 / 付运费），**借贷平衡、全部已记账**。

建议按这个顺序点一遍，照着走就知道软件怎么用了：

1. 「工作台」—— 看这个月的大致情况
2. 「凭证查询」—— 看那 9 笔账长什么样
3. 「科目余额表」—— 看每个科目还剩多少余额
4. 「会计报表」—— 看资产负债表、利润表

看完之后建议：复制一份留着对照，再新建一个自己的空白账套开始记。

示例账套登录：`admin` / `admin123`

## 这一版的变化

### 1. 建账：预置常用档案，录得了第一张凭证

以前新账套一条档案都没有，第一张凭证就存不了——带辅助核算的科目必须填辅助核算，而下拉框里根本没有可选项，只能把凭证丢掉去翻菜单找档案页。

现在建账时默认勾选「**预置常用档案**」：销售部 / 管理部 / 财务部、基本户 / 一般户自动建好。客户、供应商、存货**故意不预置**——那几类名字没有通用值，填个假的进去会跟着凭证流进报表，比空着更糟。

### 2. 批量粘贴：名单和余额表从 Excel 直接粘进来

一家公司几十个客户、上百个期初科目，一个个敲是灾难，而财务手上几乎一定已经有一份 Excel。

- **辅助档案**：档案页「批量粘贴」，编码 + 名称两列复制过来一次导入。只写名称也行，编码自动编号（C01、C02…）。**先预览再导入**，编码已存在的跳过、不覆盖。
- **期初余额**：期初页「批量粘贴期初」，编码 + 金额两列粘进来。**方向不用填**——资产自动记借、负债权益自动记贷，负数和红字括号自动转反方向。粘完先给试算（借方合计 / 贷方合计 / 差额），平不平一眼看到。

### 3. 期初不平：从「自己逐行对」到「照着改」

以前试算区只给三个数（借方合计 / 贷方合计 / 差额），看到「差额 5000」时面对 200 行只能逐行对。

现在分两层：

- **标出嫌疑人**：金额方向和科目方向相反的行标红、可点击跳转（负债填到借方是新手最常见的错）。
- **算出解法**：只报「改完一定能平」的改法——方向反了就给「把方向反过来」一键按钮，累计借贷填反了就给「对调」，只填了一边就提示补对方科目。实在解不出来，给「新增一行对方方向 + 差额金额」，选个科目就行。

### 4. 会计科目页：看得出父子关系

199 个科目以前是平铺的，`1001` 和 `100101` 看不出父子关系。现在按层级缩进显示，加「只看在用」过滤（有分录或有余额的才显示），排序可在编码 / 名称 / 类别三档切换。

### 5. Web 端跟上桌面端

- **精简模式**：默认只显示 16 个日常功能，搜任意功能名都能跳过去（藏起来，不是拿掉），开关随时可切。
- **预置常用档案**：辅助档案页同样一键可点。
- **批量粘贴**：辅助档案和期初余额的粘贴弹窗与桌面端同一套解析逻辑，两边粘同一段文本结果完全一样。

## 数据与隐私

**完全离线运行，数据不上传。** 账存在你自己电脑上的 `.fbk` 文件里，不联网、不收费。

## 已知限制

- 打印走系统默认浏览器预览（Ctrl/Cmd+P），未对接虚拟打印驱动
- 导出 Excel/CSV 仅管理员与财务主管可用，普通账号仅能打印
- 附件哈希为 SHA-256 完整性校验（防误删损坏），不防篡改
- 不要把同一个 `.fbk` 放在 NFS/SMB 网络盘被多台电脑并发直开（WAL 在网络文件系统上不稳定，可能损坏账套）

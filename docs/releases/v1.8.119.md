# v1.8.119 桌面端增值税申报表 + 生产订单下达选工艺版本

## 桌面端增值税申报表

v1.8.52 就记「桌面端增值税申报表仍只在网页端」，本版补齐 finui 视图：

- 新建 `crates/finui/src/views/tax_decl.rs`，复用网页端同款后端 `findb::taxdecl::vat_main_form`。
- 主表：销项（一般 / 简易 / 免税 / 待归类）+ 销项税额、进项税额、应纳税额 + 附加税费（城建 / 教育费附加 / 地方教育附加 / 合计）。
- 附一 / 附二：分档税率明细（税率 / 张数 / 销售额 / 税额 / 价税合计），简易计税标「(简易)」、0 税率标「(免税)」。
- 待归类金额非 0 标黄、warnings 逐条标黄；期间可上期 / 下期切换；导出 CSV（主表 + 附加税费）。
- 菜单归「期末」组（发票管理之后），`Perm::Report` 权限。

## 生产订单下达选工艺版本

v1.8.67 记「生产订单不记按哪一版工艺排产，要指定版本用接口 `?version=`（界面暂未给下拉）」。后来「新建生产订单」表单有了下拉，但 MRP / MPS 两条「一键下达」仍只走默认版本。本版补齐：

- **MRP 下达**：改成复用「新建生产订单」表单（预填产品编码 + 数量），下达前先选工艺版本。
- **MPS 下达**：`mps_convert_to_order` 加 `version` 参数写进订单的 `routing_version`；前端下达时弹「选工艺版本」再提交。

## 凭证键集分页评估关闭

v1.8.2 记「凭证列表键集分页后端已就绪（`list_page_keyset`），前端切换后续版本接入」。本版评估后**不接入前端**：

- `list_page_keyset` 按 `id`（录入先后）排序，与会计习惯的 `(日期, 凭证字, 凭证号)` 排序冲突，补录历史凭证会乱序。
- 凭证列表按期间筛选（一个月几百张），OFFSET 分页已足够快，键集优化的收益不存在。
- 维持现有 OFFSET 分页（`list_page` + `/vouchers/page`），此「待接入」标记为已评估关闭。

## 三条规矩

1. **申报表只取数、不网报**：增值税主表 / 附表的申报口径展示与导出都只算本地数据，实际申报仍在电子税务局完成。
2. **下达必须选版本**：工序清单、报工与计件单价都按所选工艺版本算，不能再事后用接口 `?version=` 补。
3. **凭证分页以会计排序优先**：为翻页快而把凭证按录入先后排序（乱序）不可接受，OFFSET 分页在按期间筛选下足够快。

## 升级说明

无 schema 变更，无需操作。桌面端「期末」菜单多一项「纳税申报」；MRP / MPS 下达生产订单时多一步选工艺版本。

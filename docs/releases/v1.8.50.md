# v1.8.50 —— 催款函、现金流上期对比，以及一条"我以为缺"的测试

三件事都是从「继续查明没做的」里翻出来的。前两件是真缺，第三件是我的误判 —— 而误判
本身值得记一笔。

## 一、催款单：导得出 Excel，但发不出一封函

催款单早就有 Excel 导出（汇总 + 明细），问题是**客户收到一张表，不知道这是什么**。
要发给客户的东西得长得像封信。

现在每个催款单能打成一页 A4 文书：抬头 / `致：XX 公司` / 欠款总额一句话 / 逐单明细 /
合计 / 落款。三个细节：

1. **每单都写逾期几天**，不只给总数。客户手里十几张单，说「你欠我 5 万、最早那笔超了
   24 天」，不如说「XSQ-8801 超期 24 天、XSQ-8802 超期 3 天」——后者能直接对上账。
   逾期按 `(开函日 − 单据日) − 账期` 算，账期取客户档案里的 `pay_days`（v1.8.48 落地
   的那个字段）；档案没填就**不标逾期**，不拿 0 天假装「没超」。
2. **预收/预付不进合计**，但在函末单独说明：「另：账面记有贵方预交款 3,000.00，已单独
   列示，未计入上面的合计。」混进合计客户会以为我们记错了账。
3. **版式认账套设置**：纸张、页边距、页码走 `PrintOptions`。能打印的东西就该跟别的
   打印件一个规矩。

网页端催款单→「打印函」；老催款单没有逾期字段（`serde(default)` 得 0），**不追溯重算**
——那是当时那封函上写过的数字，重算等于改历史单据。

## 二、现金流量表：只有本期，看不出好坏

「经营现金流 5 万」本身没有信息量，比上期多了还是少了才有。现在现金流表多一张
**「本期与上期对比」**：项目 / 本期 / 上期 / 变动。

- Excel 导出两张纸，网页表底一行摘要（上期区间、上期净额、本期变动），JSON 里多
  `prev` 与 `delta` 两块。
- **上期取等长的上一段**，不是「上月」。本期 3 个月就取上一个 3 个月，否则季度报表里
  会出现「3 个月 vs 1 个月」的假对比。
- **上期有、本期没有的项目不能消失**，要单列并标「（上期有）」。「上月买了设备、这月
  没买」正是同比最该看见的事；按本期循环一遍就收工会把它吞掉，而两张表看着都挺对。
- 对比只比**净额**：流入/流出两列塞进 A4 横向会挤爆，决策看的就是净额。

## 三、期初收集表：低频科目其实一直在

我一度以为模板只列了常用科目（在建工程、预付账款没进去）。查代码发现模板按
1xxx / 2xxx **末级科目全量**生成，只排除了由客户/供应商两张纸自动生成的 1122/2202。

也就是说「缺」是我的错觉。所以这一版的产出不是补科目，而是**补一条测试**：

```
opening_template_lists_low_frequency_accounts_too
  → 1123 预付账款、1604 在建工程、2203 预收账款、2501 长期借款 都在表里
  → 「③ 账户余额」里没有 1122/2202（那两个由两张纸生成，再填一遍会双计）
```

以后谁想「让表短一点」加白名单，这条会当场报红。「以为缺」和「真的缺」之间隔着一行
断言 —— 这条比补三个科目值钱。

## 测试与验证

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **1056** 全绿 |
| 新增测试 | `findb` 催款逾期 2 条；`finweb` 库 2 条（对比表保留上期独有项目、期初模板含低频科目）；`finweb` `dunning_letter.rs` 2 条（是一封函 / 未知 id 404） |
| 变异验证 | 3 条全部拦下（催款明细不算逾期 / 没设账期硬算逾期 / 对比表吞掉上期独有项目），下限 98→**101** |
| 自检 | check-ci / check-js / check-portable / check-design-doc / check-simple-nav 全过 |

顺带修了 README 基线表的一处陈账：**分项相加比实测多 10 条**，说明有若干行的数字早就
没跟着套件改动更新。已在表上方写明「小计是 `cargo test --workspace` 的实测合计，分项
是各套件近似条数，不一致以小计为准」，并把逐套件核对列进待办 —— 不假装已经对齐。

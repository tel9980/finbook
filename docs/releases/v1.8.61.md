# v1.8.61 —— 部门核算：从「装了不能用」到「算得对、看得该看的」

这一版把部门核算这条线从头到尾走通：默认科目表真的能录部门了，结转凭证带得住部门，
部门会计看到的明细账与凭证列表是同一套数。全部来自模拟数据体检脚本 `qa_sim`
（新增，`cargo run -p findb --example qa_sim -- /tmp/qa.fbk`）跑出来的问题。

## 一、部门核算开箱不可用（死代码）

`apply_extras()` 把 `AuxKind::Dept` 挂在 5001/5101/6601/6602/6603 上，而这五个全是
**上级科目**；紧接着 `default_accounts()` 会把所有非末级科目的 `aux` 清零。两下一凑，
默认科目表里挂了部门的末级科目是 **0 个** —— 用户想用部门核算，得先把文档读一遍、
再一个科目一个科目手工打开。体检脚本第一行就把这个数打出来了。

改成挂到 **35 个末级科目**（500101..500104、510101..510105、660101..660109、
660201..660212、660301..660305），上级科目一个不挂。

## 二、部门不能算「必填」

放开末级科目之后，`cargo test --workspace` **崩了 24 个用例**：成本分摊、制造费用结转、
费用计提、存货跌价准备这些**系统自动凭证**没有人可以选部门，一路
`第 2 行科目 660201 核算部门，必须填写部门`。

所以部门定为**可选维度**：不填就是「全公司 / 未分配」。这与另外三处早就存在的口径一致
——`DataScope::allows_dept("")` 恒真、`can_see_voucher` 放行没打标签的分录、多维损益里
有一行「未分配」。小微公司本来也未必建部门档案。

## 三、结转损益保不住部门（真 bug，会把账期卡死）

`carry_forward_rows` 用 `for_account(code, None)` 取数，把各部门的分录**聚成一条 aux 为空
的行**；`generate_carry_forward` 只是照抄这条空 aux。于是部门账套点「一键结转」直接报
校验错 —— 而 `period_end.rs` 的文档写着「保留辅助核算维度，可按部门 / 项目出利润表」。

改成：有辅助维度的科目走 `aux_breakdown` 逐维度出行。实测（真 HTTP、真账套）：

```
POST /api/periods/202612/carry-forward → 200 {"id":301,"voucher_no":"记-0025"}
  510101/D01 6600 · 510101/D02 7400 · 510101/D03 8200
  660201/D01 7200 · 660201/D02 8000 · 660201/D03 6400
  600101 借20400 · 4103 借23400
```

修复前同一调用是 400。

## 四、部门口径的边界：明细收窄，汇总不收窄

部门范围早已下推到凭证列表，但账簿一直照旧按全公司合计：同一个部门会计，凭证列表
192 张（看不到别部门），余额表却是三部门合计 238800（本部门真值 79600）。

第一版想「一起收窄」，测试立刻报**试算不平衡**：借方 400、贷方 600。原因在账务事实
——费用凭证借方挂部门、贷方「银行存款」不挂，按部门切分录必然切不平。

定案：

| 一类 | 出口 | 部门 |
|------|------|------|
| 逐笔 | 凭证列表/导出、明细账、总账、日记账、出纳日记账、科目日报表 | **收窄** |
| 汇总 | 科目余额表、试算平衡、资产负债表、利润表、现金流量表 | **不收窄**（公司口径） |

代码上这条边界是显式的：`with_user_scope` 故意不动部门，需要收窄的账簿再调
`with_dept_scope`。

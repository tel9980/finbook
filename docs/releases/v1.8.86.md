# v1.8.86 —— 网页版首页也有「那一句话」了

这一版把桌面版首页的两样东西补到网页版，并且把**判断收到一处**：
同一本账，网页版和窗口版说的是同一句话。**不改数据结构、不改记账规则**，
`1.8.85` 的账套可以直接用。

---

## 一、问题：教程教你看那行字，网页版里没有

`docs/小白日常操作教程.md` 第二节写得很清楚：

> 点左侧「首页」。**不用看懂所有数字**，从上往下只需要看三处。
> 第一处：**那行带 ⚠ 的话** —— 说的就是接下来该先办哪件事。

可是这行字**只在桌面版（窗口版）里有**。用网页版的人照着教程去找，
首页看到的是：一行标题、两块数字（利润 / 钱在哪）、一排待办按钮、
一排业务卡 —— 没有任何一句话告诉他「你现在该先干什么」。
「账有没有记错」也是同样情况：桌面版首页有，网页版没有。

## 二、改法一：网页版首页最上面加一行话，一次只说一件

```
⚠ 还有 3 张凭证没记账，下面的 8,000.00 是「已记账部分」的利润，可能偏小。
  去「凭证查询」勾选后批量记账，数字才是完整的。           [去处理]
```

右边那个按钮直接跳到该办的页面，不用自己去左侧菜单里找。

**优先级（顺序本身就是设计，不是随手排的）**：

| 顺序 | 什么情况 | 为什么排在这个位置 |
|---|---|---|
| 1 | 有凭证没记账 | 没记账的凭证**不算进利润**，这时显示的「赚了多少」是偏小的。拿着偏小的数去报价、发工资就会错 |
| 2 | 客户的钱超过 90 天没收回 | 小厂最常见的死法不是不赚钱，是赚的钱全压在客户手里，房租工资还得按月付 |
| 3 | 净欠外面（欠供应商多于别人欠你） | 不喊急，但提醒看一眼手头现金够不够付 |
| 4 | 本月还没有收入凭证 | 多半是还没开始录，先去记第一笔 |
| 5 | 都没事 | 一句放心话 + 月底四步：记账 → 结转损益 → 结账 → 备份 |

**为什么「净欠外面」必须应付不为零才算**：客户预交的订金也是「我欠他」，
但它不该让你去安排一笔付给供应商的钱。少了这个条件，预收会被说成欠款。

## 三、改法二：网页版首页加一块「账有没有记错」

```
✔ 账是平的，没有记错的凭证，可以放心出报表。
```

不平的时候直接说差多少、去哪查：

```
✖ 账不平，有凭证记错了。差 100.00，去「凭证查询」逐张看
  —— 通常是某张凭证只填了借方没填贷方。
```

六个数（期初借/贷、本期借/贷、期末借/贷）不上首页，要看去「报表 → 试算平衡」。

**两个诚实边界**：

- **算不出来就说算不出来**。取不到数时显示「账平不平暂时算不出来」，
  绝不在算不出来的时候写一句「✔ 账是平的」—— 那是首页最不能出错的一句话。
- **三期都平才算平**。只看期末会被「期初借多、本期贷多」这种正好抵消的错账
  骗过去；差额也报第一处不平的那一处，否则用户按这个数一查就对不上。

## 四、改法三：判断收到一处，两端不可能再说两种话

原来桌面版 `Dashboard::verdict()` 自己写一套文案和优先级。现在搬到
`crates/findb/src/verdict.rs`，两端都调它：

| 位置 | 改动 |
|---|---|
| `crates/findb/src/verdict.rs`（新） | `verdict(&Facts)` 给一句话 + 类型（`unposted/overdue/net_debt/no_revenue/ok`）；`trial(&TrialBalance)` 给账平不平的结论。不碰数据库，只吃数字 |
| `crates/finui/src/views/dashboard.rs` | 删掉自己的文案，改为填 `Facts` 再调 `findb::verdict`；「账有没有记错」原来只比期末借贷，现在与网页版一样三期都平才算平（顺带修掉一个只在桌面端存在的漏判） |
| `crates/finweb/src/handlers.rs` | `home_brief` 组装同一个 `Facts`；`/api/dashboard` 的 `brief` 多 `verdict`（kind/text/view/urgent）与 `trial`（balanced/diff）两个字段 |
| `crates/finweb/static/app-dashboard.js` | 新增 `homeVerdict()` / `homeTrial()`，颜色与跳转**只看 `kind`**，不匹配文字 |

**为什么必须收成一处**：两套判断最容易出的不是崩溃，是「同一本账两种说法」——
网页说先去催款、窗口说先记账，用户会以为其中一个算错了。
判断属于会计逻辑，不属于界面。

接口只增字段，老前端忽略新字段照常工作；无 schema 变更。

**顺带修掉的一个漏判**：桌面端原来只比期末借方合计和期末贷方合计。
「期初借多、本期贷多」这类正好抵消的错账会让期末看起来是平的，
桌面端显示「✔ 账是平的」。现在两端都按三期判，这条漏洞一起补上了。

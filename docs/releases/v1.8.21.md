# v1.8.21 — 导入导出：进得去，也得出得来

## 一句话

基础资料能导出成 Excel 改完再导回；三大报表能导出成真数字的 xlsx；网页端可以直接上传 `.fbk` 账套（桌面版建的、别的服务器搬来的都行）。

## 原来的问题

Web 端的「进」很宽，「出」很窄：

| 能力 | 之前 | 现在 |
|------|------|------|
| 客户/供应商/存货/科目/期初导出 | **没有任何导出按钮** | 各页一个「导出 Excel」 |
| 报表导出 | 三大报表只有打印页，试算平衡只有 CSV/PDF | 全部 xlsx，金额是真数字 |
| 网页端上传 `.fbk` | **做不到**（只认服务器自己生成的备份） | 「导入账套」按钮，支持 `.fbk` 与 `.zip` |

用户的原话是「优化账套、基础资料、报表的导入导出」。三块里最硬的是第三块：
桌面版辛苦建好的账套，一个字都搬不上云。

## 具体做了什么

### 1. 基础资料导出：列头就是接口

`crates/finweb/src/sheets.rs` 里每张表的列头与 `findb::imports` 的解析器**逐字对应**，
顺序也不动 —— 导入器是按列下标取值的，一旦顺序变了不会报错，它会把名称写进备注，
「成功」但数据错位。

- 辅助档案：`类型,编码,名称,备注`
- 存货档案：`编码,名称,保质期天,安全库存`
- 会计科目：`编码,名称,类别,方向,备注`（+ 一列只读的辅助核算提示）
- 期初余额：`科目编码,科目名称,方向,期初余额,累计借方,累计贷方`，贷方写成「贷 + 正数」

停用档案不导出（导回去会被当成要新建的）。

### 2. 顺手修掉两个真缺陷

**① 期初余额导入整批丢行。**
`/api/import/template?kind=begin` 导出的官方模板是 6 列，而 `ImportTemplate::Generic`
按 3 列解析 —— 方向列读到「库存现金」、金额列读到「借」，`MoneyWarn` 判定「借」
不是金额，**每一行都被跳过**。用户下载官方模板照着填、一条也导不进去，提示是
「期初余额「借」无法识别为金额」，完全看不出是列错位。

修法不改模板（模板已经发出去了），让解析器认两种布局：第 2 列是不是借/贷/平
即可判别。判据安全 —— 另一种布局的第 2 列是科目名称，不可能只有一个「借」字。

**② 现金流量项目档案无法经数据导入迁移。**
`aux_kind_of` 的匹配表里没有 `CashFlow`，于是「导出全部辅助档案 → 导进另一个账套」
这条闭环里，现金流量项目必然被丢。已补上 `现金流量 / 现金流量项目 / 现金流 / cashflow / cf`。

### 3. 报表导出：不另起一套取数

`crates/finweb/src/xlsxout.rs`：`Sheet { name, title, subtitle, headers, cols, rows, emphasis }`
→ 一份 xlsx。金额列是 `#,##0.00;[Red]-##,##0.00`，**空金额写空白而不是 0**
（写 0 会让合计对不上，也分不清「真的是 0」和「这行没有数」）；`emphasis`
把「小计/合计/净增加额」行加粗。

报表导出直接复用 `statement_table` / `cash_flow_statement` / `equity_statement`
—— 与打印页同一条取数路径。另起一套的后果是两张表都「挺对」但数字不一样，
而且没人说得清哪个对。

现金流量表末尾把勾稽结论（`ties()`）和「未标注现金流量项目的金额」写进表里 ——
导出的表是拿来发的，收表的人看不到页面上的那行绿字。

### 4. 账套上传

`POST /api/books/import`（仅管理员，单次上限 512MB，每账号仍受 10 个账套限制）。

顺序是刻意的：**写临时文件 → 校验 → `Db::open` 迁移 → rename → 注册**。三步校验
缺一步都会出问题：

1. `PRAGMA integrity_check` —— 传一半断线的文件仍能被 SQLite 打开；
2. 有没有 `account` 表 —— 任意 Sqlite 文件都能被 `Db::open` 迁成一个科目全空的账套；
3. schema 版本不能比本二进制新 —— 否则第一次用到新列就 `no such column`，
   而错误里没有任何线索指向「版本太新」。

支持 `.zip`（本系统「下载备份」的产物：`.fbk` + `.attachments/`），因为那是**唯一
能带走附件的格式**。zip 里只收「根目录下的 `.fbk`」和「`.attachments/<扁平名>`」，
含 `..` 或额外目录层的条目一律丢弃。

导入后会把平台管理员的平台口令哈希种成账套内管理员（与 `create_book` 一致），
否则上传上来的账套谁也进不去。

### 5. 桌面端与网页端：导出档案能原样粘回去

这一块是做的过程中发现的真缺陷，不是新功能。

桌面端「辅助核算档案」的导出表是五列（`编码,名称,上级编码,状态,备注`），
而批量粘贴的解析器只认前两列、且**表头判定要求整行都是表头词**。于是把导出的表
原样粘回粘贴框：

1. 表头行（含「上级编码」「状态」「备注」）不算表头 → 被当成数据，
   凭空多出一条名为「编码 名称」的垃圾档案；
2. 停用状态、备注、上级编码全丢 —— 导出的表导不回来，导出就没有意义。

修法：解析器改成**有表头就按列名取值**（`编码/名称/上级编码/状态/备注` 任意顺序、
任意列数），没有表头仍按原来的位置推断（行为不变）。安全判据是「整行不能有任何
一格长得像编码」—— 否则名称恰好叫「编码」的真实数据（`C01,编码`）会被当表头吞掉，
那是最难查的一类丢数据。

网页端同步补齐：`/api/aux-batch` 的预览与导入都带上上级/备注/停用；
档案导出与导入模板加了两列（老的四列文件照旧能导，越界按「没写」处理）；
`/api/aux` 支持 `include_disabled=1`，档案页加了「显示停用」勾选框 ——
原来网页端**根本看不到停用档案**，「停用」等于单向操作，停掉就找不回来了。

这个勾选框第一版写错了：把「是否显示停用」存成 `viewAux` 的局部变量，却在
`renderAux` 里引用 —— 那是另一个函数，运行到那一行直接 `ReferenceError`，
整个档案页白屏。`node --check` 一句话都不说（语法完全合法），是 CI 的
Playwright **抓到的**。E2E 跑一次半小时、失败还得翻 trace，于是补了
`tools/check-app-render.js`：把视图函数原文抽出来、给一组最小的桩**真调用一次**，
引用到作用域外的名字就当场抛错，一秒出结果。加桩时要给全（少给一个就误报），
但**不能**给「什么都返回」的万能桩 —— 那就又变回假绿了。已接进 `check-js.js`。

## 测试

876 → **910** 条，新增 34 条：

- `fincore` 170 / `findb` 398 / `core_loop` 21 / `ext_loop` 7 / `oxide_demo` 2 /
  `finui` 59 / `finweb` lib 24 / `api.rs` 193 / `aux_preset` 4 / `batch_paste` 13 /
  `customers` 9 / **`export_xlsx` 6** / **`roundtrip` 4**

三份证据，缺一不可：

| 测试 | 证明什么 |
|------|----------|
| `crates/finweb/tests/roundtrip.rs` | 导出的**字节**喂回 `imports`，数据能还原（含科目方向、辅助维度） |
| `crates/finweb/tests/export_xlsx.rs` | 路由真的挂着、权限真的生效、附件头正确、坏文件真的被拒 |
| `tools/mutate-rust.js` 新增 7 条变异 | 上面两条测试在代码被改坏时**真的会红** |

新增的 7 条变异（都手工跑过、确认 FAILED 才写进清单）：

1. 期初导入不再识别 6 列布局 → 整批丢行的回归测试红；
2. 辅助档案不认现金流量项目 → 迁移测试红；
3. 上传账套不再核对科目表 → `upload_rejects_non_finbook_file` 红；
4. 科目导出不带方向列 → `科目导出后类别与方向能导回` 红
   （报错原文：方向被类别默认值盖掉了 —— 导出必须写方向列，导回必须认它）；
5. 导出文件的表头又被当成数据 → `导出的五列表头不会被当成数据` 红；
6. 导入档案不还原停用状态 → `停用与上级编码导出后能导回` 红
   （报错原文：停用状态丢了 —— 停掉的客户又冒出来了）；
7. 表头只认全等、不认「客户编码」这种带类别前缀的 → `带类别前缀的表头也认得` 红。

第 7 条差点又写成假绿：一开始测试数据用的是 `C01`，而「编码列没认出来」时会退回
自动编号、恰好也发出 `C01` —— 改坏代码照样通过。把数据改成 `C05` 才逼出区别
（断言原文：编码列必须认出来，不能退回自动编号）。这就是「断言不要写在被测逻辑
刚好也会产生同一个值的地方」。

> 「测试必须真的会红」这条在 v1.8.19 栽过一次：当时用 `include_str!("lib.rs")`
> 断言源码里含某个调用，而断言用的字符串本身就写在测试里，永远为真 —— 假绿。
> 所以这次每条变异都落地跑过，不是照着格式填的。

## 顺手修的检查器

`tools/check-ci.js` 里「变异指向的测试必须存在」那一步，原来硬编码了 3 个文件
（`api.rs` / `user.rs` / `users.rs`）作为搜索范围。新增测试 target 后，指向它们的
变异一律被报「已不存在」；反过来，改那 3 个文件里的测试名时检查照过，而指向别的
target 的变异可能早就名存实亡。改成扫 `crates/` 下全部 `.rs`，慢一点（269 个文件），
但不会再出现「新加的 target 没登记」这类静默失效。

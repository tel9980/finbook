# v1.8.19

**精简模式：勾了不生效、取消了白改 —— 选择存不住。**

## 症状

侧栏底部那个「精简模式」勾选框，点了之后菜单当场是对的，但**退出程序再打开就回到原样**。

- 取消勾选 → 侧栏立刻展开全部菜单 ✅ → 关掉程序 → 重开 → 又勾上了
- 勾上 → 侧栏立刻收成 17 项 ✅ → 关掉程序 → 重开 → 又没了

用户以为是「精简模式坏了」，反复勾也没用。

## 根因

两个地方各错一半，凑成「当场生效、存不住」：

**① `save()` 重算覆盖。** 原来写的是：

```rust
fn save(&mut self, storage: &mut dyn eframe::Storage) {
    self.persist.simple_nav = Some(effective_simple_nav(&self.persist));
    ...
}
```

右侧的 `self.persist` 还是**上一帧**的值，跟用户刚点的结果没关系。等于每次落盘都把用户的修改盖掉。

**② `update()` 里的勾选框改的是局部量。** 每帧开头 `let mut simple_nav = effective_simple_nav(&self.persist);`，勾选框改这个局部量，但除了 `save()` 没有任何地方把它写回 `self.persist`。于是：

- 侧栏渲染用的是局部量 → **当场看着是对的**
- 落盘用的是 `self.persist` → **永远没变过**

两个错合起来，正好是用户看到的样子：当场生效，重启失效。

## 改法

把「局部量 → 事后同步」这条路整个删掉，`side_bar` 直接拿 `&mut Persist`：

```rust
fn side_bar(st: &mut AppState, ui: &mut Ui, persist: &mut Persist) {
    let mut simple_nav = effective_simple_nav(persist);
    ...
    if ui.checkbox(&mut simple, "精简模式").changed() {
        simple_nav = simple;
        persist_simple_nav(persist, simple);   // 点了就落盘，不等 save()
        ...
    }
}
```

`save()` 里只剩一件事：从没明确选过（`None`）的用户，固化成默认精简。**不再重算。**

## 测试

新增 3 条，覆盖选择能跨重启保留：

- `unchecking_survives_restart` —— 取消勾选 → 序列化 → 反序列化 → 仍是完整菜单
- `rechecking_survives_restart` —— 反向
- `sidebar_choice_survives_save` —— `save()` 不会把用户的选择改回去

> 坦白记一笔：这条路上我写废了两版测试。第一版只测 `persist_simple_nav` 自己，
> 把 `side_bar` 里的调用删掉照样绿；第二版用 `include_str!("lib.rs")` 断言源码
> 里有那行调用 —— 也被变异测试证明是假绿，因为**断言的字符串本身就在测试里**。
> 最终留下的是老实的三条：能往返、不被覆盖。

# v1.8.110 按账期每月应收应付明细（到期月表）

## 问题

老板想知道「接下来哪个月该收多少、该付多少」，好安排资金。账龄分析只往回看（这笔钱已经欠了多久），看不出「下个月有哪几张单到期」；要把未核销的往来单据按「到期月」归拢，才能一眼看到未来几个月的现金流节奏。

## 改法

把未核销往来单据按「到期月」归拢，应收（1122 客户）、应付（2202 供应商）一次出两边：

- **取数复用账龄**：把 `aging()` 内部「取未核销单据」抽成私有 `aging_items()`，新增 `ar_ap_due_schedule(db, ar_account, ap_account, upto)` 复用同一份取数——往来维度判定、方向翻转、期初影子行的口径只此一个定义点，账龄和到期表不会分叉。
- **到期日 = 单据日期 + 账期天数**：账期读 `pay_days_map`（与账龄、回款看板、催款函同一来源）；没设账期按 0 天（货到即付）。
- **到期月 = 到期日的年月**：每条未核销单据出一条 `DueEntry`（kind=ar/ap、party、doc_no、date、due_date、month、amount），按「月 → 类型 → 对象 → 到期日」排序。
- **前端**：往来核销工具栏在「账龄分析」旁加「按月应收应付」按钮，渲染月度汇总表（到期月 / 应收到期 / 应付到期 / 净额，净额为负标红）+ 明细表（类型 / 对象 / 单据 / 日期 / 到期日 / 到期月 / 金额）。

## 三条规矩

1. **与账龄同源**：`ar_ap_due_schedule` 直接调 `aging_items`，不另写一套「哪些算未核销」的口径。
2. **账期一致**：到期日用的 `pay_days` 与账龄、回款看板、催款函三处同一个 `pay_days_map`，客户档案里「账期」只此一份。
3. **应收应付同屏**：一次请求把应收（1122）与应付（2202）都算出来，月度汇总还给了净额（应收 − 应付），一眼看出哪个月是净流入、哪个月是净流出。

## 测试与门禁

- finweb 集成 `settle_due_schedules_open_entries_by_due_month`（`GET /api/settle/due` 200，月份汇总 + 明细两行全对）。
- 渲染门禁 `dueMonthHtml` 两用例（有数据 / 空）。
- 变异 134（漏掉应付）、135（账期没接上）实跑拦下。
- clippy 0 error、preflight 六步全绿。

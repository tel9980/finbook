# v1.8.46 —— 现金流量表：没人标注，也得把表填出来

现金流量表是直接法：一笔现金收支归到哪个项目（销售商品收到的现金 / 支付的各项税费……），
本该由录凭证的人标。小厂没有这个人——老板娘能照着教程把借贷写对，不会记得再给「100201
借方」点一个现金流量项目。

结果：报表**勾稽得上**（净增加额 = 期末 − 期初货币资金），内容却一片空白，全落在「未归集」
里。老板看到一张等于没用的表，而且看不出是「没发生」还是「没标」。

## 三级归集顺序

1. **凭证上标了就听凭证的**。人工标注永远优先，规则不许覆盖。
2. **按对方科目推断**。「借 100201 / 贷 600102」里的 `600102` 就是对方科目，它天然说明了
   这笔钱是什么性质。
3. **推不出来就留在未归集**，并在界面上说清有哪几笔、多少钱。

## 只在能确定时猜

一张凭证的对方科目指向**两个不同**项目时不猜：

```
借 100201  50,000        ← 收了一笔钱
贷 600102  30,000        ← 像收货款（0101）
贷 160101  20,000        ← 又像卖设备（0203）
```

这种情况记进 `ambiguous` 计数、金额留未归集，界面写「1 笔对方科目指向不同项目、未归集」。

**猜错的现金流量表比空表更糟**：空表用户会去补标注，错表用户会拿去用。

## 三个必须处理的例外

**① 税额是伴生行。** 最常见形态是收入带销项税：

```
借 100201  113,000
贷 600102  100,000
贷 22210102  13,000   ← 销项税额
```

按「两个对方科目分不清」处理的话，**每张带税凭证都会变成未归集**，规则等于白做。所以：
对方科目里同时存在 `2221×` 和其它科目时，`2221×` 不参与投票，跟着主业务走。（`2221` 单独
出现仍管用：借 2221 / 贷 银行 = 交税 → 0106。）

**② 提现不是现金流量。** 借 1001 / 贷 100201 的对方科目也是货币资金，这类凭证整行跳过——
既不能归集也不能算未归集。以前它会让未归集凭空多出两笔正负相抵的数。

**③ 方向决定项目。** 同一个科目，收和付可能归到不同项目：

| 对方科目 | 现金流入 | 现金流出 |
|---------|---------|---------|
| 2221 应交税费 | 0102 收到的税费返还 | 0106 支付的各项税费 |
| 1601 固定资产 | 0203 处置长期资产收回 | 0204 购建长期资产支付 |
| 2001 短期借款 | 0302 取得借款 | 0303 偿还债务 |

规则用**最长前缀匹配**，所以「660301 利息支出」能比「6603 财务费用」更具体地归到筹资活动
（0304 偿付利息），不用为一个特例改结构。

## 三端同一句话

归集情况的措辞收在 `CashFlowStatement::assignment_note()` 一处，桌面端、网页、Excel 导出
都用它。这是 v1.8.27「打印版式」的教训：同一件事写在三个地方，迟早会分叉。

## 一个自己造的事故，和一个补上的守卫

收尾跑全量测试时 `begin_rejects_nonexistent_account` 报红，查下去发现：`save_begin` 里那句
`if !codes.is_empty() {` 变成了 `if false {` —— **是我之前跑变异测试时被打断，源码留着变异
后的样子**。那意味着「期初录到不存在的科目」这条校验一直是关着的，而没有任何报错。

两处收口：

- `tools/check-ci.js` 本来就有一条「变异已失效」检查（`from` 串在源码里定位不到就报红）。
  我实测确认它**能**抓到这次残留（临时把那行改成 `if false`，立刻报
  `FAIL mutate-rust 的变异已失效：③ 去掉期初的科目存在性校验`）——只是残留出现后没人再跑过它。
- `tools/mutate-rust.js` 加锁文件 + 信号还原：跑之前把原文 base64 写进 `.mutation-lock.json`，
  下次启动先按它还原；`SIGINT`/`SIGTERM`/`SIGHUP` 也会先还原再退出（`finally` 挡不住 Ctrl-C，
  这就是残留的来源）。已实测：预置锁文件 + 把源码改坏 → 启动即打印「上次变异没跑完就退出了，
  已按锁文件把源码还原」。

## 测试与验证

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **1036** 全绿（fincore 196 / findb 427 / finweb api 194 / cashflow_auto 8 / 其余不变） |
| 新增测试 | fincore 规则 9 条（含「规则里写的项目编码必须真的存在」）+ 归集说明 1 条；findb 端到端 8 条；findb `reports` 改写 2 条 |
| 变异验证 | 5 条全部拦下（规则表静默不生效 / 未归集不计入净增加额 / 税额伴生行也投票 / 提现被当成未归集 / 人工标注被规则覆盖），下限 85→**90** |
| 自检 | check-ci / check-js / check-portable / check-design-doc / check-simple-nav 全过 |

「规则里写的项目编码必须真的存在」这条测试看起来笨，但它挡的是：手打错一位（`0101` 写成
`0110`）的后果是整类现金收支静默落到未归集，报表上既没有金额也没有报错。

## 怎么用

不需要做什么。录凭证时照旧只填借贷；现金流量表打开就是有数的。系统会在表下方注明
「N 笔按对方科目自动归集」——**想让某一笔归到别的项目，回凭证上手工标一个，规则就听你的**。

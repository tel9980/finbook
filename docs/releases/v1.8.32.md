# v1.8.32 —— 把 26 分钟的 Windows 构建从 push 上拿走

v1.8.31 把变异测试分片后，CI 里最后一块「不合理的长」露出来了：**它不是变异测试**。

## 现状：一个 job 吃掉整个 CI

上一次完整 CI（`d3f1f23`）逐 job 耗时：

| job | 耗时 |
|-----|------|
| **Build (Windows x64)** | **26.5 min** |
| Web E2E (Playwright) | 7.0 min |
| Mutation shard 1/4 | 7.0 min |
| Coverage (backend) | 6.1 min |
| Test | 6.0 min |
| Mutation shard 2/4 | 5.6 min |
| Mutation shard 3/4 | 5.3 min |
| Mutation shard 4/4 | 3.5 min |
| Build (Linux x64) | 2.8 min |
| 其余 5 个 | 各 < 2 min |

也就是说：**这一个 job 的时长超过所有并行 job 的总和**，而它是 CI 的关键路径——
别的 job 早就跑完了，界面上的转圈还在等它。

更关键的问题是：**它的产物没人用。** 那个 job 交叉编译出 `finbook.exe` 与
`finweb.exe` 就打包成 artifact 挂在那里，从来没有任何 job 下载它；Windows 发行包
是 `release.yml` 里的 `desktop-windows` 在打 tag 时**另建一遍**（且只建
`finbook.exe`）。每次 push 白等 26 分钟，产出一份丢掉的 exe。

## 改法：push 只 `cargo check`，release 编译留给 tag

```yaml
# ci.yml —— push + PR
check-windows:
  name: Check (Windows x64 target)
  steps:
    - run: cargo check --locked --target x86_64-pc-windows-gnu -p finbook -p finweb
```

`cargo check` **不链接**，所以连 mingw-w64 都不用装（`cargo check` 只做类型检查与
MIR 生成，产出的是 `.rmeta`），整个 job 两三分钟。它覆盖的是 push 阶段真正会踩到的
那类错：某个 `#[cfg(windows)]` 分支写错、某个只在非 unix 目标编译的依赖失效、
`std::os::windows` 用法笔误。

真正的 release 交叉编译保留在 `release.yml` 的 `desktop-windows`（打 tag 时跑）。

## 代价，说清楚

`cargo check` **不覆盖链接阶段**的错：

- 引用了 mingw 里不存在的库（`-lws2_32` 之类拼错）
- 导出符号冲突 / 重复定义
- 需要链接期资源（`.rc` 版本资源、manifest）

这类错误现在只能在打 tag 时暴露。判定：这类错**极少**，一旦出现也只需要改链接参数，
不需要改业务代码；而 26 分钟 × 每次 push 是天天在付的确定性成本。所以换了。

## 这条分界有人盯着

`tools/check-ci.js` 新增第 **2.45** 项，三个方向都会报红：

| 有人干了什么 | 报错 |
|--------------|------|
| 把 release 交叉编译加回 `ci.yml` | `FAIL ci.yml 又在 push 阶段做 Windows release 交叉编译了（那是 26 分钟的那个 job…）` |
| 把 `check-windows` 整段删掉 | `FAIL ci.yml 缺少 Windows 目标的 cargo check —— push 阶段就没人看 Windows 分支了` |
| 把 `release.yml` 的 Windows 编译删掉（「挪到 tag」变成「没人编」） | `FAIL release.yml 不再在 tag 上交叉编译 Windows release` |

两种改坏方式都实测报红，还原后通过。

## 预期效果

| 指标 | 改前 | 改后（预期） |
|------|------|--------------|
| Windows 相关 job | 26.5 min（release 编译） | 2~3 min（check） |
| CI 壁钟时间 | ~26.6 min | 由 E2E / 变异分片决定，约 **7~8 min** |

实际数字以本版 CI 运行为准，跑完再核对。

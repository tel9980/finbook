# v1.8.121 单据取号去 O(n²) + 已记账凭证 DB 触发器 + 工作台投影裁剪 + 金额门禁

对标 GitHub 同类项目（erp-mafia/accounted、actualbudget/actual、hledger）后的四项加固，按 P0→P2 一次交付。纯后端/工具链改动，无界面变化。

## A. 单据取号：O(n²) → 吃索引

**问题**：`po_next_no` / `so_next_no` / `prod_next_no` / `landedcost::next_no` / `claim_next_no` 五处取号用 `MAX(CAST(SUBSTR(no,N) AS INTEGER)) ... WHERE no LIKE '前缀%'`。`LIKE` 让 `no` 上的 UNIQUE 索引失效，每次取号全表扫——批量导入 5000 张单实测 105 秒，是 O(n²) 写路径瓶颈。

**改法**：新增 `findb::next_seq_by_prefix(conn, table, prefix, suffix_start, period)`，把前缀末字符码点 +1 算上界，改为 `WHERE no >= ?1 AND no < ?2 [AND period=?3] ORDER BY no DESC LIMIT 1`，吃现有索引；Rust 侧解析后缀 `+1`。零语义变化、零事务改造、不动 schema、不动 30+ 调用点（五个函数签名不变）。报销单保留 period 过滤。

## B. 已记账凭证不可静默改删下沉 SQLite 触发器

对标 accounted 的 enforcement triggers：会计不变量下沉到数据库。四个 `CREATE TRIGGER IF NOT EXISTS` 幂等装在 `schema::init` 尾部（不升 SCHEMA_VERSION）：

- `trg_voucher_posted_update` / `_delete`：已记账凭证的会计内容（period/date/word/attachments/source/memo）篡改与删除拦截；
- `trg_voucher_entry_posted_update` / `_delete`：分录任意改删拦截。

违规 `RAISE(ABORT, ...)`。**放行**状态流转（反记账/作废/恢复）、更正链、经办人元数据、号重排、updated_at——这些不是「钱」，是归因轨迹。`clear_vouchers()` 清库前先置 draft。

不做期间锁下沉：应用层四处已覆盖，下沉与测试造数冲突、收益低于风险。

## C. 工作台「快到期」轻量投影

**问题**：`workbench::collect` / `collect_todos` 用 `ar_ap_due_schedule` 构造全量 `Vec<DueEntry>` + 全量排序，再 filter 30 天窗口两遍；seed 2000 下 ~143ms，是 collect 481ms 的主体。

**改法**：新增 `settle::due_soon_summary(db, account, upto, today, days)`，复用同一套 `aging_items` + `pay_days_map` 口径，边扫边按窗口裁剪，零 DueEntry 构造、零排序，返回 `(笔数, 最早到期日)`。`ar_ap_due_schedule` 签名不动。

## D. 金额/账号约定可执行门禁

新增 `tools/check-money-discipline.js` 接入 preflight 第 5 步：扫 `crates/{findb,finweb,fincore}/src/**/*.rs`（跳测试/基准），三类违规自动拦——SQL `SUM` 碰金额列、`f64/f32` 与金额同现、科目代码写成整数。既有合法例外按锚定代码文字白名单。把「金额存 TEXT、Rust 侧累加、科目是字符串」从口头约定变成 CI 门禁。

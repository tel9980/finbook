# v1.8.24 — 网页版首页也有「赚没赚钱、钱在谁手上」

## 一句话

桌面版首页那两张卡，现在登录网页版第一眼就能看到；手机上也能看。

## 之前是什么样

桌面版首页左边「本期经营结果」、右边「钱在哪」，两个都是 v1.8.12–v1.8.15 陆续
打磨出来的：净利润当大字主角、带利润率和环比、成本 Top3、未记账警告；钱在哪
给四列数字 + 欠我最多的客户 + 我欠最多的供应商 + 超过 90 天的催收提示。

网页版一直没有。登录进去只有一排功能菜单 —— 而老板真正想在手机上瞄一眼的，
恰恰是「这个月赚了多少」「还有谁欠我钱」。

## 现在

`/api/dashboard` 的 `brief` 直接给格式化好的数字，前端只排版：

- **本期经营结果**：净利润（赚绿亏红大字）+ 较上月增减 + 利润率；营业收入 /
  营业成本 / 本年累计净利润；「钱都花哪了」Top3；`⚠ N 张凭证还没记账`。
- **钱在哪**：别人欠我 / 我欠别人 / 手头现金 / 净头寸（带方向）；欠我最多的
  客户与我欠最多的供应商（账龄 60 天黄、90 天红）；超过 90 天的催收提示。

## 三个口径决定

**一、数字由后端算，前端不算。** 桌面版和网页版各写一遍就会各错一遍：千分位、
利润率四舍五入、环比基准、成本口径（含 `5101 制造费用` 这类未结转的 Cost 类科目
—— v1.8.12 修过的那个坑），每一条都是踩过的。现在两端共用
`financial_totals` / `financial_analysis` / `money_position` / `status_summary`。

**二、收入为零时利润率是「没法算」，不是 0%。** 「0%」会让人以为这月白干，
事实是这月还没开张。JSON 里给 `null`，前端不显示那一行。

**三、同一家既是客户又是供应商，要标出来并给净额。** 宏源那种厂（既是外发
加工商，偶尔也拿货来做成客户）会有两条档案。现在两列各出现一次，每行带
「同一家」标记和轧出来的净额与方向 —— 客户行「他欠我 15,000、我欠他 28,000」
会显示成「净我欠他 13,000」，方向是翻过来的。

## 验证

新增 `crates/finweb/tests/home_brief.rs` 四条 HTTP 级回归，全部从**录凭证**开始
一路断言到 JSON：

| 用例 | 盯什么 |
| --- | --- |
| `home_brief_is_derived_from_vouchers` | 100,000 收入 + 15,000 房租 + 8,000 外发加工 → 成本 23,000、净利 77,000、利润率 77.0、应收 100,000、应付 8,000、净头寸 92,000、客户带名字 |
| `margin_is_null_when_revenue_is_zero` | 收入 0 时利润率是 `null` |
| `draft_vouchers_warn_but_do_not_count` | 草稿计入 `unposted`，但不计入收入 |
| `party_with_two_identities_shows_net` | 同名两身份：`both=true`、净额 13,000、客户行方向翻转 |

配套 4 条变异（`tools/mutate-rust.js` 的 ⑰ 系列，全部手工跑过确认变红）：

1. 成本口径退回只算 6401/6402（老 bug 复活）→ 净利虚高
2. 利润率写死 0% → 老板看到「这月白干」
3. 不提示未记账凭证 → 数字对但没人解释
4. 不标同一家两种身份 → 一厂两面被当成两家，老板要自己心算

## 一个测试坑（写下来免得下次再踩）

粘档案必须**两步**：`POST /api/aux-batch` 只解析预览（故意不写库，好让用户先
确认），`PUT` 才真正导入。第一版测试只发了 POST，于是客户名字全变成编码
（`C001` 而不是「奇园江门」）、`both` 全是 false —— 看着特别像产品 bug，
其实是夹具少发了一次请求。现在 `paste_aux` 里对 `inserted >= 1` 有断言，
再犯同样的错会直接报出来。

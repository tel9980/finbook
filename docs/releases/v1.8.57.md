## 三个坑（都会伪装成别的问题）

1. **搬过去的函数要显式开可见性**。原文件里 `async fn foo()` 是模块私有，搬进子模块后
   父模块的 `use self::x::*` 看不到它；编译错误却指向**路由表**说
   `cannot find value foo`，看着像路由写错了。搬过去的定义统统改成 `pub(super)`。
2. **父模块的普通 `use` 对子模块不可见**。子模块 `use super::*;` 只能看到父模块里
   `pub(crate) use` 的重导出；`use serde_json::json;` 是私有的，搬过去的代码会报
   `cannot find macro json`。所以头部依赖先转成 `pub(crate) use`。
3. **变异脚本不会告诉你目标搬走了**。`tools/mutate-rust.js` 每条变异都写着 `file:` 和
   要替换的原文；文件一搬，`file` 指向空——脚本不会报错，它只是「测试没跑」然后算通过。
   这一版加了机械校验：`--list` 的每一条，`from` 必须能在它声明的文件里找到，否则报红。
   19 条变异的路径就是这么一条条改过来的。

第 3 条是这一版真正的收获：**假绿的守卫比没有守卫更危险**，因为它让你以为有人在守。

## 搬家顺手抓到的第二个「假绿」

`tools/check-ci.js` 有 5 条规则专门盯「会话清理三种语义用错地方」（登录只顶本设备、
改密只清别的设备、重置设备全清）。拆完文件后它们当场全红——`post_login` 这些函数
已经不在 `handlers.rs` 里了。

改法不是删检查，是让它**跟着代码走**：5 条规则改成在 `handlers.rs` + `handlers/*.rs`
里找，找不到时把「搜过的 16 个文件」打出来（原来只说一句「找不到」，下一个人还得再猜）。
`fnBodyOf` 的正则顺带补上 `pub(super)` —— 只认 `pub(crate)` 的话，搬过去的函数它一个
也认不出来。

更值得记的是随后 `--selftest` 的报红：

```
FAIL 放过了  改密改成只清本设备会话（别的设备不被踢）
FAIL 放过了  重置设备绑定时不清该用户会话（旧设备不被踢）
```

这两条探针是**故意把代码改坏、看检查能不能拦下**。它们原来直接改 `handlers.rs` 里的
那段字符串；文件一搬，`String.replace` 找不到目标于是什么也没改，检查当然「通过」。
也就是说：**搬家会让自检探针静默失效**，而它们失效的表现是「全绿」。

把探针指到新文件（`handlers/auth.rs` / `handlers/platform.rs`）后，15 个探针全部
恢复「拦下了」。这一条比拆分本身更值钱：任何「删掉代码后检查还绿」都值得怀疑一下，
是不是检查根本够不着那段代码了。

# v1.8.87 —— 加工费单价：一张矩阵管住「按只、按米、按平方」

这一版解决的是氧化厂最日常的一件事：**同一种工件，报价口径不止一种**。
车间报产量永远是「只」，客户要的报价单却是「㎡」或「kg」，不同客户还可能各算各的。
以前只能靠人脑把 300 只换算成 7.02 ㎡ 再乘单价 —— 算错一次几十块，单子上还看不出错。

**有 schema 变更（48 → 49，纯加表加列）**，老账套升级不锁表、不丢数据。

---

## 一、问题

- 「加工费规则」是一张**一维**的表：一条规则 = 一个单位 + 一个价。
  一个工件要同时按 只 / 米 / kg / ㎡ 报价，就得建 4 条规则，彼此看不出关系；
  规则一多，一屏根本看不全，改价还得挨条找。
- 试算框里的「数量」是**计价单位**的数量。用户得自己先把 300 只折成 7.02 ㎡ 再输进去，
  系统从头到尾不知道「1 只 = 0.0234 ㎡」这件事。
- 结果：报价单上的面积、重量，全靠人算；算错了没人能从系统里发现。

## 二、改法一：给物料挂「计价口径 + 折算系数」

新表 `item_calc_unit`：**1 个库存单位 = factor 个计价单位**，一个物料可以挂好几个口径。

```
MB01（氧化件）  →  按 ㎡：1 只 = 0.0234 ㎡（保留 2 位）
                →  按 kg：1 只 = 0.0012 kg
                →  按 只：1 只 = 1 只
```

开单时填「300 只」、选口径「㎡」，系统自己算成 **7.02 ㎡** 再乘单价。

**折算顺序是铁律**：先把数量折算并抹平到口径位数，**再**乘单价。
反过来的话，对账单上写「7.02 ㎡ × 9.80 = 68.80」，客户按 7.015 算出来是 68.75，
一句「你怎么算的」就说不清。折算结果是 0 直接报错 —— 那说明系数填错了。

## 三、改法二：单价矩阵，一屏看全

「销售 → 加工费规则」现在是一张矩阵：

```
物料                  按只      按米      按kg      按㎡
MB01 氧化件           0.80       —         —        12.00
                                                      起步 30.00
MB02 型材              —        6.50      3.90        —
```

- 格子里**直接改单价**，改完即生效。
- 点「调」能改起步价，也能**提前录下一版价**：写 `2026-03-01`，
  到那天自动换过来，旧单仍按旧价 —— 不用记得月底回来改。
- 格子里写「没设系数」的，是还没告诉系统「1 只折合多少 ㎡」；点一下就去录。
- 「没定价」的格子空着写「未定价」，**不会预填 0** —— 预填 0 一路点下去就是白送。

## 四、匹配规则：口径不同不互相顶

- 单价的匹配仍是「物料+客户 > 只限物料 > 只限客户 > 通配」。
- **新增：给了口径就必须同口径**。`12 元/㎡` 的价拿去乘 `300 只` 是几百倍的错账，
  所以宁可报「这一格还没定价」，也不拿别的口径凑。
- **同精度比生效日**：已生效的价里挑生效日最晚的那条。
- **只录了未来价时照报**，但会标明「X 月 X 日才生效」——
  报「没有规则」会让老板以为价丢了、去重录一遍，两条价并存更乱。
- 生效日必须写成 `2026-03-01`。`2026-3-1` 会被当场拒绝：判定是字符串比较，
  不补零的写法永远小于 `2026-03-01`，那条价可能一辈子不生效。

## 五、顺手修掉的一个坑

桌面版「加工费规则」的编辑框以前没有「生效日」这一栏。加了字段之后如果在桌面上点
「编辑」再保存，会把它清空 —— 网页端提前录的下一版价就白录了。
这一版把「生效日」加进桌面端的表单，编辑时原样带回。

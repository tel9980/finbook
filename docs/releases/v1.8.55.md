# v1.8.55 —— 部门范围与写侧越权：读和写各抄一遍口径，迟早抄漏

v1.8.54 把"不是报表页的读"补齐了。这一版收剩下两类：**部门范围**和**写侧**。

## 一、工资早就收口了，报销没有

工资那边有一个 `scope_payroll`，列表 / 导出 / 银行代发 / 个税申报表四个出口共用：

```rust
rows.iter().filter(|r| user.user.data_scope.allows_dept(&r.dept)
                    && doc_in_scope(user, &r.employee))
```

报销是散着的——`list_claims` 与 `export_claims` 各写一遍过滤，**而两份都只写了
`own_doc_only`，没有部门**。于是设了「只给生产部会计看生产部」之后：

- 报销列表照样列出销售部、行政部的单子；
- 导出成 Excel 也照样带出去。

不报错，不提示，就是多了。这类漏法有个共同特征：**同一个判断在 N 处各写一遍**。
现在收成两个函数：

| 函数 | 给谁用 |
|------|--------|
| `scope_claims(user, rows)` | 读：列表 / 导出 |
| `claim_visible(user, c)` | 写：改 / 删 / 审批流转 / 生成凭证 / 新建时的部门校验 |

两者口径相同（部门范围 ∧ 仅本人经手），改一处即改全部。

## 二、写侧：看不见的单据不能改

这是比"看多了"更隐蔽的一类。`own_voucher_only` 的人看不到别人的凭证 —— 但"看不到"
和"拿着 id 能不能改"是两件事。

审计结果（**写侧其实早就守住了**，这版补的是测试）：凭证的 8 个写接口
（`save_voucher` / `void` / `post` / `unpost` / `amend` / `audit` / `unaudit` / `sign`）
与 `batch-post` 全部过 `can_see_voucher`。守住了，但**没有一条测试证明它守住了** ——
下一个人加接口时很容易照着一个漏的抄。

所以补 `own_voucher_only_cannot_touch_others_voucher`：

- 老板建一张凭证；
- `own_voucher_only` 的会计 `GET /api/vouchers/{id}` → 403/404；
- 再试 `post` / `void` / `audit` → 全部拒绝；
- 反向一条：老板作废自己的凭证仍然 200（闸门不能把主人也拦住）。

## 三、顺手改的一个顺序问题

`claim_voucher` 原来先校验参数（"请填写支付科目"）再验权限。对范围外的单子，
服务端连"你的参数对不对"都不该告诉调用方 —— 这本身是个信息泄露面（可以拿来探测
单据是否存在、字段结构如何）。改成**先验权限再验参数**。

## 四、测试与验证

`crates/finweb/tests/scope_claims.rs` 三条：

| 测试 | 守什么 |
|------|--------|
| `claim_list_and_export_respect_dept_scope` | 部门范围只给生产部 → 列表只剩 1 张；导出的 CSV 里**不能出现**销售部那笔 340.00 |
| `claim_write_endpoints_refuse_other_dept` | 范围外的单子：审批 / 改 / 生成凭证 全部拒绝；**本部门的提交仍然 200** |
| `own_voucher_only_cannot_touch_others_voucher` | 别人凭证查不到、改不了、记账/作废/审核都被拒；自己的仍可作废 |

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **1080** 全绿 |
| 变异验证 | 109 → **111**，2 条全拦下（报销列表不按部门过滤、报销写侧不按部门拦） |
| 自检 | check-ci / check-js / check-portable / check-design-doc / check-simple-nav 全过 |

两个坑值得记：

- 导出的测试要用**有 `Export` 权限**的角色（会计角色没有），所以那个用户建成
  「应收会计」，否则测到的是 403 权限墙，不是数据范围；
- 「本部门照常可用」的断言不能用"审批通过"——报销单得先 `submitted` 才能 `approved`，
  用草稿直接批会 400，测出来的是状态机不是范围。

## 还没做

- **部门范围在凭证侧**：凭证没有部门字段（挂在分录的 `aux.dept` 上），所以
  `DataScope.depts` 目前只作用于工资与报销。要不要让"部门会计只看本部门分录"是
  产品决策 —— 一本账里分录混着部门，按部门切凭证会切出不平的分录。
- **科目范围 ∧ 凭证可编辑的交叉**：能看某科目，但改凭证会连带未授权科目 —— 目前
  靠 `can_see_voucher` 整张放行，没有逐行检查。

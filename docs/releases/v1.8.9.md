# FinBook v1.8.9

两处会真正影响日常记账的改动：**抹零不再被当成错误拦住**，**数量金额式科目用上了真实单位**。

## 行为变更

### 数量 × 单价 ≠ 金额：改为提醒，不再拦截

抹零、整单取整、抹去角分、谈好的折扣，都会让「数量 × 单价」和实付金额差几块甚至几十块。这是真实的商业事实，不是记账错误。

旧行为把它当硬错误拦下（容差仅 0.01 元），后果是用户为了能保存，只能去**篡改数量或单价来迎合公式**——那才是把账做假了。

现在：

- 差额大于 0.01 元时**提示一句**（含差额金额），用户确认是抹零后正常保存；
- 账上记实付金额，数量照实填，两边各自为真，差额就是抹零那笔；
- **数量或单价压根没填仍然拦截**——那才真会让账不清。

实现上 `fincore::Issues` 拆成两档：`push()` 记错误（拦保存）、`warn()` 记提醒（不拦），`into_result()` 只在有错误时返回 `Err`。比较前先按分四舍五入，避免小数位多的数量因浮点尾差天天报到 1 分。

### 精简模式补上资金管理 / 费用报销 / 客户供应商银行档案

精简模式（`simple_nav`，默认开启）原为 12 项，对「钱分多个银行户 + 微信放、一个人记账」的小企业不够用：账户余额只能去余额表绕，新客户来了没处加档案。现扩充到 17 项：

- `Funds` 资金管理：多银行户 + 微信的日报、票据、账户余额
- `Claims` 费用报销：人手少时零星费用先垫后报
- `Aux(Customer/Supplier/Bank)`：三张要就地维护的档案

部门/员工/项目/存货档案仍在完整模式（属管理会计与库存范畴）。同时把原先前遗漏的 `Inventory`、`InventoryDeep`、`ScmDeep`、`Cost` 一并纳入精简模式的隐藏范围——之前勾了精简模式，库存和成本核算仍然留在侧栏。

取消勾选精简模式即恢复全部菜单，**不删任何功能**。

## 新增

### 小工厂建账工具链（`crates/findb/examples/`）

- `build_shop.rs`：一键生成来料加工厂账套——212 科目、59 客户、27 供应商（含 6 家外发厂，独立 `W` 编码）、3 个资金账户（G 行对公要票 / N 行当现金用 / 微信）、19 个存货档案。
- `opening_sheet.rs`：生成《期初收集表.xlsx》，5 个 sheet，预填客户供应商编码，工厂照填金额即可。
- `verify_shop.rs`：账套自检（科目 / 档案 / 数量金额式配置 / 试算平衡）。

### 存货档案按品类分单位

19 个存货档案覆盖化工（`HG`，kg）、染料（`RL`，kg）、挂具（`GJ`，套 / 个）、包装（`BZ`，卷 / 个 / 捆），带规格型号。12 个存货科目统一配置为「挂存货档案 + 按数量核算 + 真实计量单位」，取代原来一律写「个」。

## 兼容性

- 无 SCHEMA 变更，仍为 **v38**。旧账套直接打开即可。
- 数量 × 单价 的校验从「拦」变为「提醒」，只会让原本存不进去的凭证变得能存，不影响已有数据。
- 精简模式项数变化只影响侧栏显示，权限与数据不受影响。

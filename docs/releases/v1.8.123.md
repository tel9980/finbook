# v1.8.123

## 这一版做的是什么

README §9「已知限制」里挂了很久的一条：**款到发货（先款后货）开关**。

### 问题：欠着钱也能一直发货

老逻辑里发货**完全不看收款**。客户一分钱没付，订单照样能一路发完、确认收入、
挂应收。风控全靠人盯——而「发一半、收一半，再发一半、一分没收」这种温水煮青蛙
的欠法，人眼很难在中途发现。

## 怎么改的

新增账套参数「款到发货」（`BookOptions.prepay_gate`），三档：

| 值 | 行为 |
| --- | --- |
| 关闭（默认） | 不检查。老账套升级后行为完全不变 |
| 收款不足提醒 | 只写一条审计日志「款到发货提醒」，照常发货 |
| 收款不足强控 | 拒绝发货，错误信息里带清楚「累计应确认多少、已收多少」 |

### 两个口径决策

1. **累计比，不是单次比。** 判断的是「本次发货后**累计**应确认的含税收入」对
   「**累计**已收款」。按单次比会漏掉「发一半收一半、再发一半没收」：每次单看
   只差一点，累计起来已经欠了一整车。
2. **含税比含税。** 客户实付的收款额是含税钱，订单的 `total_amount` 是不含税合计。
   拿不含税去比会系统性高估缺口、把正常订单拦下来。摊分口径与收入确认凭证完全
   一致（按数量比例摊 + 四舍五入到分），否则闸门报的金额和凭证上的金额对不上，
   用户没法自己核。

### 挂在哪两个入口

- **Web 全链路**（`so_shipment_all`：收入凭证 + 发货行 + 出库流水同一事务）——
  校验放在开事务**之前**，拒绝时数据库里一点痕迹都不留。
- **桌面端纯流水入口**（`so_shipment_add`）—— 不挂的话「换个入口就能绕过风控」。

金额为零的订单（赠品/样品）不拦：没有「收多少钱」的概念。

前端：Web 账套参数页与桌面端设置页都加了这一项下拉。

## 三条规矩

1. **默认关闭，老账套行为一模一样。** 升级不改变任何既有单据的发货结果。
2. **两个发货入口都要拦。** 风控只挂在一条路径上，等于没挂。
3. **拒绝时不留痕。** 没发货行、没凭证、没出库流水——不能出现「报错了但账上多了半笔」。

## 升级说明

无 schema 变更，旧账套直接打开即可。默认关闭，需在「账套参数」里手动开启。

# v1.8.30 —— 谁能把表带出门

v1.8.29 加了「账龄导出」，按钮上线后马上撞上一个安排问题：后端要「导出数据」权限，
而这个权限原来只有**管理员**和**财务主管**有。

可是催款前导账龄的，是**应收会计**。

## 不给导出，真实的结局是截图

这不是「他们就不导了」。真实行为是拿手机/QQ 截图发给老板和客户 —— 截图不进操作
日志、不能对账、改一个数字也没人知道。**把权限收得比工作流更紧，不会让人少带数据
出去，只会让带出去这件事变得查不到。**

所以边界改成按岗位划：

| 岗位 | 能导出 | 理由 |
|------|--------|------|
| 系统管理员 / 财务主管 | ✅ | 一直有 |
| **应收会计 / 应付会计** | ✅ **本版新增** | 发账龄、发应付清单是本职，本来就有报表权限 |
| 会计 / 出纳 / 审核人 / 仓管 / 订单专员 / 成本会计 / 只读 | ❌ | 只能打印预览：纸面留痕可控 |

**账套文件备份（`Backup`）仍然只给系统管理员** —— 能导出报表不等于能拿走整个账套。
这两件事一直是分开的权限，以后也别合并。

## 开了权限就必须留痕

导出等于把数据带出门，所以账龄导出补了操作日志：

```
导出 · 导出往来账龄 · 2026-10 至 2026-10-27 · 科目 1122 · 24 行
```

谁在什么时候、把多少家的往来余额带出去，事后查得到。这条有测试守着。

## 顺手修的三个「看着在守，其实没守」

1. **死按钮**：账龄导出按钮原来对所有角色都渲染，会计点了得到 403。现在按
   `can("export")` 显示，与其它导出按钮一致。
2. **变异助手 `CORE` 丢参数**：`const CORE = (name) => [..., "user::tests::"]` ——
   `name` 根本没被用上，实际效果是「跑所有 user 测试」。于是某条变异被**别的**用例
   顺手拦住也显示 PASS，看不出目标用例守没守住。改成 `user::tests::${name}` 后重跑，
   两条旧变异仍 PASS（它们本来就被正确守住，只是判断不精确）。
3. **变异插了重复 match arm**：想验证「导出权限顺手开给会计」，第一版往 `match` 里
   插了一条新的 `Role::Accountant` 分支 —— 但 match 取第一条，原分支在前面，变异
   等于没生效，测试照过、被误读成「放过了」。改成在真分支里加 `Export` 才拦得住。

第 3 条是这个工具最容易骗过自己的地方：**改了源码，但语义没变**。

## 已在跑的账套怎么生效

岗位权限是**代码里的表**，不改你库里已有账号的额外授权：

- 用「应收会计」「应付会计」岗位建的账号，升级后重新登录即拥有导出权限。
- 如果当初给某人**额外勾了**「导出数据」，那是账号级授权，与岗位无关，不受影响。
- 想收紧某人：用户管理里勾掉该账号的「导出数据」即可（账号级 deny 优先于岗位）。

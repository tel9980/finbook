# v1.8.63 —— 受托加工的三件事：客供料、加工费、计件

一家小型氧化（来料加工）厂的现场侧，有三个动作账务系统原本接不住：客户的料进厂怎么管、
加工费按面积怎么报、工人按件拿多少钱。这一版补上这三件，**既有表结构一行没改**。

## 一、客供料台账：客户的料不是自己的资产

来料加工的料不估值、不进存货、不出凭证、不参与成本。所以没往 `inventory` 里塞，
而是新开两张表（`consign_doc` 单据头 + `consign_line` 行），用四类单据维护结存：

| 类型 | 码 | 符号 |
| --- | --- | --- |
| 来料 | `in` | + |
| 交货 | `out` | − |
| 退料 | `return` | − |
| 损耗核销 | `loss` | − |

结存维度是 **客户 + 物料 + 批次**（同物料两个批次不互相顶账），单号按类型分前缀
（`LR-202611-001` 来料、`JH-` 交货、`TL-` 退料、`SH-` 损耗）。三条规矩都写成了测试：

- **减项必须先有余额**：交货 60 之后再来 50 直接 400「现存客供料 40，本次 50 超出可核销数量
  （先补登记来料）」——负结存是最难查的一类账，宁可在保存时就拦下；
- **编辑要排除自身**：把 60 改成 70 时，本单原本占用的 60 不能算进"现存"，否则被自己拦住；
- **聚合在 Rust 侧做**：结存和对账单都是"取平表 → 内存里加"，**不用 `SUM()`**——SQLite 的
  `SUM()` 对 TEXT 存的钱会退化成浮点，误差会一路带到对账单。

对账单按客户 + 期间区间出，列 期初 / 来料 / 交货 / 退料 / 损耗 / 期末，期初取区间起点
之前的累计结存，所以跨月能对上。

## 二、加工费规则：最低收费与加急费的顺序是会吵起来的

`price_rule` 表 + 一个纯函数 `quote()`，顺序写死：

```
基础价 = 数量 × 单价
补差   = max(0, 最低收费 − 基础价)   ← 先兜底
小计   = 基础价 + 补差
加急   = 固定费 + 小计 × 比例%       ← 再按兜底后的金额算比例
合计   = 小计 + 加急
```

顺序反过来会出现"加急费被最低收费吃掉"，客户和厂里各有一套说法。举例（18 元/㎡、起步 30、
加急 20 元 + 10%）：12.5 ㎡ → 225；0.5 ㎡ → 30（补 21）；12.5 ㎡ 加急 → 267.5（加急 42.5）。

规则匹配四级优先级：**物料+客户 > 只限物料 > 只限客户 > 通配**。这里踩过一次：给
"物料+客户"分支写了 `continue`，忘了通配兜底，结果只维护一条通配规则时报价直接报
"没有匹配的加工费规则"——兜底分支必须在每个精度上都可达。

`GET /api/price-rules/quote?item=&customer=&qty=&rush=1` 只算不存，开单页用来试算。

## 三、计件工资：先补一张流水表，再谈汇总

`prod_op`（工序）存的是**累计值**（`qty_done`/`hours`/`worker`），没有期间、没有时间戳——
点一次报工是往上加，加完就分不出"这个月做了多少"。按期间算计件工资缺一个维度，所以：

- 新增 `prod_op_log` 报工流水：`advanced::prod_op_report()` 在同一个事务里既更新 `prod_op`
  的累计值，也写一条流水（日期取当天，期间由日期推出）；
- `piece_rate` 表存计件单价（物料 + 工序，两者不能都空——都空等于给所有人所有活定价）；
- `piecepay::compute(db, period)` 按期间汇总到人；无单价的行**保留**但标 `matched=false`、
  金额 0，看得见"这活没定价"，而不是悄悄少一行；
- 回填走 `POST /api/payroll/piece-fill`：只把应发**提到不低于计件额**（已经够了就跳过），
  再调既有的 `business::payroll_calc` 重算社保个税，`payroll` 表结构一行没动。
  重复点不会重复加钱——判据是"应发是否已经够了"，不是"有没有回填过"。

顺手补的：Web 端原先**没有任何生成工序清单的入口**（只有桌面端有按钮），网页上根本走不到
计件这一步。现在下达生产订单时若该存货有工艺路线就自动生成工序清单，另给了
`POST /api/prod/:id/ops/init` 手动补建、`POST /api/prod/op/dispatch` 派工。

## 四、界面

侧栏新增三个视图（`生产制造` 组：客供料台账、计件工资；`销售` 组：加工费规则），
客供料台账带单据登记、结存、客户对账单；加工费规则带试算报价；计件工资带"算计件 → 回填
→ 打印"，回填前弹确认框。

## 没动

- **客供料不出凭证**：数量口径，客户对账用对账单；要不要按"来料加工"的账务口径入账，
  是下一件需要厂里会计确认的事。
- **`so_line` 没有单价规则字段**：报价是接口层面的"一键带入"，销售订单行仍是手填单价，
  免得改动波及一地结构体字面量。
- **计件单价不分工序版本**：同一物料同一工序只有一个单价，工艺路线换版本不另算。
- **分摊与损耗成本**：槽液、水电、返工件的成本归集仍是人工设率，这一版没碰成本核算。

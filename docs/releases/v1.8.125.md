# v1.8.125 — 往来期初明细参与核销（schema v58）

## 这一版改了什么

开账时录的应收/应付期初明细（旧账），此前只进账龄展示、**不参与核销**。客户上一年欠的
8000 会一直挂在账龄上，本期收到 10000 也只会配给本期新开的发票。这一版把期初明细接进
核销链路：手动核销、自动核销（FIFO）、账龄、客户余额、对账，口径全部打通。

## 实现要点

- **新增 `opening_settle` 表**（schema v58）：记「期初明细 ↔ 收付款分录」的核销额。
  没有改 `settle_record`——它的 `from_entry`/`to_entry` 是 `voucher_entry(id)` 的非空外键，
  而期初明细没有凭证分录，硬塞伪 entry 会违反外键；且它有 68 处读取方，动它风险太大。
- **负 entry_id 接入**：真分录 `entry_id` 为正，期初单用 `-opening.id`。`settle_pair` 按
  符号分派到 `settle` 或 `opening_settle`；应付期初在贷方，参数要翻。
- **自动核销排序**：期初单追加进来后统一按日期重排，否则会排在所有本期分录之后，
  FIFO 反着来（最老的旧账最后才被吃）。
- **已核销额两边都算**：`settled_of` / `settled_map` 把 `opening_settle` 并进来。漏掉会让
  一笔已用于核销期初的收款看起来「还没用过」，被自动核销再配一次（实测 1000 被吃成 1800）。
- **Web**：核销页列出期初单；手工核销期初单**不支持差异核销**（差额留在账上）。

## 三条规矩

1. 期初单的已核销额 = `opening_settle` 累计，账龄/客户余额/对账三处口径必须一致。
2. 自动核销先吃期初（最老）；一笔收款可以「先吃期初一部分、再吃本期一部分」。
3. 同一笔收款不能重复使用：核销过期初之后再拿它核销第二张，必须报「超过核销方未核销额」。

## 升级说明

老账套打开时自动建 `opening_settle` 表（`migrate_v58`，幂等）。历史期初明细的已核销额
从 0 起算——此前它们本来就不参与核销，所以不需要回填。

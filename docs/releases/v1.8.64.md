# v1.8.64 —— 一个功能两种界面：算钱的地方只留一处

v1.8.63 的三块受托加工功能只有网页版。同一个账套，打开桌面客户端就少了三个功能——
所以这一版补三件事：**Web 三块的 E2E 覆盖、桌面端的三个入口、以及把"算钱"从界面层挪回数据层**。
顺带把计件回填的算钱逻辑抽成 `piecepay::fill_one()`，网页与桌面共用一份。

## 一、算钱的地方只留一处

计件回填在网页端原本是 handler 里的六十行：读旧工资、比应发与计件额、拼备注、
调 `payroll_calc` 重算社保个税、`payroll_upsert` 写回、记日志。桌面端要同样的按钮，
这六十行就得再抄一遍。

两遍的代价不是字数，而是**口径漂移**：某天改了"应发与计件额相等时怎么处理"，
改了网页忘了客户端，同一个账套两个界面开始给出不同答案。

所以新增：

```rust
piecepay::fill_one(db, period, &pay) -> DbResult<Option<PieceFill>>
```

`None` 就是"不用动"（应发已不低于计件额）——这既是回填的判据，也是它幂等的理由，
不需要额外记"回填过没有"。留在上层的只有权限（`Perm::VoucherNew`）与数据范围
（看不见的部门不改写工资表），因为"谁能看"和"怎么算"是两件事，混着写就会出现
"界面上看不见的人，工资被改了"。

新增两条单测钉住这条口径：应发 0 → 抬到 150 并按 150 重算个税；
底薪 500 已在工资表 → 计件 100 **不把应发压到 100**。

## 二、桌面端补三个入口

`crates/finui/src/views/process.rs`，三个界面都只做"查出来、摆成表、交给 findb"：

- **客供料台账**（`业务` 组）：客户过滤、单据列表、点开看行、登记单据（客户/类型/日期/
  多行物料数量批次）、结存表、客户对账单窗口；
- **加工费规则**（`业务` 组）：规则表格、编辑区、停用开关、试算报价面板
  （显示"基础价 / 最低收费补差 / 加急加急 / 合计"的拆解，不在界面里自己算）；
- **计件工资**（`业务` 组）：按期间汇总到人、点人看工序明细（无单价的行标红提示）、
  计件单价维护、回填工资表（带确认框，回填前先过部门数据范围）。

删除一律走统一确认框（`ConfirmAction::DeleteConsignDoc / DeletePriceRule / DeletePieceRate`）：
客供料单据删了结存跟着变，且单据不占期间结账，删错只能重新登记。

## 三、新写的三条 E2E

新增 `e2e/tests/process-extra.spec.js`：

| 用例 | 断言的关键点 |
| --- | --- |
| 客供料：来料 → 交货 → 超交被拦 → 结存与对账单 | 超交后**单据数没变**（只判 toast 会把"报错但已入库"判成通过）、结存 100 → 40、对账单 期初0/来料100/交货60/期末40 |
| 加工费：面积计价 → 最低收费兜底 → 加急 | 12.5㎡=225、0.5㎡=30（补差 21）、加急 267.5、加急率 120% 被拦且规则数仍为 1 |
| 计件：报工 → 按人汇总 → 回填（幂等） | 张三 100 件×1.5=150、回填空「已回填 1 人」、再回填空「没有需要回填的人」、工资表应发按数值等于 150 |

写这三条时踩的三个坑写进了 `docs/功能参考.md` §4.107：**只判 toast 等于没判**
（超交后还要问一次服务端，单据到底有没有进库）；**能被接口造的前置数据就别点界面**
（计件那条的工艺路线/订单/派工/报工全走 `/api`，只在"算计件/回填"这一层点真按钮）；
以及**保存被拒时窗口故意不关，遮罩会挡住后面的按钮**——第一版跑在 CI 上就是两条用例
各卡满 60 秒超时，报错还指在下面那一行上，看着像"点不动"。

## 没动

- **客供料仍不出凭证**：数量口径；要不要按来料加工的账务口径入账，等厂里会计确认。
- **`so_line` 仍没有单价规则字段**：报价是一键带入，销售订单行仍手填单价。
- **桌面端不做分摊与成本归集**：与本轮无关，仍是人工设率。
- **桌面端与网页端界面各写一份**：这是两端技术栈决定的，能共用的是数据层与算钱逻辑，
  界面本身没法共用——所以"算钱只写一处"才更重要。

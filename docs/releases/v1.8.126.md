# v1.8.126 — 桌面端补齐两个入口 + 期初核销口径收尾

## 这一版改了什么

三件事，性质不同：

1. **桌面端补上「合并报表」入口**（此前只有 Web 有）。
2. **桌面端补上「工序检验」页**（此前只有 Web 有）。
3. **修掉 v1.8.125 的三处漏改**：两处演示账断言前提失效、一处催款单按期初原额催收。

前两件是「功能早就做完，只是入口没搬过去」；第三件是上一版把期初明细接进核销之后，
几个**下游消费方和断言没跟着改**——CI 上表现为 `Test` + `Coverage (backend)` 双红。

## 实现要点

### 合并报表：口径搬到 findb，两端共用

聚合逻辑原来只写在 `crates/finweb/src/handlers/books.rs` 的 `consolidate_preview` 里。
给桌面端加就等于抄一遍，两份代码迟早算成两个数。现在搬到
`crates/findb/src/consolidate.rs`：

- 收 `&[ConsolSource]` 而不是 `&Db`——合并天然跨多个账套文件，每个账套是独立的 `Db`，
  由调用方自己打开后传进来。
- 科目编码取**并集**（`BTreeSet` 天然按编码排序，各账套列才对得齐），零余额科目不占行。
- Web handler 改成三行转调；`CONSOL_NOTE` 常量两端共用，文案不会各写一份又走偏。

桌面端新增 `crates/finui/src/views/consolidate.rs` + `NavItem::Consolidate`（归「账簿报表」，
需要 `Perm::Report`）：`rfd` 多选 `.fbk` → **`Db::open_no_migrate`**（只读场景不该触发迁移）
→ 同一个 `preview`。

### 工序质检：桌面端第 4 个 tab

`MfgTab` 加 `Qc`，「生产制造」页多一个「工序检验」：订单号加载检验记录 + 一行录入表单
（检验数量 / 不合格数 / 处置三选 / 日期 / 备注）+ 9 列明细表。数据层一行没改——
`prod_qc_save` / `prod_qc_list` 本来就在。

### 桌面端核销页接入期初单

`reload()` 把 `opening_open_entries(...)` 追加进借贷两张表（`entry_id` 为负，
按 `(date, no, line)` 排序让期初单排在同期分录前面）；`do_settle()` 遇到负 id 走
`settle_pair`，且拒绝差异核销——期初单没有对应分录，差异凭证无处可挂。

## 修掉的三处漏改

1. **演示账「未清分录净额」断言前提失效**。旧不变量「未清分录净额 == 分录净发生」只在
   「核销两边都在分录集合内」时成立；期初单参与核销后集合不再闭合——一笔收款被期初单
   吃掉后 `open` 归零，而对侧（期初单）不在分录集合里，分录侧净额就凭空多出期初的金额
   （`oxide_demo` 实测 `-56160 → 11840`，差额正好是期初单的 68000）。
   改成**两边一起算**，不变量变成恒等式「未清净额 == 科目余额」，与 `BalanceSnapshot` 对齐。
2. **账龄断言跟着变**：`oxide_demo` C01 `68000/65300 → 2700/0`；`oxide_vat_demo` 恒信 S01
   整户结清（账龄里连行都没有）、大发 S02 `18000/11820 → 6180/0`。
3. **催款单按期初原额催收**（`crates/findb/src/settle/dunning.rs`）：期初 5000 已被收款吃掉
   2000，客户收到的催款单还是 5000。改为按「期初金额 − `opening_settle` 累计」计入，
   核销干净的期初行直接跳过。

## 三条规矩

1. 合并报表两端必须是**同一个函数**算出来的：同样的账套、同样的期间，每一行每一列逐分相等。
2. 桌面端打开合并报表**不触发账套迁移**：只读场景不该改动别人的账套文件。
3. 期初单在两端核销页都要看得见、勾得掉，但**不能差异核销**。

## 升级说明

- **无 schema 变更**（仍为 v58）。老账套直接打开即可。
- 桌面端侧边栏「账簿报表」组下新增「合并报表」，需要报表权限。
- 「生产制造」页新增「工序检验」tab。

# v1.8.38 —— 三处「看着能用、其实没接上」

这一版没有新功能。修的是三处**代码都在、开关都有、就是没生效**的缺陷，
外加一个每天都会被问的问题（「这 5 万是哪几张单」）终于能点开看。

## 一、建账和导入账套不过参数校验（最该修的一条）

v1.8.27 把账套参数的校验收进了唯一的落库入口 `Db::set_options`。但**建账本身
也是一条写参数的路**，`create_with` 当时没调校验，于是：

| 填错 | 当时的结果 | 后果 |
|------|-----------|------|
| 应收科目填 `1122`（汇总科目） | 账套正常建出来 | 自动生成凭证时往汇总科目记，分录记在不能记账的科目上 |
| 预算控制填 `warning`（该是 `warn`） | 账套正常建出来 | 静默按「关闭」跑，超预算一路放行 |

而且**没有任何报错**，要等到第一次在参数页点保存才提示 —— 那时业务已经在跑了，
用户只会认为「新版本把保存按钮弄坏了」。

现在**建账**过同一套校验，报错里带上具体哪一项、填的是什么；校验失败不会留下
半个账套文件（测试里断言了 `!path.exists()`）。

**导入账套刻意不拦**：老账套里可能本来就有历史脏值（那时还没校验），硬拦下来
等于「从别处搬过来的账套打不开」，比参数不对更糟。它会在下一次保存参数时被拦住，
那时用户能看到具体哪一项不对。

## 二、未核销清单会随账套变大（222.9 KB → 56.2 KB）

`/api/settle/open` 原来把该科目所有未核销分录一次给完。1980 张凭证的账套实测
**222.9 KB**，按 6000 张推算近 700 KB —— 手机上看一眼核销页要下半个兆。

现在默认只给 200 笔，`limit=0` 保留全量（导出与脚本用）。但真正要小心的不是体积：

> 第一页说「共 792 笔、合计 8,482,200.00」，翻到第二页变成「共 200 笔、合计 2,140,000.00」
> —— 会计会以为钱少了。

所以**笔数与合计都算在分页之前**，只有明细行分页；真要截断时 `truncated` 会明说，
界面上显示「未核销 N 笔，已显示前 M 笔」和「再显示 200 笔」按钮。

悄悄少给几行比慢十倍更坏 —— 表现是「这单明明还欠着，核销页里找不到」。

## 三、套打纸型：三种纸不能共用一个设置

小厂里同时用着三种纸：凭证 A5 或 241×140 连续纸、账簿 A4、收付款单 A5 或三等分联。
而原来凭证套打写死 `A4 landscape`，账簿更是**把打印设置收进来了却一行没用**
（所以凭证能调偏移、账簿不能，同一台针式打印机上两种纸表现不同）。

现在分三档，各自可选：

| 设置 | 默认 | 可选 |
|------|------|------|
| 凭证纸型 | A4 横向 | A4 / A5 / 三等分联 / 241×140 连续纸 |
| 账簿纸型 | A4 横向 | 同上 |
| 单据纸型 | 跟随单据模板 | 同上 + 跟随模板 |

认不出来的值（比如 `B5`）**保存时报错并带出原值**，打印时兜底 A4。两头都要有：
只在保存时报错，老账套里的脏值会让人打不出纸；只在打印时兜底，用户会以为设置生效了。

## 四、账龄能点开看单据

账龄表只回答「最老 148 天」，答不了催款时第一句要问的：**这 5 万是哪几张单、各挂多久**。

- **网页版**：往来账龄表里点客户名 → 下方列出该对象全部未核销单据（日期 / 凭证号 /
  摘要 / 借方 / 已核销 / 未核销 / 账龄天数）。
- **桌面版**：账龄页点往来单位 → 下方「未核销单据」卡片，同一个口径。

天数按 **截止期间的最后一天** 算，与账龄表的「最长账龄」同一个基准 —— 一个按今天
一个按期末，就会出现「账龄说 148 天、下钻说 160 天」，差的 12 天正好是对账时最想
问清的那部分。

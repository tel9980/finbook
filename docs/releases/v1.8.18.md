# v1.8.18

**期初批量粘贴：预览和保存终于说同一句话。**

## 修了什么

上一版（v1.8.17）给期初加了一条「只能录在末级科目上」的校验。加完之后，同一个动作出现了两套说法：

| 操作 | 结果 |
|---|---|
| 期初页手填 `1002`，点保存 | ❌ 报错「必须录在末级科目上」 |
| 从 Excel 粘 `1002`，点预览 | ✅ 显示「3 条可导入」 |
| 接着点导入 | ❌ 报错 |

用户看到的是**预览骗人**：明明说能导，一点就炸，还只报第一行。几十行的期初要来回试十几趟才知道哪几行有问题。

原因：解析函数 `fincore::batch::begin::parse` 只用「科目表里有没有这个编码」判断，`leaf_codes` 参数只拿去算「你抄错的那行像不像 100201」的相似度提示，**从来没用来判断「这行是不是末级」**。

## 现在的行为

预览阶段就把非末级行标出来，并把能录的子户直接列给用户：

```
跳过：这不是末级科目，期初要录到子户上（可录 100201、100202、100207）
```

被跳过的行不计入试算，所以试算里的「差额」是真差额，不会因为一行跳过就凭空多出 125,000。

## 顺手补齐的手册

`docs/日常记账手册.md` 的 1.2 节新增「期初该录到哪个科目」：

- 讲清什么叫末级（下面不再挂子户），以及为什么非得这样（试算平衡表按末级汇总，录上级等于这笔钱不在任何一行里）
- 一张照抄表：11 类常见家底，左边标出「❌ 常见误区」（如 `1002`、`1122`、`1403`），右边给该录的末级科目（含银行多个户、材料多种类、税种各一笔）
- 怎么自己判断末级：看科目页有没有缩进子行
- 批量粘贴遇到非末级时，预览会说什么

## 测试

- `fincore::batch::begin`：新增「非末级科目在预览里就标跳过」「没给末级科目表时不判非末级」；「跳过原因都有中文文案」补上 `NotLeaf` 两个变体（空的、三个子户带省略号）
- `finweb::batch_paste`：新增「期初预览把非末级科目标成跳过」，直接打 `/api/begin-batch` 验证预览与 `/api/begin` 保存口径一致
- 全量：fincore 165 / findb 395 / 集成 193 / finweb 12 / finui 56 / core_loop 21 全绿

## 需要留意

`parse` 的 `leaf_codes` 语义扩展了一点点：原来只用于相似度提示，现在还兼作「末级判定」。传空数组时不做判定（避免测试里的最小科目表被误伤），当前两个调用点（Web 预览、Web 导入）传的都是完整科目表，行为一致。

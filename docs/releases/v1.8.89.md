# v1.8.89：按规格自动算单价（客户说「2.5 元一米」，你只要填规格）

## 一句话

客户报的是**费率**（元/米、元/㎡），工件给的是**规格**（`1200*80`、`1250*250*3`，毫米）——
中间那步「1 件折合多少米、多少平方」现在软件自己算：粘一串规格进去，出来每件多少钱；
开单时填规格也能直接报价。

## 为什么做

v1.8.87 的折算系数要人**先按计算器算出**「1 只 = 0.0234 ㎡」再手抄进去。实际跑起来三个问题：

1. 抄错一次差几百块，而且单子看着完全正常，查不出来。
2. 规格一改（板从 1250 宽变成 1000 宽）系数就作废，没人回头改 —— 报价还是旧口径。
3. 报价单上「0.31 ㎡ × 80 = 25.00」自己乘不上，客户当场就要怀疑（0.3125 才对得上）。

## 改了什么

### 1. 折算规则（`crates/findb/src/processfee.rs`）

| 口径 | 折合量 | 需要几维 |
|---|---|---|
| 只 / 条 / 件 / 个 / 支 / 片 / 套 / 根 | 1 | 规格可以不填 |
| 米 / 米长 / m | 第一维 ÷ 1000 | 1 维够算，但**至少写两维**才认 |
| ㎡ / 平方 / 平方米 / 平米 | 前两维相乘 ÷ 1 000 000 | 2 维 |
| kg / 公斤 / 千克 | 三维相乘 ÷ 1 000 000 × 密度 | 3 维 + 密度 |

- `parse_spec` 宽进：`1250*250*3`、`1250×250×3`、`1200 x 80`、`1250mm*250mm`、全角 `＊`、
  逗号分隔都认；**严出**：只有一个数（`1200`）就返回 `None`，绝不按 `1200 × 1` 猜。
- `spec_factor` 一律 `.round_dp(4)`：0.3125 只留 2 位会变 0.31，80 元/㎡ 从 25.00 变成 24.80。
- `spec_prices(rate, unit, specs, density)`：一个费率 + 一批规格 → 每行 `{spec, dims, factor, price, note}`。
  **不落库** —— 算完就扔，结果是给人看的，不是账。
- `quote_with_spec(...)`：报价时带规格直接折算。**手录系数优先**（`basis="manual"`），
  没有系数才按规格算（`basis="spec"`）—— 人工核对过的实测值不能被近似值顶掉。

### 2. 接口（`crates/finweb/src/handlers/processfee.rs`）

- `GET /api/price-rules/quote` 新增 `spec` / `density`；`spec` 非空时 `conv` 多带 `dims` 与 `basis`。
- 新增 `POST /api/price-specs/calc`：`{rate, unit, specs, density}` → `{rows}`，`price_view` 权限，
  `specs` 上限 500 行（再多就不该在这个框里算了）。
- 折合量返回 `fmt_dp(4)` 而不是 `fmt_money()`：显示 0.31 会和金额对不上。

### 3. 界面

- 「销售 → 加工费规则」新增「按规格算单价」面板：费率 + 口径 + 密度 + 规格大框 → 一张表
  （规格 / 规范写法 / 1 件折合 / 单件价 / 说明）。坏行金额列打 `—`，不写 `0.00`。
- 报价试算框多了「规格」一格；桌面端同一页也能填，折算过程以灰字显示
  （「折算（按规格 1250×250×3：300 只 × 0.3125 = 93.75 ㎡」）。

### 4. 门禁

- 单元测试 6 条（文件共 21 条）；集成测试 `spec_turns_a_rate_into_a_piece_price`；
  渲染检查 3 条 `specRowsHtml`；变异 `73–76`（缺一维按 1 补 / 手录系数被盖 / 折合量只留 2 位 / 不看密度），
  全部实跑拦下。

## 兼容

老账套直接升，schema 无变化（v1.8.87 的 v49 已含所需字段）。不用规格就当它不存在，
原来的折算系数照旧生效。

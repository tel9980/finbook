# v1.8.54 —— 数据范围：漏一个出口，就是一套"看着都对"的两份数

`SECURITY_TODO` 推荐顺序第 2 项（M-4 设备绑定已在 v1.8.53 修完）。

## 一、漏的不是报表页，是"不是报表页"的那些地方

权限分两层：**角色**决定能干什么，**数据范围**（`DataScope`）决定能看哪些数据。
报表页有权限检查是本能；漏的是**不是报表、却显示同一批数字**的地方：

| 出口 | 改前 | 现在 |
|------|------|------|
| 试算平衡（JSON / CSV / PDF / 打印 / Excel） | 带范围 | 带范围 |
| 三大报表（打印 / Excel / JSON） | 带范围 | 带范围 |
| 明细账 / 总账 / 日记账 | 带范围（`ledger_query_from` 统一收口） | 带范围 |
| 凭证列表 / 凭证打印 / Ctrl+K 搜索 | 带范围 | 带范围 |
| 工作台 | 带范围 | 带范围 |
| **首页**（本期经营结果 / 钱在哪 / 本年累计） | **不带**（`financial_totals(.., None)`） | **带范围** |
| **往来**（账龄 / 未核销清单） | **不带**（只查权限，不查科目） | 范围外一律 **403** |
| 存货账龄 | 不适用（存货不是科目维度） | 不适用 |

这两处的症状是一样的：**首页看到全公司，点进利润表只剩自己的**。两边都"看起来对"，
数字不一样，但没有一处报错。

## 二、范围外给 403，不能给空清单

账龄和未核销清单里，空清单有明确含义：「这户真的没欠款」。越权时也返回空，会计会
拿着这个结论去催款、去对账，更糟的是他会以为账套数据丢了。

所以范围外一律：

```
403 无权查看该科目
```

空与无权限必须分开 —— 下一步动作完全不同（一个去催款，一个去要权限）。

## 三、怎么知道还漏没漏：从"取数"倒着找，不从权限中间件找

不看权限代码，看**取数点**：把 `handlers.rs` 里每一处取金额的调用列出来
（`financial_totals` / `financial_ytd` / `financial_analysis` / `money_position` /
`statement_table` / `cash_flow_statement` / `equity_statement` / `trial_balance` /
`settle::aging` / `open_entries` / `invoices::tax_summary`），逐个看它拿到的 `scope`
是 `Some(&user.user)` 还是 `None`。

中间件只管"能不能进这个页面"，而"页面里查了几批数、每批带不带范围"只有取数点自己
知道。这个方法这一轮就把首页与往来两处揪出来了。

## 四、测试与验证

`crates/finweb/tests/scope_dashboard.rs` 两条，都从**越权者**视角写：

- 范围只给 `600101`（主营业务收入）的会计，首页「手头现金」不能是 `100.00`
  （那 100 属于范围外的 `1001`）；
- 同一会计查 `112201` 的账龄 / 未核销 → **403**，且错误信息说明是权限问题；
- 反向一条：查自己范围内的科目仍然 200 —— 加闸门最容易顺手把正常路径也堵掉。

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **1077** 全绿（实测输出，不是分项相加） |
| 变异验证 | 107 → **109**，2 条全部拦下：把首页 `scope` 改回 `None`、把账龄的科目判断改成 `if false` |
| 自检 | check-ci / check-js / check-portable / check-design-doc / check-simple-nav 全过 |

顺带一提：这一轮**没有发现新的越权读**，说明其余出口的范围是接对了的。而"没发现"
也是要写下来的结论 —— 否则下一次没人知道这块查过。

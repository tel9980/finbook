# v1.8.83 —— 往来期初明细可以逐行「改」了

这一版只补一个真实的操作缺口：老账搬迁时按单据导入的**往来期初明细**填错了，
以前只能删掉重加或整张表重导，现在每一行都能直接改。
**不改数据结构、不改任何记账规则**，`1.8.82` 的账套可以直接用。

---

## 一、问题：填错一行，得删掉整行重来

网页「期末 → 往来核销」页下方的「往来期初明细（按单据·迁移）」，
以前只有「查」和「删」两个动作。发现客商编码写错、单据日期填反、金额多打一个零，
只能：

1. 删掉那一行 → 回导入页改 Excel → 重新导入；或
2. 靠导入页「同三元组幂等跳过」的规则绕过去 —— 但那根本不是「改一笔账」，
   一不留神还会撞上别的单据号。

这是上一轮盘点里唯一没被「应收应付对账批次」顺带盖住的功能缺口。

---

## 二、改法：每行加一个「改」

现在表格右侧多了「改」按钮（有「录凭证」权限才显示），点开可以改：

| 能改 | 保留不动 |
|---|---|
| 类型（应收 / 应付）、客商编码、客商名称、单据号、单据日期、金额、备注 | 原始录入人、录入时间、行 id |

保存走新接口 `PUT /api/arap-opening/:id`（与既有查询、删除同一路径），
并记一条「档案 / 修改往来期初」日志。桌面端本来就没有这块界面，无需改动。

**校验口径与导入完全一致**，另外多一道防重：

| 检查 | 不通过时 |
|---|---|
| 类型只能是 `ar` / `ap` | 400 类型只能是应收 ar 或应付 ap |
| 客商编码、单据号不能空 | 400 客商编码和单据号不能为空 |
| 单据日期须 `YYYY-MM-DD` | 400 单据日期须为 YYYY-MM-DD |
| 金额必须是正数 | 400 期初金额必须是正数（预收/预付请填科目期初） |
| 同一「类型 + 客商 + 单据号」不能撞车 | 400 同一客商下已有这张单据号，请换个单据号 |
| 行已经不存在 | 404 往来期初明细不存在 |
| 没有「录凭证」权限 | 403 |

防重这一条是导入没有的：导入遇到相同三元组是**静默跳过**（用来保证重复导不会翻倍），
但「改」如果把 A 行改成 B 行已有的单据号，账龄分析和对账就会凭空少一笔，
所以必须显式报错，而不是悄悄放过。

---

## 三、口径没变：改明细不等于改科目期初

期初明细仍是**影子挂账**：进「账龄分析」（单据号标「期初」），暂不参与自动核销；
金额总额仍以**科目期初**为准。改一行明细不会自动去动 `112201` / `220201` 的期初数，
所以改完仍要按 `docs/老账搬迁操作步骤.md` 第三节把三处对一遍：

1. 往来期初明细的应收/应付合计；
2. 科目余额表 `112201` / `220201` 的期初数；
3. 资产负债表、试算平衡表。

文档也把两个容易混的问题分开了：**科目期初余额**属于账套起点，仍不能跨期间随便改；
**往来期初明细**是逐笔单据，现在可以一行行改。

## 五、升级注意

- **无 schema 变更**：数据库仍是 v48，不需要迁移；`arap_opening` 表结构一个字段没动。
- **新增一个接口**：`PUT /api/arap-opening/:id`，旧客户端不用它也不受影响。
- **账套、凭证、报表数字一个都没变**；只是把「删掉重加」换成「原地修改」。
- 网页版需要刷新一次页面才能看到新的「改」按钮（静态资源有缓存）。

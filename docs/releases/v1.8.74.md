# v1.8.74 —— 月度简报：一页纸，零新增录入

## 一、问题

老板每月就问三件事：赚了多少、钱在哪、干了多少。这些数都躺在账里，但分散在利润表、
资产负债表、应收应付、生产订单、返工单五六个页面上。凑一遍半小时，于是就不看了。

## 二、这一版做了什么

新增「月度简报」（桌面端与网页端都在「管理会计 / 账簿报表」下），一张纸十一行：

- **赚了多少**：营业收入 / 营业成本 / 期间费用 / 税金 / 净利润
- **钱在哪**：货币资金 / 应收账款 / 应付账款 / 存货
- **干了多少**：本月完工数量 / 返工成本

每行都带上月数与增减、增减%。**不新增任何录入字段**，全部从既有单据算出来。

三个口径决定：

1. **收入成本利润与利润表同一份实现**（`advanced::financial_totals`），包括「小厂不做
   成本核算时把 5101 等成本类科目余额计入成本」那段处理。简报不再写第二遍口径。
2. **上月没账时同比显示「—」，不是 0%**。判据看上月有没有凭证（不是金额是否为 0），
   上期为 0 或负数时也不给百分比。
3. **增减的方向由数据层给**（`better_high`）：利润涨是好事、应收涨不是。界面只上色，
   不猜方向——猜错会把「应收暴涨」标成绿色。

顺手把 `FinTotals` 补了 `expense` / `tax` 两个字段（原来只有 revenue/cost/net_profit，
拆不出「期间费用」和「税金」），净利润的算式原样保留、只改了写法。

## 三、明确放弃

**不做**按槽位/面积摊制造费用。氧化厂可以按「槽位占用小时」「挂具面积」摊水电与槽液，
但得先给每条工艺路线补录槽位数与面积两个属性。一个月几十张单的小厂，录入成本远大于
分摊精度带来的收益。按报工工时/产量摊已经够用（v1.8.69）。

## 四、验证

| 项 | 结果 |
|---|---|
| `cargo test --workspace --locked` | 36 个目标全绿 |
| 新增 findb 单测 | 十一个数 + 上月对比（含百分比与方向标记）；上月没账时同比全空；1 月的上一期是去年 12 月 |
| 新增接口用例 | 造上月 1000 / 本月 2000 两张已记账凭证 → 收入 2000、上月 1000、增减 +1000、百分比 100.00、现金 3000 |
| 变异 ㊼ | 3 条全拦下（上月没账也硬做同比、应收正负颠倒、百分比少乘一百） |
| fmt / 警告 / clippy | 0 处 / 0 条 / 0 error |
| check-js、check-ci | 通过 |

## 五、没动

- 不做出图（趋势折线）：一页纸放十一个数已经够了，画图会把页面撑长，老板反而不看。
- 不做部门维度（哪个班组最费钱）：那要看多维损益，口径不一样，混在一页纸里会让人误读。
- 客供料仍不出凭证（v1.8.70 定案）。

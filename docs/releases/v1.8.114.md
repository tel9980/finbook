# v1.8.114 账期加开票日口径 + 工作台待办补全 + 慢查询基准

## 问题

三件事：

1. **账龄起点只能按发货日**：应收逾期到底从「发货日」还是「开票日」起算，不同厂习惯不同。之前写死在「发货日（没发货退回订单日）」，改了习惯就要改代码。
2. **工作台「该干的事」还缺两块**：货发了但票还没开（催财务开票）、供应商的钱快到账期了（该安排付款），都不在工作台待办里，老板要翻进单据页才知道。
3. **没有慢查询基准**：历次「去 N+1」都是凭 grep 找到的逐单查询，没有一套可复跑的基准来量化「改之前 vs 改之后」，也不好发现新的慢点。

## 改法

- **账期起点开关**：`BookOptions` 加 `ar_aging_start`（`ship`=发货日默认 / `invoice`=开票日），账套参数页加下拉框；`so_receivable_as_of` 按开关选起点——开票日口径下用「最早有效销项发票日」，没开票退回发货日，再退订单日。
- **开票日数据源**：新增 `so_invoice_dates(db)`——发票与订单的关联在 docflow 勾稽表（`push_from_so` 下推发票时 `link_add("so",..,"invoice",..)`），取每张订单最早一张 `kind='out'` 且 `status!='rejected'` 的发票日期。
- **工作台待办两条**：`collect` 与 `collect_todos` 各加——「销售/待开发票」（已发货但无有效销项发票的确认单，跳发票管理）与「采购/快到期的应付」（应付到期日在今天起 30 天内，跳往来核销）。
- **慢查询基准**：新建 `crates/findb/benches/hot_reads.rs`（criterion），种子 500 张销售/采购单+往来凭证，基准 4 个热读：`so_receivable`、账龄分桶、到期月表、工作台 `collect`。

## 三条规矩

1. **开票日口径是「可选」，不是替换**：默认还是发货日；只有账套参数选了「开票日」才走开票日，旧账套（缺字段）按发货日。
2. **待开发票只看「已发货」的确认单**：没发货的单还没到开票环节，不算；作废发票不算（得重新开），所以只要存在「任何一张作废发票但没有效发票」仍算待开。
3. **快到期应付含今天**：窗口是 `[今天, 今天+30天]`，今天到期的必须提醒（左闭右闭），不能漏掉当天。

## 升级说明

**schema 不变**（仍 v55）。新增账套参数 `ar_aging_start`，默认 `ship`（发货日），旧账套升级后保持原行为不变；想改开票日口径到「设置 → 账套参数」里选。工作台「该干的事」多出「待开发票」「快到期的应付」两条，无需配置，自动出现。

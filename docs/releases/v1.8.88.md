# v1.8.88：加工费单价可以批量导入了

## 一句话

客户发来一张价目表，**整张贴进来就导完**，不用一格一格点；同一格重导是覆盖，
坏行只跳过它自己，并且告诉你「第几行、坏在哪」。

## 为什么做

v1.8.87 做完了单价矩阵（客户 × 物料 × 口径），但录入只有两条路：
点格子改价、或者开弹窗填七列的表单。氧化厂四十个客户、十几个工件，
真按这个录入法，价目表永远录不完 —— 而客户发过来的本来就是 Excel。

## 改了什么

### 1. 导入解析（`crates/findb/src/processfee.rs`）

- `import_rules` / `import_calc_units`，返回 `PriceImport{created, updated, skipped, warnings}`。
  **不复用**通用的 `ImportResult{ok, skipped, warnings}`：要区分「新建」和「覆盖已有那一格」，
  会计最怕把「导入 200 条」当成「加了 200 个价」。
- 表头自动跳过（首格含「物料/编码/客商」或 `item`/`code`，**且第四格不是数字**）；
  `#` 开头当注释；空行不计行号。
- 身份 = `物料 + 客户 + 口径 + 生效日`：同格覆盖 → `updated`，换生效日 → 新一版 `created`。
- 坏行只跳过自己，警告带**真实行号**（表头占第 1 行，与 Excel 里看到的一致）。
- `rule_import_template()` / `unit_import_template()` 与解析器**共用同一份列头常量**，
  模板不会和解析器跑偏。

### 2. 接口（`crates/finweb/src/handlers/processfee.rs`）

`POST /api/price-rules/import`、`POST /api/calc-units/import`（`price_edit`）、
`GET /api/price-import/template?kind=rules|units`（`price_view`，带 BOM 的 CSV）。
请求体 `{text}` 或 `{file}`（xlsx/csv 的 base64）—— 两条入口都走同一个 CSV 解析器。

### 3. 界面（`crates/finweb/static/app-hr.js`）

「销售 → 加工费规则」工具栏「批量导入」：选导入什么、粘贴（或选文件）、开始导入。
结果区说人话：`新增 12 条、覆盖 3 条、跳过 2 行`，跳过用黄字列原因（最多 10 条，
多余的显示「还有 N 行没列出来」）；一条都没读到就说「一行都没读到 —— 是不是粘错了地方？」，
绝不显示「新增 0 条」让人以为成功了。

### 4. 顺带修掉一个会把价藏起来的毛病

矩阵里「有价但还没设折算系数」的格子，原来整格渲染成「没设系数」三个字，
把已经录好的价一起藏了 —— 导入一张价表之后满屏「没设系数」，用户会以为没导进去。
现在价格照常显示，下面补一行小字「未设系数 · 点这里录」（点了直接开录系数）。
通配行（「任意物料」）本来就没有系数概念，不显示这行小字。

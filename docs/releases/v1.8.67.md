# v1.8.67 —— 计件单价跟着工艺版本走

## 一、问题

计件单价原来只有「物料 + 工序名」两列。工艺一改版（同一道工序换了槽液、加了工时），
单价跟着改，历史报工就会按新价重算 —— 上个月已经发出去的工资，这个月重算一遍数不对，
谁也说不清差在哪。反过来，单价还钉在老价上，新活就少发钱。

## 二、这一版做了什么

- `piece_rate` 新增 `version`（留空 = 不限版本）；报工流水 `prod_op_log` 新增
  `routing_version`，在报工那一刻从 `routing.version` 抄下来，事后不回查工艺路线 ——
  工艺改了删了，历史流水的版本与金额都不变。
- 匹配规则：先比「物料 + 工序」的具体程度，同档里「钉住这一版」的优先于「不限版本」；
  流水没带版本时，钉住版本的规则不适用（说不清哪一版就不按它算）。
- 只有非默认版本工艺的账套，工序现在也能生成（先找默认版本，没有就退到第一个版本）；
  接口 `POST /api/prod/:id/ops/init?version=V2` 可指定版本。
- 网页端建工艺路线支持 `version` 字段，按版本分组保存（删除是按版本删的，混在一起会串）。
- 桌面端与网页端的计件单价都能填版本，明细表显示每条流水按哪一版算的价。

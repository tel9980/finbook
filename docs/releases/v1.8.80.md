# v1.8.80 —— 开发流程：本地只做快检，编译和测试交给 CI

这一版**不影响你拿到的软件**：数据库结构没变、界面没变、功能没变，
`1.8.79` 的账套可以直接用。改的是我们自己的做法 —— 以及一个被这次改动顺带揪出来的漏洞。

---

## 一、起因：本地编译其实一直在白干

发版前我一直在本地跑两件事：`cargo test --workspace`（6 分钟）和交叉编译 EXE（4 分钟）。
盘了一下账，两边都是亏的：

| 做法 | 耗时 | 结论 |
|---|---|---|
| 本地 `cargo test --workspace` | ~6 分钟 | **不值**：CI 里它和其它 15 个 job 并行，结论不比本地慢 |
| 本地交叉编译 EXE | ~4 分钟 | **不值**：`release.yml` 只在 tag 上出产物，本地编出来的东西没人要 |
| 本地 `node tools/preflight.js` | **20 秒** | **值**：挡的是「一提交就让整轮 CI 白跑」的低级错误 |

而且本地编译不是白干，是**有过事故的**：

- v1.8.76 本地编出的 `dist/` 被 `git add -A` 带进库里，CI 把它当成发布产物挂上了 Release；
- 为了清掉那个 30MB 的历史对象，全仓历史被重写了一遍，还要等 GitHub 侧 GC。

所以规矩改成一条：**本地不产出发版物，编译和测试交给 GitHub**。

---

## 二、新增 `tools/preflight.js`（提交前的快检）

```bash
node tools/preflight.js          # 全量，20 秒
node tools/preflight.js --fast   # 改文档/前端时用，6.6 秒
```

六步，判据一律看**退出码**（不看输出文字 —— 这条教训写在 `tools/check-js.js` 头部）：

| 步骤 | 耗时 |
|---|---|
| 前端静态检查（语法 + 重复 id + 行为约束 + 视图真渲染） | 3.9 s |
| 仓库卫生（CI 配置可解析 + 变异清单未过期 + 全编码无损坏） | 2.6 s |
| 工具脚本可移植性（不许写死本机路径） | 0.07 s |
| 设计文档引用未漂移 | 0.07 s |
| `cargo fmt --all -- --check` | 2.1 s |
| `cargo check --workspace --all-targets --locked` | 10.9 s |

**不含** `cargo test`、变异测试、E2E、打包 —— 那些留在 CI。
失败时只回放末尾 40 行，不让长输出淹掉结论。

## 三、顺带揪出来的：CI 从来没有格式闸门

`cargo fmt --check` 一跑就红 —— 仓库里**有 8 个文件的格式本来就没对齐，而 CI 一直没拦**。
也就是说格式再脏也没人会发现，直到某天有人顺手 `cargo fmt` 一下，diff 里冒出几百行无关改动。

两件事一起做了：

1. `cargo fmt --all` 修正（+159/−76，**纯排版，无逻辑改动**）；
2. CI 的 Test job 加 `cargo fmt --all -- --check` —— 两秒的事，和 preflight 同一条命令，
   本地不过、CI 必红，两边不会各说各话。

## 四、README 里写成了规矩

- **§8.0 分工**：三条账摆出来（本地 test 不值、本地编 exe 不值、本地 preflight 值）。
- **§11 改写**：标题从「重新交叉编译 Windows 包」改成「**出 Windows 包：发版时由 CI 编，本地不编**」，
  正文给四步发版流程；本地编译降级为「只想亲眼看一眼 exe」时的手段，并注明产物留在 `target/`、别拷进 `dist/`。

## 五、如果你自己改了代码想验证

```bash
node tools/preflight.js    # 提交前，20 秒
git push                  # 剩下的交给 CI，看 Actions 结果
```

真的要看 CI 具体哪个 job 红了，再按需跑 `cargo test --workspace` 或对应单测 ——
README §8.1 列了手工跑全量的命令。

## 六、本版没有的东西（说明清楚，免得误会）

- 没有数据库变更（schema 仍是 **v48**，与 1.8.79 相同）
- 没有界面变化
- 没有修任何业务 bug
- 1.8.79 的账套、备份文件可以直接用

也就是说：**如果你只是用软件，停在 1.8.79 也完全没问题**；这一版的意义是让下一版更快、更少出错。

# FinBook v1.8.7

这一版是**桌面端功能与 CI 门禁加固**：报表期间跟随顶栏全局期间，建账向导默认开启审核/出纳并写入账套参数，余额表/汇总表零值统一显示 `0.00`，备份文件名精确到毫秒，期末结转/模板生成加事务互斥，对比表变动率保留负号，清空业务数据时清理挂凭证链接，期初余额在已结账期间锁定。

**不改记账规则、不改凭证校验、不改数据库结构**（仍为 V36），直接覆盖升级即可。

## 这一版修了什么

### 1. 桌面报表期间跟随顶栏全局期间（H17）

桌面端的“科目余额表/明细账/凭证列表”在进入页面时只把期间初始化为当前全局期间，之后切换顶栏期间页面不动，用户看到的还是旧数。

现在新增“上次跟随的全局期间”字段：只要用户没有手工改过期间输入框，切换顶栏期间就会同步更新 `from/to`；一旦用户手工改过，后续切全局期间保留用户选择。覆盖报表、账簿、凭证列表三处，并补了期间同步单元测试。

### 2. 建账向导增加审核/出纳选项，默认开启（H18）

桌面端建账向导曾把 `enable_audit` / `require_cashier` 硬编码为 `false`，导致新建账套出生就绕过审核留痕和出纳复核，和 Web 端建账口径不一致。

现在向导“进阶设置”里明确显示“启用审核留痕”“启用出纳复核”两个复选框，均默认勾选，勾选结果写入 `BookOptions`；测试夹具也都显式声明这两个字段，避免依赖默认值。

### 3. 余额表/汇总表零值统一显示 `0.00`（M5）

Web 端三大报表已统一零值 `0.00`，但桌面“科目余额表 / 汇总表”仍用 `amount_label`，零值留白，容易被误读为“没取到数”。

现在余额表的期初/借/贷/累计/期末列和汇总表的借贷发生额列切到 `report_amount`，零值显式写 `0.00`；凭证分录、明细账等半列本来就该空的表格保留 `amount_label` 零值留白，口径不变。

### 4. 备份文件名精确到毫秒（M6）

手工备份文件名只精确到秒，同一秒内连续点击“立即备份”会互相覆盖，静默丢失一份。

现在文件名时间戳精确到毫秒（`YYYYMMDD_HHMMSSmmm`），连续点击不再覆盖；旧备份和新备份的解析规则兼容。

### 5. 期末结转 / 模板生成加事务互斥（M1）

结转损益、年末结转和模板生成都存在“先检查再写入”的竞态：两个并发请求都能通过“本期未结转/未生成”检查，各插一张重复凭证。模板生成还存在“凭证已保存、`mark_generated` 失败时下次再生成一张”的问题。

现在取数、幂等判断、取号、落库全部放进同一 `BEGIN IMMEDIATE` 写事务，后来者等待前者提交后再取数，第二次看到净额已清零，拒绝重复结转；周期性模板按 `last_period` 拒绝本期重复生成，手工模板保留多次调用能力。

### 6. 对比表变动率保留负号（M2）

对比表“变动率”对分子取了 `abs()`，收入从 100 降到 80 时显示 `+20%`，与差额的负号自相矛盾。

现在分子保留方向，只对分母取绝对值；涨跌方向与差额一致。

### 7. 清空业务数据时清理挂凭证链接（M3）

桌面“清空业务数据”删除了凭证和期初，但没有清理 `payroll.voucher_id`、`stock_move.voucher_id`、报销/预付/盘点/票据/借款等单据的 `voucher_id`；之后界面会指向不存在的凭证号，新建凭证复用该 id 时还会“认错”新凭证。

现在同一事务里把所有业务表的 `voucher_id`（含 `paid_voucher_id` / `social_voucher_id` / `settle_voucher_id`）置 NULL 或 0，再删凭证；补了回归测试。

### 8. 期初余额在已结账期间锁定（M4）

结账后仍可改期初余额，会让已结账月份的历史报表全部变动，和“已结账不能删凭证”的锁口径不一致。

现在 `upsert_begin` / `delete_begin`（含事务内版本）在写入前校验 `closed_upto`，已结账期间拒绝修改并提示“请先反结账”。

### 9. CI 发布门禁加固（M7 / M8 / M9 / M10 / M12）

- Release workflow 新增“校验 tag 提交在 main 上”并在发布前等待该提交的完整 CI 全绿（含 `check-js`、`check-ci`、`cargo test`、变异测试、E2E），再执行全量测试和交叉编译；
- 变异测试把 `notRun > 0`（测试根本没跑）也判为失败，不再把“变异没被守住”当成通过；
- `check-ci.js` 修复两处假检查：测试名提取直接取命令数组最后一项（不再依赖永远不匹配的引号正则）；`mutation` job 必须真的执行 `node tools/mutate-rust.js`，光有文件不够；
- `check-simple-nav.js` 删掉恒真断言，用 app.js 的真实 `isNavVisible` / `navMatches` 逻辑重写；
- Playwright CI 设 `retries: 0`，本地保留 1 次，不再把首次失败的重跑吞掉。

# v1.8.65 —— 改得动的与改不动的：工资表三道闸，报价一键带出

这一版没有新功能，只有两件"补齐"：把工资表的改动口径补严，把加工费规则接进开单。

## 一、工资表：三条改动路，同一道闸

工资表有三条改动路径：界面上改一行、整批重算、v1.8.63 新加的计件回填。
删除单行早就拦着（已挂凭证的行不许删），但**改金额这三条路一直是敞开的**：

- 期间已结账 —— 凭证都不许录了，工资表却还能改；
- 本月工资计提凭证已生成 —— 凭证按旧金额入了账，改完工资表，`voucher_id` 还链着那张凭证，
  界面上看着"已计提"，对账时才发现差钱。

所以新增 `business::payroll_guard_editable(db, period)`，两条判断写在一处：期间已结账拒绝；
该期间有工资行链着计提/社保/发放任一张凭证拒绝。三条路径各自调它——`fill_one` 里自己调，
因为桌面端和网页端都走它，闸放在数据层，以后再加第四条路径也跑不掉。

计件回填尤其要挡：它是把应发**往上抬**，看着"多发了不会错"，但账务上改的是同一个字段。
本月已按底薪计提 3000、回填后工资表写着 5000，到发放环节按 5000 冲应付，
应付账款会剩 2000 要人去总账里找。正确顺序是：先回填计件 → 再生成计提凭证。

报错分开写清是哪条闸，并指向下一步：

```
2026年1月 及以前期间已结账，工资表不能再改
2026年1月 的工资凭证已生成（1 行已链接凭证），要改工资请先删除/反记账相关凭证
```

## 二、销售报价单：按加工费规则一键报价

v1.8.63 做的加工费规则（面积×单价 → 最低收费兜底 → 加急）此前只能在"加工费规则"页试算，
真正开单时单价还是手敲。现在报价单那行多了个「按规则报价」按钮：

- 填了存货（物料）与数量，点一下，单价按规则算出来填进去；
- 弹出提示把拆解写清：`12.5 × 18 = 基础价 225，最低收费补差 0，加急 42.5，合计 267.50`；
- 单价填的是「合计 ÷ 数量」（保留 4 位），这样报价单金额正好等于规则算出来的合计；
  低于最低收费时这个单价会高于规则单价——那正是"最低收费"的意思。

计价口径全在 `findb::processfee`，界面不自己算。

## 没动

- **客供料仍不出凭证**：数量口径，要不要按来料加工的账务口径入账需要厂里会计确认。
- **桌面端销售开单仍手填单价**：本轮只接了网页报价单；桌面端开单编辑器没有"按规则报价"。
- **计件单价不分工序版本**：`piece_rate` 只有物料 + 工序名，不看 `routing.version`。
- **成本分摊仍是人工设率**：槽液、水电、返工件成本不自动分摊；挂具无台账。
- **多维损益不做分摊**，本版未变。

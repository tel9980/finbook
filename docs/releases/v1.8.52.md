# v1.8.52 —— 桌面端补上三处「网页有、桌面没有」

这三个都不是新功能，是**同一件事的第二个入口**。两个入口最容易长成两套逻辑，
所以这一版的重点是「共用一份数据和一条口径」。

## 一、发票管理（桌面版）

一般纳税人能不能抵进项，看两件事：**有没有专票、认没认证**。`taxdecl.rs` 里只有
`status == "verified"` 的进项才计入可抵扣。而这版之前，登记发票与点「认证」只能
在网页端做。

后果不是「少个按钮」。桌面版是记账的主入口，记完账没处登记发票，于是「记了账但没
登记发票」谁都不会发现——直到申报时进项凭空少一截，再去翻三个月凭证。

页面顶部三张卡，**必须分开**（加成总数没有意义）：

| 卡 | 含义 |
|---|---|
| 待认证进项税额 | 登记了但还没认证，**现在不能抵** |
| 已认证进项税额 | 可以抵 |
| 销项税额 | 要缴 |

税额拆分是纯函数 `split_amount_tax`：不含税 = 合计 ÷ (1 + 税率)，税额 = 合计 − 不含税。
**先算不含税再相减**，不用「合计 × 税率 ÷ (1+税率)」各算一遍——两条路径在分位上会差
1 分，而发票上「不含税 + 税额」必须刚好等于合计。

顺带修了 `invoices::summary` 的一个语义问题：它把待认证和已认证加在一起，报税时看到
那个数是错的。新增的 `tax_summary` 按「进项/销项 × 状态」分开。

## 二、期初收集表（桌面版）

四张纸（客户应收 / 供应商应付 / 账户余额 / 基本资料）原来的构造逻辑整块长在
`crates/finweb/src/sheets.rs` 里。这一版**把数据搬到 `findb::opening_book::collection_template`**，
返回与 xlsx 无关的 `CollectionSheet`，两端只负责摊成自己的 Sheet 类型。

为什么非要搬而不是复制：这张表**同时是导出和导入的契约**。在桌面下载、到网页导入，
列头必须一模一样；两端各写一遍，第一列一改就有一边悄悄错位，而 xlsx 不会报错。

桌面上的四个动作就是流程本身：

```
期初收集表（下载） → 导入期初收集表（先预检，不落库）
                   → 确认导入 → 导入后对账
```

预检阶段借贷不平会红字写「直接导入会被拒绝」，不让人填完两百行再被拒一次。

## 三、现金流打印/导出带上期对比

桌面导出的 `cash_flow_sheet` 原来只有本期四列。现在走 `cash_flow_sheet_with_prev`：

- 上期取**等长的上一段**（`reports::prior_range`），季度报表不能拿 3 个月比 1 个月
- **上期有、本期没有的项目单列并标「（上期有）」**——按本期循环一遍就收工，
  「上月买了设备、这月没买」这件最该看见的事会被吞掉，而两张表看起来都挺对
- 只比净额（流入/流出再乘两期，A4 横向放不下）
- 取不到上期就自动退回四列，不报错

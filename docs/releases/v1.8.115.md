# v1.8.115 清冗余/死代码：删订单级冗余列

## 问题

`sales_order.shipped_amount` / `purchase_order.received_amount` 两个**订单级**冗余列：建表后虽被 `so_save`/`po_save` 写回，但执行进度真值在 `so_shipment`/`po_receipt` 流水表。v1.8.113 已经把 `so_get`/`po_get`/`so_list`/`po_list` 统一改成「实时汇总流水」并删了行级两列（`so_line.qty_shipped`/`po_line.qty_received`），订单级这两个列就成了「建表占位 + 写回 + 被覆盖」，没有任何读方真信它，是纯冗余。

## 改法

- **删列（schema v56）**：`SCHEMA_VERSION` 55→56；新增 `fn migrate_v56(conn)`（循环 `ALTER TABLE ... DROP COLUMN`，`column_exists` 幂等）；DDL 与 `MIGRATE_V6` 同步删 `sales_order.shipped_amount` / `purchase_order.received_amount`；迁移链 `migrate_v55` 后接 `migrate_v56`。
- **读路径**：`so_get`/`so_list`/`po_get`/`po_list` 的 SELECT 删这两列，结构体字段先 `Money::ZERO` 再被实时汇总覆盖（`so_shipment_progress` / `po_receipt` 累加）；`so_save`/`po_save` 的 INSERT/UPDATE 删这两列与参数。
- **结构体字段保留**：`SalesOrder.shipped_amount`/`PurchaseOrder.received_amount` 字段**不删**——它们是读路径实时汇总后的内存结果，`workbench` 走势、`so_shipment_notice` 等下游仍在用。

## 三条规矩

1. **删的是列、不是字段**：DB 层删两列（迁移 + DDL），Rust 结构体字段保留（实时汇总后填值），下游读字段不受影响。
2. **迁移幂等**：老账套带这两列 → 升级删掉；全新账套 DDL 本就没有 → `column_exists` 跳过，再跑不报错。
3. **进度只有一个真相**：已发/已收金额一律从 `so_shipment`/`po_receipt` 实时汇总，不再有任何读方读「写回的冗余列」。

## 测试与门禁

- 变异 148（删列迁移漏掉销售订单 shipped_amount）、149（采购单执行进度改读冗余列、回退为不汇总）实跑拦下。

# v1.8.59 —— 一万行文件的第二课

v1.8.57 把 `handlers.rs` 从 18119 行拆到 4707 行。这一版接着做两件事：把里面的
**请求/响应结构**按归属搬走，把两万行的 **`tests/api.rs`** 按域拆开。

## 一、DTO：谁用谁负责

移走 115 个类型：

| 去向 | 数量 | 判据 |
|------|------|------|
| `src/dto.rs`（共享契约） | 8 | 被 ≥2 个域引用，或主模块/测试也用 |
| 各自的域文件（`handlers/hr.rs` 等） | 107 | 只被一个域引用 |
| 留 `handlers.rs` | 12 | 只在主模块内部用 |

判据是数引用点，不是猜：主文件其余部分、15 个域文件、`tests/`、`lib.rs` 各出现几次。

**为什么「只被一个域用」的要搬走**：留在共享文件里等于把实现细节挂到公共词汇表上 ——
下一次有人改它，会以为自己动的是契约。

`handlers.rs` 4707 → **3426 行**，`dto.rs` 577 → **673 行**。

## 二、`tests/api.rs` 两万行：拆文件，不拆测试二进制

Rust 有个硬约束值得记下来：**`tests/api.rs` 里的 `mod foo;` 会去 `tests/foo.rs` 找** ——
crate 根文件的子模块放在**它所在目录**，不是同名子目录。所以既要拆成多文件、又要保留
「一个测试二进制」，正确形状是把根文件挪进目录：

```
tests/api/main.rs   ← 共享夹具（imports + 17 个 helper）
tests/api/auth.rs   ← main.rs 里 mod auth;
tests/api/settle.rs
...
```

Cargo 会把 `tests/api/main.rs` 识别为名为 `api` 的测试目标，`mod auth;` 就能找到同目录文件。
按用例里出现的路由前缀归属，194 条用例落到 14 个域文件。

唯一判据：**测试条数还是 194**。

## 三个坑（都是"看着没问题"的那类）

1. **`mod common;` 路径变了**。根文件进了子目录后，`tests/common/mod.rs` 要靠
   `#[path = "../common/mod.rs"]` 指过去。
2. **`use common::*;` 子模块看不见**。子模块只写 `use super::*;`，父模块里的 `use`
   不是重导出 —— 25 条用例集体报 `cannot find function authed_get`。改成 `pub use`。
3. **夹在用例之间的 helper 会被整段漏掉**。第一版只把「文件开头到第一个 `#[tokio::test]`」
   当夹具区，于是 17 个定义在文件中间的 helper（`authed_delete`、`provision_plain_user`…）
   既不在头段也不在任何用例块里，直接消失。**所以自检不能只数测试条数，还要比对
   「拆前拆后的顶层 fn 名字集合」** —— 这条是这次真正的收获。

## 又一处「假绿」

`tools/check-ci.js` 靠「`crates/finweb/tests/api.rs` 存在」定位仓库根。文件一搬，
15 条自检探针与两处夹具检查全报「定位不到仓库根」。改成认两个路径（旧文件或新目录），
并把探针的改坏点跟到新的 `isRepoRoot(c)` 上 —— **探针自己也是代码，它改坏的位置同样会过期**。

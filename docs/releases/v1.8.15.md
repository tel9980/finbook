# FinBook v1.8.15

支持「**同一家单位既是客户又是供应商**」——比如宏源既做外发加工（你欠他钱），又拿料来加工（他欠你钱）。

## 为什么这个必须做对

小厂里这种事很常见：一家厂今天给你做外发，明天拿料来你这里加工。

系统里客户和供应商是两个档案，首页「钱在哪」会**分两行显示**：

```
欠我最多的客户              我欠最多的供应商
宏源化工   15,000.00        宏源化工   28,000.00
```

老板看到这两个数，得自己心算 15,000 − 28,000 = **我实际还欠他 13,000**。

不算这一步会出两种错：

- 两笔都付 → 多付 15,000
- 两笔都催 → 得罪供应商

## 现在怎么显示

```
欠我最多的客户                  我欠最多的供应商
宏源化工   15,000.00            宏源化工   28,000.00
  ↔ 我欠他 28,000.00               ↔ 他欠我 15,000.00
    → 净我欠他 13,000.00             → 净我欠他 13,000.00
```

黄色那一行就是净额，不用再自己算。

**不合并成一行**：两边金额和账龄都要能查（哪笔催、哪笔付是两件事）。但净额必须明示。

## 预收超过欠款也能算对

宏源预付你 50,000，你欠他 28,000：

```
供应商 宏源化工: 我欠他 28,000.00 | 他预付我 35,000.00 → 净他欠我 7,000.00
```

（预付的 50,000 先抵掉他欠你的 15,000，剩 35,000 再抵你欠他的 28,000）

## 建档时会提示

新建客户时，如果这个名字已经是你的供应商，编辑窗口顶部直接标黄：

```
↔ 这家已经是你的供应商（编码 S001），建好后他既是客户又是供应商，首页会按净额显示
```

避免你只建了一头，首页只显示一半。

## 踩到的两个坑

### 1. 净额带负号 + 文字方向 = 双重否定

第一版显示「净我欠他 -13,000.00」——负数配"我欠他"，读起来是"我欠他负一万三"，实际是我欠他一万三。

改成：金额永远是正数，方向单独一句话说清。

### 2. 预收的那一侧被过滤掉了

宏源预付我 50,000 时，客户侧是贷方余额（预收），被"只列正数"的过滤条件跳过——于是双身份匹配失效，供应商行看不到"他预付我 5 万"。

修正：匹配用的映射必须包含预收/预付那一侧，不能只从"欠我最多的客户"列表里建。

## 兼容性

- 无 SCHEMA 变更，仍 **v38**
- 不需要改任何已有档案；同名档案自动识别
- 如果你的客户和供应商名称写法不同（如「宏源化工」vs「宏源化工有限公司」），不会被识别为同一家——**建议档案名称保持完全一致**

# v1.8.22 — 列名就是接口：导出的表改完一定导得回去

## 一句话

导出的 Excel 现在**认列名不认位置** —— 你把备注拖到第一列、把用不上的列删掉，
改完照样导得回去；页面上能编辑的字段（税点、开票情况、计量单位、辅助核算维度、
数量、分户）导出表里也全都有了。

## 原来的问题

v1.8.21 立了一条规矩：导出的列头必须与导入模板逐字一致。这条规矩只对了一半 ——
它守住了字面，没守住顺序。用户拿到导出的表，第一件想做的是「把备注拖到右边
好看一点」「删掉用不上的上级编码列」。表还是那张表，列头一个字没改，但位置全变了。

按列下标取值的解析器**不会报错**，它会把名称读进备注、把编码读进上级编码，然后
提示导入成功。这比报错糟糕得多。

真出过一次错：一张「备注挪到第一列、上级编码被删掉」的表，解析器退回按位置取值
时第 4 列正好是编码，于是「上级编码 = 自己」，导进去报
`上级编码不能是自己（C001）—— 会形成环，层级汇总无法收敛`。提示看起来像档案数据
有环，其实是解析器在猜。

第二类缺口是「页面上能改、表里没有」。按「这个字段在哪个界面上能改，表里有没有」
挨个查，四张表全有漏：

| 表 | 界面上能改、表里之前没有的 |
|----|--------------------------|
| 客户/供应商 | 税点%、开票情况、信用额度、开户行、银行账号 |
| 存货 | 计量单位、备注、停用 |
| 科目 | 辅助核算维度、数量单位、币种、现金/银行标志、停用 |
| 期初 | 数量、分户（客户/供应商/存货/项目/部门/职员/银行账户） |

税点那栏尤其要命：小厂 59 个客户每个税点都不一样（13% 专票 / 3% 代开 / 不要票），
原来只能点开档案一个个改 —— 想核对一遍税点得点开 59 次；搬账套则税点全丢。

## 具体做了什么

### 1. 解析器先认列名，认不到才退回位置

`crates/findb/src/imports.rs` 新增 `HeadMap`：

- `normalize_header`：去掉空白、全角空格、`*`、`：`，英文转小写 —— 用户从别处
  粘来的表头常带 `编码*`、`名称：`；
- `row_is_header`：**整行任一格**是「编码」类词就算表头。不能只看某一列，
  因为「哪一列是编码」正是用户要改的东西；
- `HeadMap::cell(&aliases, pos)`：按别名查列名；查不到时 —— **有表头就返回空，
  没表头才退回 `pos`**。

最后这条是这次真正的修法。`HeadMap` 里那个 `has_header` 字段是必需的：
**缺一列在有表头的表里意味着「用户删了它」，不意味着「大概是这一列」。**

期初表原来靠「第 2 列是不是借/贷」判别 6 列还是 3 列布局 —— 猜布局只对没有表头的
老文件有意义。现在有表头就直接按列名取方向/期初余额/累计借方/累计贷方/数量/分户。

向后兼容：没有表头的老文件（四列 `类型,编码,名称,备注`、三列 `科目编码,方向,金额`）
行为一点不变，两条测试盯着。

### 2. 四张导出表补齐「页面上能改的字段」

新列**一律追加在末尾**，老列位置一位不动 —— 已经发出去的模板、用户手上的旧文件、
别处抄来的表格，全都还能被认出来。

- 辅助档案：老 6 列（`类型,编码,名称,备注,上级编码,状态`）+ 按档案种类给扩展列 ——
  客户/供应商 `税点%,开票情况,信用额度`；银行 `开户行,银行账号`；存货 `规格型号,计量单位`；
- 存货档案：`编码,名称,保质期天,安全库存,备注,计量单位,状态`；
- 会计科目：`编码,名称,类别,方向,备注,辅助核算维度,数量单位,币种,现金科目,银行科目,状态`
  （原来第 6 列写着「只读提示，导回时不生效」，自相矛盾，现在真的生效）；
- 期初余额：前 6 列不变 + `数量,客户编码,供应商编码,存货编码,项目编码,部门编码,职员编码,银行账户`。

停用档案现在**也导出**（带「状态=停用」）。原来不导出是有道理的（导回去会被当成
新建），但那样「导出改一遍再导回」就会把停用的客户重新变回启用 —— 录凭证时又能选到。

### 3. 空单元格是「不动」，不是「清空」

导入器对扩展属性（税点、信用额度、开户行……）的规则：空单元格 = 保留原值。
反过来做会让「导一张只有编码和名称的表来改名字」变成一次批量清零事故。
与 §4.74 里「空金额写 `write_blank` 而不是 0」是同一个道理：表里没有数，
不等于数是零。

### 4. 网页端也能看到停用档案

档案页加了「显示停用」勾选框（`include_disabled=1`）。停用是单向操作，关掉勾选框
就找不回来 —— 想恢复一个客户，得先能看见它。

## 验证

- **往返测试** `crates/finweb/tests/roundtrip.rs` 4 → **8 条**：客户税点与开票情况、
  存货单位与停用、科目辅助核算与数量单位、期初数量与分户。断言的是「导回去之后
  数据回到库里」，不是「表里有这一列」。
- **单元测试**：`findb` 398 → **402**（列头认列名所以列顺序可以换 / 没有表头的老文件
  仍按位置解析 / 期初表能带分户与数量 / 期初表列顺序换了也认得）；`finweb` lib
  24 → **25**（档案扩展列按种类不同）。
- **变异测试** 新增 6 条并逐条跑过：档案导出不带税点列 / 有表头时缺列仍按位置兜底 /
  期初导出不带数量列 / 科目导出不带辅助核算维度 / 存货导出不带计量单位 /
  期初导入不还原分户 —— 每条都必须让对应测试失败。
- 全量 `cargo test --workspace` **919 条**全绿。

## 升级提示

- 手上用 v1.8.21 导出的旧表仍然能导入（老列位置没动）。
- 想批量核对客户税点：客户页「导出 Excel」→ 改「税点%」和「开票情况」两列 →
  用「导入」导回去。开票情况填「每次都开票 / 有时开有时不开 / 从不开票」，
  空着表示不动。

# v1.8.79 —— 应收应付对账：先把对方的数录进来，对好了才落账

这一版来自一个具体问题：**「能不能按应收应付对账金额批量录入，等对好账后再修改？」**

以前只有两条路：在 Excel 里对完，再回软件手工做调整凭证（两套数，手指一抖就对不上）；
或者干脆拖到下个月。这一版把它做成一个正经流程：**对账期间账上一分钱不动**，
对好了、确认了，才由系统把差额汇总成一张草稿凭证。

顺带把"老账怎么搬进来"也写成了可照抄的步骤：期初收集表四张纸，先预检再导入。

---

## 一、新功能：期末 →「应收应付对账」

桌面版和网页版都有，同一套后端，口径不分叉。

### 三步走

1. **选一边（应收/应付）+ 期间 → 「新建这次对账」**
   名单按账面自动列好：有余额的户一个个摆上来，金额先等于账面数。
2. **把对方报来的数改上去**
   行内直接改；对方发来 Excel 就整段粘贴 `客商编码,金额[,备注]`。
   差额立刻显示：「对上了」/「差 X」。说不清的先点「标争议」，不挡别人。
3. **「确认这一批」**

### 确认时到底发生了什么

| 情况 | 结果 |
|---|---|
| 所有户都对上了 | 批次标「已确认」，**不生成任何凭证** |
| 有差额（且无争议） | 差额汇总成**一张草稿凭证**（`VoucherSource::Business`），摘要「应收对账调整（批次名）」；审核、记账由你决定 |
| 有争议的户 | 跳过，不参与差额合计 |

草稿凭证没人记账就等于没发生；点「打回重对」还会自动把草稿删掉
（已记账的要先反记账，系统会明确提示）。

### 两条保险丝

- **按账面列名单不覆盖你已经录的数**（只补缺的户）。
- **已确认的批次不许再改数**，改就得打回重对，账和表不会各说各话。

### 两张体检表

- 「账面还有 N 户没录进来」：账上有余额、这次对账单上却没有 —— 多半是漏了对。
- 「这些编码不在档案里」：录进来的客户/供应商编码还没建档，先建档再对账。

## 二、老账一次性搬进来：`docs/老账搬迁操作步骤.md`

建账期最疼的一步，现在有表可填、有闸门可拦：

1. 网页版 **期初建账 → 导入期初收集表 → 下载空模板**（四张纸：客户应收 / 供应商应付 / 账户余额 / 基本资料）
2. **先预检（不落库）**，核对借贷是否相等
3. 不平 → **整批拒绝**并报出差额（不会只写进去一半），改表重来
4. 搬完必查三处：往来期初明细合计 = 112201/220201 期初 = 资产负债表

## 三、性能

对账是"一个月做一次、但要来回改十几次"的操作，所以按"改一次、算一次"设计，
不做逐帧重算。演示账（48 张凭证、已结账）实测：

| 操作 | 耗时 |
|---|---|
| 新建批次 | 1.86 ms |
| 按账面列名单 | 6.12 ms |
| 重算账面 | 2.23 ms |
| 读明细（含汇总） | 0.12 ms |
| 列批次（含合计） | 0.09 ms |

- 桌面视图只在"动作发生后"刷新（`dirty` 标记），不随帧查询。
- 明细行内输入用「失焦才落库」，不会逐字符写数据库。
- 账面余额一次 SQL 取完（未核销分录 + 往来期初），批次合计用一条聚合查询，没有 N+1。

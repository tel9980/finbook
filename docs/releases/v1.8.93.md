# v1.8.93 加工费调价历史

## 问题

客户拿三个月前的单子来问「当时怎么按 0.15 算的」，答不上来。

单价表里一格就是一条规则，改价通常是**就地改**：原来 0.2 直接改成 0.15。改完旧值
就没了 —— 打开单价表只看得见「现在是多少」，看不见「改之前是多少、谁改的、哪天改的」。
生效日那一列也救不了：它说的是「什么时候开始按这个价算」，不是「谁改的」。

## 改法

新表 `price_change`（schema v53），一次改动一条，记时间、操作人、动作、物料 / 客户 /
口径 / 工艺档 / 生效日、改前单价、改后单价、备注。

| 动作 | 什么时候写 | 界面上怎么显示 |
|---|---|---|
| 新增 | 新建规则 | 只显示新价 |
| 改价 | 单价或最低收费变了 | `0.20 → 0.15` |
| 停用 / 启用 | 停用开关翻转 | 只显示原价 |
| 删除 | 规则被删 | 只显示删前的价 |

改备注、改名称**不记** —— 历史表是给人查价的，不是操作流水；每改一次备注留一条，
真实调价就被埋了。

## 界面

- 网页「销售 → 加工费规则」页底部「调价历史」：物料可以筛，默认最近 50 条，
  列 = 时间 / 物料·客户 / 口径 / 动作 / 单价 / 谁 / 备注。
- 桌面端同一页底部「调价历史（最近 30 条）」折叠表。
- 两处默认都折起来，不占首屏。

## 谁能看到

`Perm::PriceView`（看价的人都能看历史）。写入不需要额外权限 —— 能改价的人（`PriceEdit`）
改完自然留痕。

## 顺带的兼容

- `rule_save` / `rule_delete` 保留原签名（不记操作人），内部委托 `rule_save_by` /
  `rule_delete_by`；桌面端与既有测试不受影响。
- 新表只在 v53 迁移里建，老账套打开时自动建好，历史从「升级之后」开始记 ——
  之前的改动没有数据可补，文档里写明了。

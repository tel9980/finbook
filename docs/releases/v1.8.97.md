# v1.8.97 批量调价：客户说「今年全线涨 3%」

## 问题

一年一度的调价是最烦的一件活。二十年老客户、四十个工件、七八种口径（只 / 米 / kg / ㎡ /
工艺档 / 规格段 / 数量段），一格一格改要半天；改到一半接个电话，回来就不知道改到哪儿了。
更麻烦的是改完没有凭据 —— 客户问「我这一档今年什么时候涨的、涨了多少」，只能翻聊天记录。

## 改法

「加工费规则」页工具栏加**批量调价**：选范围 → 选方式 → 填幅度 → 定生效日 →
先「看会改哪些」→ 确认后「执行调价」。

三种方式：

| 方式 | 填什么 | 例子 |
|---|---|---|
| 按百分比 | `3` 涨 3%，`-5` 降 5% | 12.00 元/㎡ → 12.36 |
| 加减固定金额 | `-0.5` 降 5 毛 | 0.80 元/件 → 0.30 |
| 直接设定 | 调完就是这个价 | 全部定成 15.00 |

## 三条规矩

1. **只动现在正在生效的那一版。** 同一格可能存着历史版本，批量调价以「生效日早于调价日的
   最新一版」为底价 —— 把历史版本也乘一遍没有意义，还会把已经结算完的老账改了。
2. **写成新的一版价，不覆盖老价。** 调完价目表里多一条「2027-01-01 起 12.36」，老价仍在，
   调价历史里也有「谁、什么时候、从多少到多少」。
3. **同一天重跑是覆盖，不是叠加。** 手抖点两次不会变成涨 6%。

调到 0 或负数的行不落库，但在预览里点名说清是哪条、原价多少 —— 静默跳过最让人上火。

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/price-rules/adjust?customer_code=&item_code=&mode=&value=&effective_from=&memo=` | 预览 `{rows, warnings, count}`，不落库 |
| `POST /api/price-rules/adjust` | 执行，返回 `{rows, warnings, created, updated}` |

权限：预览 `price_view`，执行 `price_edit`。每条都走 `rule_save_by`，所以调价历史自动留痕。

  `批量调价跳过算成零或负数的`、`批量调价的参数得看得懂`；

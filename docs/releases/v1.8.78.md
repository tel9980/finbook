# v1.8.78 —— 利润分析表按「实际发生」算：结转不再把整月支出冲成 0

这一版只改一张表，但这张表是老板每个月真正会看的那张。
起因是一句反馈：**「小型加工厂以简单实用为主，以实际发生业务为基准，可能不是很规范」**。
按这句话重新对了一遍口径，发现原来有三处是「按教科书算的」，不是按厂里算的。

三处都修了，每处都有可复现的数字。

---

## 一、原来的问题：月末结转一次，整张表就空了

演示账 `恒亮氧化加工厂一般纳税人演示账.fbk`（2026-11，48 张凭证，已结账）实测：

| 状态 | 收入 | 支出 | 净利润 |
|---|---|---|---|
| 默认（一行科目都没挂） | 450,000.00 | 0.00 | 450,000.00 |
| 点「自动挂科目」之后 | 450,000.00 | 61,651.16 | 388,348.84 |
| **账上真实**（6001 − 成本费用） | 450,000.00 | 432,880.82 | **17,119.18** |

净利润虚增 **371,229.66**。点开一看，支出行全是 0，原因是：

支出行取的是「借方 − 贷方」**净额**。而 5101 制造费用在月末会被一张凭证全额转出
（凭证 #20「结转11月加工成本」）——`510106 房租` 借 20,000 / 贷 20,000，一进一出，
净额就是 0。凡是做过月末结转的月份，这张表都会变成「只有收入、没有支出」。

原来的排除逻辑只认 `source='carry_forward'`（结转**损益**），拦不住手工/自动转账做的
「结转**成本**」，两种结转在账里长得完全一样。

## 二、改成「实际发生」：支出 = 借方 − 贷方 + 结转转出

口径一句话：**这个月真花出去的钱，不能因为月底做了一笔结转就从表上消失。**

- 结转转出 = 该科目的贷方里、同一张凭证借方落在成本类（`5001`/`1405`/`1406`/`6401`）上的那部分
- 红字冲销（借贷都在本期）照旧自然抵销为 0，不会因为新口径而重复计
- 收入行不变（贷 − 借）

实测（演示账，挂好科目后）：

| 项 | 金额 |
|---|---|
| 表上支出（15 行合计） | 424,150.82 |
| 表外体检（账上有、表上没有） | 8,730.00 |
| **合计 = 账上真实支出** | **432,880.82** |
| 净利润 | 25,849.18（收入 450,000 − 424,150.82） |

那 8,730.00 是原表没有的四个科目：510102 折旧费 6,000 / 510105 车间其他 2,600 /
660303 手续费 100 / 660305 其他 30。老口径下它们被闷在表里看不出来。

## 三、新增「表外体检」：把差额摊在桌面上

只要账上还有费用没落到这 16 行里，表下面就直接写出来，按金额降序、最多列 6 条：

> 还有 8,730.00 元费用没落到表上任何一行（510102 折旧费 6,000.00、660303 手续费 100.00…）

- 只看末级科目，父科目不再重复计一遍（`snap.for_account` 会聚合下级，早期实现因此在父/子两级各算了一次，
  测试里表现为 6,100 被算成 12,200）
- 范围：`5101 / 5401 / 6403 / 6601 / 6602 / 6603 / 6711`
- **刻意不看 `5001` 和 `6401`**：5001 的在产品余额会和制造费用重复喊，6401 是这 16 行费用的汇总

记账的人不用懂这句话，只需要记住一个等式：**表上支出 + 表外体检 = 账上真实支出**。

## 四、「按这张表生成科目」先认现有的，不再造第二套

老实现是无条件在 `5101` 下新建同名科目。拿到一本真实账套（`小工厂/小工厂账套.fbk`，
5101 已有 15 个厂里自建的明细）跑一次：

| 做法 | 5101 末级科目数 | 后果 |
|---|---|---|
| 旧：无条件新建 | 15 → **30** | 「厂房租金」和新建的「厂租」并存，「电费」和「水电费」并存，成本被劈成两半 |
| 新：先认现有，认不出才建 | 15 → **17** | 只新建了 染料封闭剂、包装材料 两个，其余 14 行都挂到账里已有的科目上 |

判定规则照抄「自动挂科目」那一套：只认末级、一行一科目、支出行只认成本/费用类、
收入行只认收入类、名字对不上就不硬凑。两个按钮现在共用同一份匹配逻辑
（`candidates()`），不会再出现「自动挂科目挂得好、生成科目却造重复」的分裂。

## 五、产量不再摆一个假 0.00

第一行「收入：月总产量」读的是生产工单的完工数量。**没有录工单的时候，它现在是空的**，
而不是 0.00 —— 0 是「产出为零」，空是「还没录」，两件事不能混。要用产量就先去「制造管理」录工单。

顺带把「这一行是不是收入行」从「有没有产量」里摘出来，改成独立的 `is_revenue` 字段
（原来拿 `qty.is_some()` 兼职判断，产量留空之后这个兼职就断了）。

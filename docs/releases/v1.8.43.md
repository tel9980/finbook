# v1.8.43 —— 期初四张纸收不到的东西

v1.8.42 加了「导入后对账」，六项校验全绿。但用模拟数据跑一遍，发现**指标全绿、账其实是
错的**：四类期初根本没有地方可以填。

## 一、③ 账户余额少了四列

之前这张纸只有「科目编码 / 科目名称 / 余额」三列。于是：

| 收不到的东西 | 后果（都不报错） |
|---|---|
| 存货的**数量** | 期初数量为 0，第一次出库结存就成负数，数量金额式明细全错 |
| 银行科目的**账户** | 期初落不到具体账户，银行日记账从零开始 |
| **预收**（客户预交的钱） | ①② 只收正数，负数「已跳过」→ 应收虚增、预收消失 |
| **预付**（先付给供应商的钱） | 同上 → 应付虚增、预付消失 |

现在 ③ 是 7 列：`科目编码 / 科目名称 / 余额 / 数量 / 客户·供应商编码 / 存货编码 / 银行账户`，
模板的「怎么填」页也把这四条写清楚了（预收填 2203 + 客户编码、预付填 1123 + 供应商编码、
存货要填数量、银行要填账户编码）。

## 二、顺带抓出来的四个「静默错」

加列的过程中暴露了四个同类毛病，都是**不报错**的那种：

1. **导入器没跟着改**。模板加了列、解析器不认 —— 用户填了，导进去没有，也没提示。
2. **`continue` 跳不出内层循环**。校验「编码在不在档案里」写在嵌套 `for` 里，`continue`
   只跳出内层，于是既报「找不到」，又把这一行写进了库，留下一个谁也查不到的孤儿期初。
3. **合计边走边加**。轧差补的 4103 只调了一边，回显「借方 65,000 = 贷方 65,000」——
   两边都错还能对上，而库里实际 71,000。而且分借贷不能看科目首位：4103 以「4」开头，
   但它完全可能是借方（亏了），要按**符号**判。
4. **表头认成说明文字**。模板每张纸上面有标题行和说明行，原来只看「这行有没有『编码』
   『科目』『项目』」，说明里提到「科目」就被当成表头 —— 真表头变成数据第一行被跳过，
   数据改用兜底列号解析：编码和余额恰好还在原位，**多出来的列全丢**。

## 三、对账新增第 7 条：数量核算科目必须带数量

这条直接堵住上面那个最贵的后果：存货有金额没数量时，库里看着「5000 元」很对，
但第一次出库结存就是负数。现在对账会点名：

```
[!!] 数量核算科目都填了数量 —— 有金额没数量：140501(库存商品)
     —— 在 ③ 表填「数量」列；或者改用「期初库存」导入数量流水
```

## 模拟数据实测（`cargo run --release -p finweb --example chk_opening_probe`）

一份四张纸都填全的表：现金 2000 / 工行 8000（账户 B01）/ 存货 5000（数量 2.5，存货 HG001）/
应收 C001 50000 / 应付 S001 28000 / 预收 C002 8000（2203）/ 实收资本 35000。

导入后逐行核对，四条辅助维度**都进了库**：

```
100201   8000.00   银行=B01
140501   5000.00   数量 2.50   存货=HG001
2203    -8000.00   客户=C002
对账：借 71000.00 = 贷 71000.00，7 项校验全过
```

## 测试与验证

| 项 | 结果 |
|----|------|
| `cargo test --workspace` | **1005** 全绿（findb 1 条解析单测 + finweb 1 条端到端） |
| 新增端到端 | 真下载模板 → 填 ③ 的数量/存货/银行 → 导入 → 从 `/api/begin` 读回断言 qty 与 aux |
| 变异验证 | 3 条全部拦下（③ 不读数量列 / ③ 不读银行账户列 / 客商列按资产·负债方向判），下限 78→**81** |

## 怎么用

1. 网页 `期初余额` → 「下载期初收集表模板」；
2. 先看第一张「怎么填」页（预收/预付/存货/银行四条都在里面）；
3. 填完点「导入后对账」——**先看红字再导入**，预检不落库。

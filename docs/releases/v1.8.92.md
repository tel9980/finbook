# FinBook v1.8.92 — 按数量分档定价

## 一句话

同一个活儿，500 件以下一个价、以上一个价：报价时按**这一批的计价数量**自动挑档，
不用人先算一遍再判断该按哪一档。

## 原来卡在哪

小批量和大批量的价本来就不一样：500 件以下要调机、装挂具、开槽，人工摊不开；
500 件以上能连着做，单价自然低。以前的处理办法只有两个：

1. 一律用同一个价 —— 小批量接了亏人工，大批量报了丢单；
2. 建两条规则，名字里写「小批量」「大批量」，**开单时靠人挑**。

第 2 种的问题不是麻烦，是**挑错了看不出来**：单子照常打出来，金额也对得上格式，
只是这一单收少了三成。月底对账才发现，已经发了十几单。

## 改法

单价规则再加两列（schema **v52**）：数量下限、数量上限（空 = 不限）。

| 物料 | 口径 | 数量 | 单价 |
|---|---|---|---|
| MB04 | 件 | ≤ 500 | 0.35 |
| MB04 | 件 | > 500 | 0.25 |

报价：

```
300 件  → 小批量 → 300 × 0.35 = 105.00
800 件  → 大批量 → 800 × 0.25 = 200.00
正好 500 件 → 小批量（下限不含、上限含）
```

## 三个关键口径

1. **比较对象是「计价数量」，不是库存数量。** 按㎡ 报价的活儿，600 只 = 14.04 ㎡，
   没到 500 ㎡，就该走小批量价 —— 如果按只数判，600 只 > 500，一件小活儿被按大批量价
   报出去，看着便宜、实际亏在人工上。
2. **上限含、下限不含。** 「500 以下」填上限 500，「500 以上」填下限 500，两句接上，
   正好 500 件只命中一条。两头都含的话，同一批货今天按这条、明天按那条，取决于谁先建。
   这条与 v1.8.91 的规格档统一了（那边也改成下不含）。
3. **数量档不进单价矩阵，但列在「分段价」表里。** 矩阵一格装不下两条不同批量的价，
   而「分段价」面板现在一格显示成 `≤ 200 cm ・ ≤ 500 件`。

## 一个已知边界

规格档与数量档可以叠加：先按尺寸定口径、折算成计价数量，再按数量挑档。
但如果**口径留空、完全由规格定档**，那一步还没有折算后的数量可比 —— 此时数量档不参与。
要叠数量阶梯，就自己选口径（选了口径就会先折算、再定档）。

## 升级说明

- schema 从 v51 升到 **v52**，只加两列（`qty_from`、`qty_to`），老账套自动迁移，账套格式不变；
- 不分档的规则行为完全不变（两列留空 = 老样子）；
- 导入模板从 14 列变 16 列，末尾多「数量下限 / 数量上限」；老模板照样能导（按位置读）。

# FinBook v1.8.0

这一版补齐往来账里最"不规整"的一类：**两边对不上号**的核销。

1. **跨单位互抵（代收代付）**：客户 B 欠我们货款，钱却是 **A** 打过来的；或者客户 A 欠我们、我们欠供应商 B，三方约定 A 直接把钱顶给 B（**三方抵账**）。以前系统只肯"同科目、同往来单位"地核销，这类场景要么记错、要么手工补分录；现在挑好两条挂账，系统自动出一张**过渡凭证**把两边接上，一次结清。
2. **文案更正**：v1.7.0 的"往来对冲单"其实**不要求客户与供应商是同一家公司**——客户填 A、供应商填 B 就是三方抵账。上一版发布说明写窄了，这次改准。

## 这一版的变化

### 1. 跨单位互抵（代收代付 / 三方抵账）

**在哪里**：往来核销 → 「手工核销」。挑好一借一贷后，工具栏多了一个「**跨单位互抵**」勾选框（网页版是「跨单位互抵」按钮）。

**它解决什么**：普通核销要求两条分录**同科目、同往来单位**——这是为了不出错，但现实里经常对不上号：

- **代收代付**：B 的货款挂的是"应收-B"，可打钱进来的是 **A**。两边都在"应收账款"下，但往来单位不同（B vs A）。
- **三方抵账**：客户 A 欠我们 1000，我们欠供应商 B 600，三方说好 A 直接把 600 顶给 B。一个在"应收"，一个在"应付"，连科目都不同。

**怎么用**（以"A 的付款冲 B 的货款"为例，三步）：

1. 到往来核销，查询未核销，上面（借方）挑 **B 的应收**、下面（贷方）挑 **A 的收款/预收**；
2. 勾上「**跨单位互抵**」，填好金额（如 `1000`）；
3. 点「核销」——系统自动生成一张**过渡凭证**：**借 应收账款-A 1000 / 贷 应收账款-B 1000**，并把两边各自核销干净。

结果：A 名下的钱清了 B 的货款，B 的应收不再挂账；把这张过渡凭证和 A 的收款合起来看，净额就是「**借 银行 / 贷 应收账款-B**」。

**三方抵账**同样操作：借方挑 **A 的应收**、贷方挑 **B 的应付**，互抵后过渡凭证是 **借 应付账款-B / 贷 应收账款-A**（和"往来对冲单"出的凭证一样，区别是这里按**具体分录**挑，不用让系统按先进先出摊）。

**跨科目怎么看两张清单**：如果两侧科目不同（如客户应收抵供应商应付），在工具栏的「**对方科目**」里填第二个科目（如 `2202`），两张未核销清单会合并显示，才能同时挑到跨科目的两行。同科目跨单位（代收代付）时对方科目留空即可。

**几条规则**（都会当场拦下，不会悄悄记错）：

- 借方必须是**借方挂账**、贷方必须是**贷方挂账**（方向反了会提示）；
- 互抵金额不能超过任一端未核销额；
- 两条都必须是**已记账**的分录；
- 两条分录**同科目同往来单位**时，照常走普通核销，**不会**多出一张没必要的过渡凭证；
- 过渡凭证是**草稿**，需记账后才进余额（与收付款单一个规矩）；要撤销就删掉这张凭证（已记账的先反记账），两边的核销会一起退回。

### 2. 文案更正：往来对冲单不要求同一家公司

上一版发布说明里"客户与供应商需要是同一家关联方"写窄了。实际不要求——客户填 A、供应商填 B，即可做三方抵账。网页端和桌面端的说明都已改正。

## 数据与隐私

**完全离线运行，数据不上传。** 账存在你自己电脑上的 `.fbk` 文件里，不联网、不收费。

## 已知限制

- 跨单位互抵出的过渡凭证是**草稿**，需会计记账后才进余额（与收付款单一个规矩）
- 跨单位互抵**不与差异（抹零）同时使用**：需要抹零时先互抵，再对剩余部分单独做「差异核销」
- 三方抵账只按你挑的两条分录做抵销，系统**不会**替你核验三方协议、也不会自动判断 A 与 B 是否同一家
- 往来对冲单（按客户/供应商整体先进先出）与跨单位互抵（按分录精确挑）是两条并行入口，按需选用
- 打印走系统默认浏览器预览（Ctrl/Cmd+P），未对接虚拟打印驱动
- 不要把同一个 `.fbk` 放在 NFS/SMB 网络盘被多台电脑并发直开（WAL 在网络文件系统上不稳定，可能损坏账套）

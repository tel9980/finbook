# v1.8.127 — 电子发票识别导入 + 银行流水重复导入去重

## 这一版改了什么

两件都是从「参照同类开源财务软件的能力清单」里挑出来的、finbook 此前真正空缺的一环：

1. **发票识别导入**：PDF / XML / JSON / 图片（二维码）/ 纯文本，本地解析成发票草稿，人工核对后再入账。
2. **银行流水重复导入去重**：按行内容指纹判断，同一段流水导两次不再重复入账。

背景是三个财务项目的取舍调研：microFinancexd（Python）与 ky（Java8/GPL-3.0）都无法与 finbook
在代码层融合（语言不通、许可证污染、ky 全仓无 .sql 跑不起来），但它们共同点出了 finbook 的
一个真实短板 —— **外部票据和流水进入系统的这一层太薄**。这一版把这一层补齐。

## 实现要点

### 发票识别：五条通道，全程本地

`crates/findb/src/invoice_import.rs`（新模块，约 860 行）+ `POST /api/invoices/parse`。

| 文件 | 通道 | 做法 |
|------|------|------|
| `.xml` | xml | quick-xml 遍历事件，收集「纯标签名」与「父.子」两份键 |
| `.json` | json | serde_json 递归拍平，数组下标 `[i]` |
| `.pdf` | pdf | pdf-extract 抽文本层 → 文本正则；无文本层（扫描件）直接拒 |
| png/jpg/bmp/gif | image | image 解码灰度 → rqrr 找二维码 → 解税局标准载荷 |
| txt / 其它 | text | 直接跑正则 |

**四条硬规则**（每条都对应一个实际踩过的坑）：

1. **抽不出发票号码一律拒收** —— 号码是唯一业务主键，没号码的草稿进台账既不能查重也没法对账。
2. **金额三缺互补但不自愈** —— 缺「不含税」用 `价税合计−税额` 推；三者都在却对不上时**只警告不改数**。
3. **进项/销项看本企业落在哪一侧** —— 销售方含本企业名 → 销项，购买方含 → 进项。
4. **图片通道一律标记需复核** —— 二维码只编码号码/金额/日期，没有交易对手与品名。

本机不引入 OCR 引擎（tesseract/ONNX 会把单文件 exe 撑大几十 MB），图片通道只有二维码一条路，
解不出就明确报「请提供 PDF/XML 或手工录入」，不假装识别成功。

### 识别只给草稿，确认后才入账

`/api/invoices/parse` **不写库**，只回 `draft` + `warnings` + `duplicate`：

- `warnings`：金额不一致、日期没认出、销售方缺失等。
- `duplicate`：顺手按「同类型 + 同号码」查一次，已登记就把旧记录回给前端 —— 保存前就提示撞号。

前端「发票管理 → 导入发票」：选文件 → 识别 → **打开确认弹窗逐项可改** → 点保存才 `POST /api/invoices`。
识别留痕（通道/引擎/置信度/原文/双方税号/品名摘要）用模块级变量 `invoiceParseCarry` 带到保存请求，
落进 `invoice.parse_*` 列。**不自动入库**：错一张票直接进台账会参与抵扣计算，事后极难定位。

### 银行流水去重：内容指纹不含余额与勾对状态

`bank_statement` 加 `statement_hash` 列。指纹 = `sha256("科目|日期|摘要|结算号|借方|贷方")`。

刻意**不含余额与勾对状态**（余额随后续流水变、勾对随人工操作变），也**不含期间**
（跨月重叠的回单仍应被认出是同一笔）。`import_csv` 先把已有指纹读进 `HashSet`，逐行
`seen.insert` 失败即重复，计入 warns 跳过。

### schema v58 → v59

- `invoice` 加 8 列：`parse_channel` / `raw_text` / `engine` / `confidence` / `needs_review` /
  `buyer_tax_no` / `seller_tax_no` / `item_summary`。
- `bank_statement` 加 1 列：`statement_hash`。
- 全部走 `MIGRATE_V59` + `migrate_generic`；**索引不写进 DDL**（遵守既有的
  `no_ddl_index_may_reference_a_current_migration_column` 约束）。
- `Invoice` 里识别留痕收成嵌套结构 `InvoiceParse`，9 处构造点只需补 `parse: Default::default()`。

## 新增依赖

`quick-xml 0.42` / `pdf-extract 0.12` / `rqrr 0.11`（关 img feature）/ `image 0.25`（只开
png/jpeg/bmp/gif）/ `regex 1`（lock 里已有）。许可证全部在 `deny.toml` allow 列表内，无需改白名单。
`pdf-extract` 依赖的 `lopdf 0.42` 已修 `RUSTSEC-2026-0187`（无界递归栈溢出）；printpdf 仍带
lopdf 0.31，故该 advisory 的 ignore 保留。

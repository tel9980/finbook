# v1.8.49 —— 账套参数：导得出、导得回，恢复默认不撞账

参数页十六个字段（编码级长、启用期间、企业名称、税号、本位币、五个开关、六个业务默认
科目、预算控制、单据前缀、打印版式、凭证字）。以前全靠手记——换台机器要一项项比着填，
误改一处想回去只能靠回忆。

这一版给三个出口：**导出配置 / 导入配置 / 恢复默认**，桌面端和网页端都有。

## 导出：整个对象原样写出，不挑字段

少导出一个字段，导入后它就静默回到默认值，而症状是「换了机器某个设置不一样」——
没有任何报错，极难自查。所以导出的就是 `BookOptions` 本身，`serde` 序列化什么就是什么。

文件形如 `恒亮氧化_账套参数_20261029.json`。

## 导入：结构项不同就整体拒绝，一个字段都不改

`code_scheme`（科目编码级长）和 `start_period`（启用期间）**与已有科目树和期初数据绑在
一起**：改级长，存量科目就对不上上下级；改启用期间，期初就从另一期开始算。所以导入
先比这两项，不同就报错：

```
配置文件里的科目编码级长 [3, 3, 3] 与当前账套 [4, 2, 2, 2, 2] 不同——编码级长决定
科目树怎么分叉，不能被配置文件覆盖
```

**报错比静默降级好。** 如果做成「跳过这两项、其余照搬」，配置文件里明明写着 4-2-2-2-2，
导入后账套还是 4-2-2-2，用户只会以为导入整个没生效，然后开始怀疑别的设置也没进去。

## 恢复默认：只清偏好，不清身份

| 恢复 | 不动 |
|------|------|
| 打印版式（方向/字号/边距/偏移/页眉页脚/落款） | 企业名称、税号 |
| 预算控制 | 科目编码级长 |
| 单据前缀 | 启用期间 |
| 生产制造模块开关 | 业务默认科目（六个） |
|  | 审核、出纳签字开关 |

理由不是「改起来麻烦」，而是后四项**与已经记过的账绑在一起**：改了默认科目，自动生成
的凭证会记到别处（甚至记到不存在的科目）；关了审核开关，等于用一个按钮把内控默默关掉。
用户点的是「恢复默认」，不是「重开一套账」。

## 怎么用

**网页**：`系统设置` → 底部三个按钮 —— 导出配置 / 导入配置 / 恢复默认。

**桌面版**：`账套参数` → 工具栏右侧 —— 导出配置 / 导入配置 / 恢复默认。

换机器的流程：旧机器「导出配置」→ 拷到新机器 → 新建同名账套（先建好科目表）→
「导入配置」。若两边科目编码级长不同，导入会被拒绝并说明，这是**有意的**。

## 一个诚实的说明

恢复默认**不管**存档里的历史配置——没有「配置版本历史」。真要追查「上周谁把预算控制关了」，
现在只能翻审计日志里 `修改账套参数` 那几条。做配置版本化要动 meta 表结构，这一版没做。

# FinBook v1.8.3

这一版分两块：**修掉 v1.8.2 的明细账回归**（点查询后整张表消失），并让**利润表「全是 0」这件事能被看懂**。记账口径、报表取数公式一行未动。

## 这一版的变化

### 1. 利润表全零时，直接告诉你为什么

以前利润表里每一行都是 `0.00`，页面没有任何解释：可能是本期没业务，也可能是凭证还没记账，还可能期间/账套选错了，用户只能猜。

现在只要整张表**全零**，表格上方会出现一条明确提示：

> **本期各项目都是 0.00**：该期间没有已记账的损益发生额。利润表只统计已记账凭证（草稿 / 已审核未记账都不算），并剔除系统生成的结转损益凭证。请先确认左上角账套与期间，再到「凭证」查看本期 6xxx 损益科目是否已记账。

有任何一个非零金额时，这条提示不会出现，不干扰正常看表。

### 2. 三大报表回显「服务端实际取数期间」

资产负债表、利润表、现金流量表的标题行下方，现在都会多一句：

```
（服务端取数：2026-11 ~ 2026-11）
```

它显示的是**后端真正用来查数的期间**，不是输入框里你填的字。如果这两者对不上（比如输入框被清空、手输格式不对），一眼就能看出来，不用再怀疑「是不是报表没取到数」。

### 3. 打印预览的零值显示 `0.00`，不再留空

打印/打印预览页原来按「财务惯例」把普通行的 0 打成空白，结果整列金额看起来像丢了，用户据此报障。现在打印页与网页、接口口径统一，零值一律显示 `0.00`。

> 记账口径不变：只是显示方式统一，打印出来的数字与屏幕上完全一致。

### 4. 修复：明细账查询后整张表消失（v1.8.2 引入的回归）

v1.8.2 给明细账加了虚拟滚动（大数据量不卡），但容器替换的顺序写反了：先把表格搬进新容器、再让新容器替换表格，此时表格已经不在原位置，浏览器抛出 `NotFoundError`，**查询中断、整张表明细从页面消失**。

v1.8.3 修复了这个顺序，并顺带修掉三个同源问题：

- 连续查询会一层层嵌套滚动容器（现在只建一次、复用）
- 切换总账/日记账后旧的可视区高度残留（现在切页时拆掉容器，恢复正常渲染）
- 「打印预览」取错了元素（`#l-table` 本身就是表格，再找它的子表格拿到的是 `null`），且虚拟滚动下只会打印屏幕上的十几行 —— 现在按全量数据重拼后再打印

> 如果你在 v1.8.2 里点「查询」发现明细账空白，不是没数据，就是这个原因。

### 5. 新增 3 项回归测试

针对打印页补了单元测试，锁住三件事：普通行零值必须印 `0.00`、负数必须保留红字、两列表头不能被拼坏。全仓测试由 842 项增至 **845 项**。

## 利润表自查小抄

看到金额不对时，按这个顺序看：

1. **账套**——左上角是不是你要查的那家？
2. **期间**——标题下方的「服务端取数」是不是你想要的月份？
3. **凭证状态**——利润表只认 `已记账`；草稿、已审核未记账都不进表。
4. **科目**——只有 6xxx 损益科目进利润表；只记银行/应付这类科目，表里当然是 0。
5. **结转**——系统生成的结转损益凭证会被自动剔除；如果你手工做了一张「结转损益」凭证，它不会被识别为结转凭证，会把损益科目冲平，看起来就是全 0。这种情况把那张手工凭证删掉或改由「期末处理 → 结转损益」生成即可。

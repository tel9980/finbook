# FinBook Web 多租户套帐架构（已实现）

> 一句话模型：**平台管理员只管账号、看全部账套，不建账套；普通用户自己建账套、自己是账套的主人；账套与账套之间完全隔离；账套内部引擎一行未改。**

对应代码：`crates/finweb/src/{realm,state,handlers,dto}.rs` + `static/app.js`；集成测试 `tests/api.rs`。

---

## 1. 角色与权限

| 角色 | 身份来源 | 能做什么 |
|---|---|---|
| **平台管理员** | 启动时引导创建（`FINBOOK_ADMIN_USER` / `FINBOOK_ADMIN_PASS`，不设口令则自动生成 16 位强口令并打印一次） | 开通/停用/删除平台账号、重置口令、重置设备绑定、查看并进入**所有**用户的账套 |
| **普通用户（owner）** | 平台管理员在「平台账号」页开通 | 登录后**自建任意多个账套**，自己是每套账的管理员，可邀请已有平台账号的用户进入账套（会计/出纳/审核…） |
| **账套成员** | owner 在账套内「用户管理」开通（要求同名平台账号已存在） | 平台登录后可进入被邀请的账套，按账套内角色（Accountant 等）工作 |

要点：
- 管理员**不需要**建账套，也不归属任何账套；进入他人账套时使用**临时身份**（内存构造的账套管理员，**不写入**该账套 `user` 表，不留痕迹），仅用于查看与纠错。
- 普通用户可建**多个**账套，账套之间数据完全隔离（独立 `.fbk` 文件、独立科目/凭证/用户表）。
- 账套成员协作：owner 账套内开通的用户名若已有同名平台账号，该成员即可登录 Web 并进入该账套；审批流等多角色协作恢复可用。
- 成员管控即时生效：owner 可随时停用（立即踢掉其全部会话）或移除成员；归属者本人的账套内身份不可被停用/降权/改名，防止账套失去主人。

## 2. 数据模型

### realm.db（平台身份库，SQLite，WAL）

```
realm_user(id, username UNIQUE, display_name, password_hash, is_admin, disabled, must_change_pwd, device_id, created_at)
realm_book(id, key UNIQUE, path, owner_username, company, created_at)
```

- `realm_user`：能登录 Web 的"平台账号"，与任何账套无关。`device_id` 为平台层「一人一机」的设备绑定（旧库自动 `ALTER TABLE` 迁移补列）。
- `realm_book`：账套目录。`owner_username` 决定可见性（管理员=全部，普通=本人与被邀请成员）。

### 账套文件（`.fbk`，完全不变）

账套内部仍是自己的 `user` 表（Admin/Supervisor/Accountant/…角色 + 权限 + 数据范围 + 设备绑定）。

## 3. 身份对账（关键设计：引擎零改动）

进入账套时（`CurrentUser` 提取器，三步）：

1. **平台校验**：`realm_user` 存在且未停用；
2. **账套授权**（三选一，否则 403）：平台管理员 / 账套归属者 / 账套 `user` 表已存在该用户行（被邀请成员）。入口 `POST /api/books/:key/select` 用同一套规则；
3. **身份对账**（分三种情况）：
   - 账套内已有该用户行 → 直接采用（成员/归属者的角色、权限、数据范围照常生效）；
   - 没有行且是**归属者** → 自动种子一行 Admin（口令哈希复用平台侧），保证 owner 永远进得了自己的账；
   - 没有行且是**平台管理员**（查看他人账套）→ 构造**临时身份**（内存中的账套 Admin，不落库），操作仍以管理员用户名记入审计日志。

这样 2000+ 行账套业务代码（凭证、报表、库存、采购销售…）完全无需感知多租户。每套账的公司名随账套走（`CurrentUser.company`），打印/导出/PDF 自动带本套公司名。

## 4. 登录与鉴权流（两段式）

```
POST /api/login                    平台登录（不选账套），返回平台身份 + 可见账套列表
GET  /api/books                    账套列表（管理员=全部，普通=本人）+ 平台身份摘要
POST /api/books                    自建账套（key 可留空自动生成 "用户名_YYYYMM[_n]"）
POST /api/books/:key/select        选择当前账套（授权校验 + 会话绑定）
DELETE /api/books/:key             删除账套（平台管理员 或 归属者）
GET  /api/me                       账套内身份（PublicUser，含 perms）
```

删除账套的顺序要点：先摘运行期注册（否则后续请求会把已删文件重新打开成空库）→ 清空停留在该账套的会话 → 删目录记录 → 落盘删文件（含 WAL/SHM 残留）。没有它就会形成死锁：有账套的用户删不掉账号，却又无处删账套。

会话与设备策略：
- 平台层「**一人一机**」：普通账号首次登录绑定 `device_id`，换设备登录被 403 拒绝（提示联系管理员重置）；管理员豁免，可多端并存。重置后旧会话全部失效。
- 平台层一人**一会话**：普通账号每次成功登录踢掉旧会话。
- 强制改密用户仅放行 `/api/change-password`、`/api/logout`、`/api/login`（不删会话，改完即恢复）。

设备绑定是平台级约束：同一账号在任何账套内都受同一设备绑定管束，与单个账套内的 `user.device_id` 互不干扰（后者仍由桌面端 finui 使用）。

## 5. 平台账号管理 API（仅平台管理员）

```
GET    /api/platform/users                      列表（含 device_bound 设备绑定状态）
POST   /api/platform/users                      开通（首登强制改密）
PUT    /api/platform/users/:username            展示名/停用/升降管理员（防删最后一个管理员）
DELETE /api/platform/users/:username            删除（不能删自己；仍有账套归属时拒绝）
POST   /api/platform/users/:username/reset-password   重置口令（并同步其账套内同名用户哈希）
POST   /api/platform/users/:username/reset-device     重置设备绑定（踢掉该用户全部会话，之后可在新设备登录）
```

口令同步：用户改平台口令 / 管理员重置口令后，自动把新哈希同步到其名下账套内的同名用户行。

## 6. 前端流程（app.js）

```
登录页 → 账套选择页（列表卡片 + 「新建账套」）→ 进入账套（主应用）
                    ↑ 切换账套（顶栏按钮）──────────────┘
```

- 侧边栏新增「平台管理」组（仅平台管理员可见）：**平台账号**、**全部账套**。
- 会话区分两层身份：`session.platformAdmin`（平台层）与 `session.user.is_admin`（账套内）。
- 会话恢复（boot）：`/me` 成功→直接进应用；失败但 `/books` 成功→停在账套选择页；都失败→登录页。

## 7. 部署环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `FINBOOK_LISTEN` | `127.0.0.1:8080` | 监听地址 |
| `FINBOOK_REALM` | `./data/realm.db` | 平台身份库路径 |
| `FINBOOK_BOOKS_DIR` | `./data/books` | 自建账套存放目录 |
| `FINBOOK_ADMIN_USER` | `admin` | 引导管理员用户名 |
| `FINBOOK_ADMIN_PASS` | 自动生成 | 引导管理员口令（自动生成时启动日志打印一次） |
| `FINBOOK_ADMIN_MUST_CHANGE` | `false` | 引导管理员是否首登强制改密 |
| `FINWEB_STATIC_DIR` | exe 同级 `static/` | 前端静态资源目录 |
| `FINWEB_SECURE_COOKIE` | 关 | 生产 HTTPS 下开启 Secure Cookie |

## 8. 已知行为变化与限制

1. **设备绑定在平台层生效（本次修复）**：Web 登录绑定 `realm_user.device_id`，普通账号换设备登录被 403 拒绝，管理员可在「平台账号」页**重置设备**（同时踢掉旧会话）；管理员账号豁免、可多端。账套内 `user.device_id` 仍只服务桌面端 finui，与平台绑定互不干扰。
2. **账套成员可登录 Web（本次恢复）**：owner 在账套内开通的用户名若已有同名平台账号，该成员即可登录并进入该账套协作；若平台账号不存在，「用户管理」会直接拒绝创建（避免产生无法登录的死账号），前端会提示先找平台管理员开通。
3. **管理员进入他人账套不留痕迹（本次修复）**：平台管理员查看他人账套时使用临时身份（不写入该账套 `user` 表），账套 owner 的「用户管理」列表保持干净；所有操作仍以管理员用户名记入账套审计日志。owner 的账套内账号行若被误删，下次进入会自动重新种子。
4. **重置口令不解封账号**：`reset-password` 只改口令、清强制改密标志，不会把 `disabled` 置回 false，需管理员另行编辑账号取消停用。
5. **最后一名管理员受保护**：删除平台账号时若目标是管理员且全平台仅剩这一个管理员，拒绝删除（`update` 降权亦有同样保护）。

## 9. 兼容与迁移

- 旧单账套 `FINBOOK_DB` 不再作为主配置；如设置 `FINBOOK_DIR`，其中的 `.fbk` 仍会注册进运行期账套表（便于读取旧数据），但归属以 `realm_book` 为准。
- 全新部署即"全新开始"口径：不迁移旧管理员账套，需要时手动将旧 `.fbk` 放入 `FINBOOK_BOOKS_DIR` 并向 `realm_book` 插入一条归属记录。

# FinBook 财务管理系统 — 使用说明

> 金蝶 / 用友风格的桌面财务软件，单文件账套，Rust 编写。
>
> 当前版本覆盖：核心闭环（账套 → 科目 → 期初 → 凭证 → 账簿 → 报表 → 期末结账）+ **期末四件套**（固定资产 / 银行对账 / 往来核销 / 月度自动化）+ **业务三件套**（存货 / 工资个税 / 费用报销）+ **管理会计三件套**（预算 / 多维损益 / 自定义报表）+ **资金管理**（票据 / 融资 / 资金日报 / 资金预测）+ **成本核算**（计价方式配置 / 期末结价）+ **供应链全生命周期**（采购 / 销售 / 库存深度）+ **生产制造**（MRP / 工艺路线 / 工序报工）+ **安全中心**（口令策略 / 账户锁定 / 会话超时 / 登录审计）+ **出纳作业台**（出纳日记账与日清、现金盘点、支票簿、员工借支、票据融资台账联动凭证、按日资金日报、资金预算）+ 凭证模板 / 常用摘要 / 电子附件。

## 1. 安装与启动

| 平台 | 文件 | 大小 | 依赖 |
|------|------|------|------|
| Windows 10/11 x64 | `target/x86_64-pc-windows-gnu/release/finbook.exe` | ~12 MB | 无（标准 Windows DLL） |
| Linux x64 | `target/release/finbook` | ~17 MB | xkbcommon, fontconfig（系统已带） |
| macOS | `cargo build --release` | — | — |

> **发布包内容**（GitHub Release 的 zip / tar.gz 里现在有三个文件）：
>
> | 文件 | 作用 |
> |------|------|
> | `finbook.exe` / `finbook` | 主程序，双击即用 |
> | `新手使用说明.txt` | 面向零基础用户的大白话说明（4 步走通） |
> | `示例账套.fbk` | 一家小商贸公司 2026-01 的完整账（9 张已记账凭证），**先打开它看效果**，再新建自己的空白账套 |
>
> 示例账套登录：`admin` / `admin123`。

启动方式：

```bash
# 不带参数：进入"请选择账套"页
./finbook

# 带账套路径：直接打开该账套（仍需在登录页输入用户名密码）
./finbook /path/to/company.fbk
```

> 账套就是一个 `.fbk` 文件（标准 SQLite 库），备份只需复制该文件。

### 1.1 在服务器上多用户共享同一账套

`.fbk` 是标准 SQLite 文件，**可直接复用已有服务器上的账套**，无需迁移数据。

- 启动时已启用 `journal_mode = WAL` + `busy_timeout = 5s` + `synchronous = NORMAL`，
  因此**同一台服务器上多个进程 / 多个登录用户可同时打开同一个 `.fbk`**，
  并发写入会自动等待而不会报 `database is locked`。
- 典型部署：把 `.fbk` 放在财务服务器的**本地磁盘**上，各会计人员通过远程桌面 / 终端服务
  在同一台服务器上各自启动 FinBook 登录同一账套；或在同一台机器上多开实例。
- 推荐做法：让 FinBook **运行在账套所在的服务器本机**。若把 `.fbk` 放在 NFS / SMB 网络
  共享盘上再被多台不同电脑同时打开，SQLite 的 WAL 模式在网络文件系统上不稳定，
  可能损坏账套——此时应改用"服务器本机运行 + 远程桌面"模式。
- 升级不破坏旧账套：旧版本账套打开时自动执行 schema 迁移（含账号设备绑定字段），
  原有用户、凭证、余额全部保留。

以下用「示例科技有限公司，启用期间 2025-01」走通从建账到期末结账的完整业务。

![01_login](screenshots/01_login.png)

> **普通账号由管理员开通**：管理员在「系统 → 用户权限」新增账号后，该账号才能登录（详见 §6）。

## 3. 期末四件套（期末处理扩展）

### 3.1 固定资产（期末 → 固定资产）

四个页签：**资产卡片 / 计提折旧 / 折旧明细 / 资产台账**。

- **新增卡片**：编码、名称、类别、原值、残值率（0~1）、预计月数、启用期间、使用部门（辅助核算）、折旧科目映射
- **计提折旧**：选定期间一键计提全部在用资产，自动生成「借：管理费用—折旧 / 贷：累计折旧」凭证（`VoucherSource::AutoTransfer`）；已计提期间自动跳过，不重复计提
- **台账**：原值 / 累计折旧 / 净值实时滚算；支持清理（生成处置凭证）

### 3.2 银行对账（期末 → 银行对账）

三个页签：**对账单录入 / 自动勾对 / 余额调节表**。

1. 录入银行对账单（日期 / 摘要 / 收 / 付 / 余额）
2. **自动勾对**：按金额 + 方向 + 结算方式智能匹配企业日记账与银行对账单
3. 未达账项手工调整，**余额调节表**一键生成：企业账面余额 ± 未达 = 银行对账单余额 ± 未达

### 3.3 往来核销（期末 → 往来核销）

- 三个页签：**手工核销 / 自动核销 / 账龄分析**
- 应收（1122）/ 应付（2202）按客户/供应商逐笔核销，核销凭证自动生成
- **账龄分析**：30/60/90/180/180+ 天五段账龄，按辅助对象汇总

### 3.4 月度自动化（期末 → 自动化）

四个页签：**调汇 / 自动转账 / 检查清单 / 一键月末**。

| 页签 | 功能 |
|------|------|
| 调汇 | 期末按记账汇率重估外币货币资金/往来，汇兑损益凭证自动生成（`VoucherSource::FxAdjust`） |
| 自动转账 | 定义模板：结转成本、摊销费用、计提税金等，按公式（固定额 / 期末余额×比例 / 取对方科目发生额）+ 执行频率（每月/季/年）一键生成凭证 |
| 检查清单 | 结账前自动体检：损益未结转、草稿/待审凭证、借贷不平历史、未核销往来、未计提折旧、未对账银行等 |
| 一键月末 | 按「检查 → 计提折旧 → 调汇 → 执行自动转账 → 结转损益 → 记账 → 结账」顺序串行执行，逐步日志反馈 |

## 4. 业务三件套 + 管理会计三件套

### 4.1 存货核算（业务 → 存货）

- **出入库单**：采购入库 / 销售出库 / 其他出入库；出库行数量为负，成本由引擎计算
- **存货盘点**：盘点单按仓库**快照账面** → 录实盘 → 应用生成 其他入库/其他出库 流水 + **盘盈盘亏凭证**（借/贷 1901 待处理财产损溢，金额 = 差异 × 标准价；未配标准价只调流水）；草稿可删、已应用不可删（冲回做反向盘点），仓储作业权限（仓管员专属）
- **批次与库位**：存货档案配「保质期天数」→ 批号自动生成 `BT+日期+序号`（或手工指定）；**批次余额 = 库存流水按 (存货,批号) 汇总——与普通库存同一本账**；批次登记（其他入库/出库带批号、仓库、初始库位）；**FEFO 近效期先出推荐**（无效期批次按生产日期）；**临期预警**（默认30天窗口）；库位主数据（存储/拣货/隔离）；仓储作业权限
- **收发存汇总**：期初 / 本期入库 / 本期出库 / 期末，按存货 + 仓库汇总
- **成本核算**：**移动加权平均 / FIFO** 两种计价引擎，结转销售成本一键生成凭证

### 4.2 工资与个税（业务 → 工资）

- **工资表**：按部门/职员录入应发、三险一金、专项附加扣除
- **个税计算**：累计预扣法（计税基数 = 应发 − 三险一金 − 专项附加 − 5000×月数，首月 3% 起档），自动算出本期应扣个税
- **凭证生成**：计提工资 / 发放 / 扣个税 / 扣社保四组分录一键生成

### 4.3 费用报销（业务 → 报销）

- 状态机：**提交 → 审批 → 付款 → 完结**（可驳回），全程留痕（申请人 / 审批人 / 付款人）
- 审批通过后自动生成报销凭证（借：管理费用等 / 贷：其他应收款或银行）

### 4.4 安全中心（系统 → 用户权限）

| 页签 | 功能 |
|------|------|
| 用户管理 | 管理员**新增 / 停用 / 改密 / 重置绑定设备**普通账号，设定角色与细粒度权限；**强制改密**横幅（口令过期提示） |
| 我的口令 | 任意登录用户可在此**修改自己的口令**（验证旧口令 + 策略校验），被强制改密的用户在此完成首次改密 |
| 口令策略 | 最小长度、复杂度（字母+数字）、有效期天数、**连续错 N 次锁定 M 分钟**、会话空闲超时分钟 |
| 登录审计 | 每次登录 / 失败 / 锁定 / 超时登出全部留痕，可按用户/时间筛选 |
| 数据范围 | 按用户配置可见辅助对象（部份/全部），界面灰字提示逐步接入各账簿 |

> **默认口令策略**：≥8 位且含字母+数字、有效期 90 天、错 5 次锁 15 分钟、闲置 30 分钟自动登出。
> **默认管理员**：账套内只有 `admin` 一个内置账号（默认口令 `admin123`，首次登录强制改密）；其余账号由管理员在「用户管理」开通。

### 4.5 账号设备绑定（一人一设备）

为防止同一账号在多处同时登录，FinBook 在每次登录时采集**设备指纹**并绑定账号：

- **首次登录自动绑定**当前设备；之后**换设备登录会被拒绝**（提示"该账号已绑定设备 XXX"）。
- **管理员不受此限制**，可在任意设备登录，也不绑定设备。
- 员工换电脑时，由**管理员在「用户管理」点击「重置绑定」**解除原绑定，该账号即可在新设备重新登录。
- 设备指纹来源：Windows 读 `MachineGuid`、Linux 读 `/etc/machine-id`、macOS 读 `IOPlatformUUID`，
  兜底用「主机名 + 用户名」哈希；绑定的设备名显示在用户列表「绑定设备」列，方便管理员辨认。

### 4.6 导出管控（普通账户只能打印，不能导出）

报表与账簿的"导出 Excel / 导出 CSV"按钮**需要 `Export` 权限**，仅**系统管理员与财务主管**拥有：

- **普通账户（会计 / 出纳 / 审计 / 只读）看不到"导出"按钮**，界面显示灰字提示"无导出权限，仅可打印预览"。
- 所有能看报表的账号都有**「打印预览」按钮**：把数据生成一份带打印样式的 HTML，用系统默认浏览器打开并自动弹出打印对话框。
  打印走的是 HTML，**不会以文件形式落地**，满足"只能打印、不能把整表数据带出"的管控。
- 凭证的 Excel 导出同样仅管理员 / 财务主管可用；屏幕内的凭证打印预览人人可看。

### 4.7 管理会计三件套

| 模块 | 说明 |
|------|------|
| **预算**（管理会计 → 预算） | 按科目 + 期间编制预算额；执行分析：实际发生 vs 预算、执行率、超支标红 |
| **多维损益**（管理会计 → 多维损益） | 按部门 / 项目 / 客户任意维度切分收入成本费用，输出多口径利润表 |
| **自定义报表**（管理会计 → 自定义报表） | 报表设计器：行 = 取数公式（科目余额 / 发生额 / 辅助明细），保存后一键刷新预览、导出 |

### 4.8 凭证模板 + 常用摘要（凭证 → 模板）

- **凭证模板**：把常做的分录组合存成模板（含借贷方向、金额公式、辅助核算），到期（月/季/年）提醒，一键生成草稿凭证

### 4.9 出纳作业台（出纳 → 资金管理）

出纳岗位的完整闭环（出纳角色默认 `填制凭证 + 出纳签字 + 账簿报表` 即可上岗，记账/审核仍归会计）：

| 能力 | 说明 |
|------|------|
| **出纳日记账** | 资金管理 → 日记账：现金/银行科目逐笔（仅已记账 H-3）+ 滚动余额；**日清标记**按科目按日核对封账；**收款/付款登记**一键跳转凭证录入并预填科目 |
| **现金盘点** | 账面按当日资金日报口径快照 → 实盘录入 → 差异一键生成盘盈盘亏凭证（对方科目 1901 待处理财产损溢）；账实相符记录可直接删除 |
| **支票登记簿** | 票号/类型/付款科目/收款人/金额，开出 ↔ 作废流转；纯备查簿不入账，删除无凭证联动 |
| **员工借支** | 建单 → 支付（借 其他应收款-员工 / 贷 资金，同事务出凭证）→ 核销（冲账费用 + 退回现金 / 贷 其他应收款），超额与状态机守卫、幂等 |
| **票据 / 融资台账** | 贴现、背书、兑付、融资到账与结清**同事务自动生成台账凭证**（存量台账可「生成凭证」回填），资金台账与总账不再脱节 |
| **资金日报（按日）** | 上日结余 / 本日收支 / 日末结存，按日翻页（仅已记账） |
| **资金预算** | 现金/银行科目的预算 vs 已记账实际执行（预算行在预算管理维护） |
| **出纳签字** | 账套参数开启后，涉现金/银行的凭证记账前必须出纳签字（凭证弹窗按钮 + 账套参数开关），日记账带签字列 |
| **报销支付落账** | 报销单支付即自动生成付款凭证草稿（默认贷 100201），手动「生成凭证」幂等返回同一张 |
| **收付款单** | 资金管理 → 收付款（Web + 桌面）：保存即出凭证并按往来单位对未清挂账 **FIFO 自动核销**（见 §4.10） |

### 4.10 供应链全流程（对标金蝶：订单 → 出入库 → 收付款 → 会计记账）

从「创建订单」到「出纳收付」再到「会计记账」的完整链路，关键节点**同事务自动生成凭证**：

| 环节 | 动作与卡控 | 自动生成凭证 |
|------|-----------|--------------|
| **订单创建** | 销售/采购单据页「新建订单」：明细行编辑器，行金额=数量×单价、税额=金额×税率（服务端计算），草稿自由改删 | — |
| **订单确认** | 草稿 → 已确认（可作废）；**客户信用控制**：客户档案「信用额度」（0=不限），确认时校验「已确认订单占用（总额−已收款）」≤ 额度，超限拒绝；草稿不占额度 | — |
| **发货执行** | 已确认才能发货/退货（草稿/作废拦截）；**按比例确认收入**：收入与税额 × 本次数量÷订购总量（发货封顶未发量、退货封顶已发量不超额冲回）；订单状态随发货进度自动推进 部分发货/已完成 | **借 应收账款(客户辅助) / 贷 主营收入 / 贷 销项税**；退货出反向冲回 |
| **入库暂估** | 采购到货登记执行进度；入库未票在「采购暂估」登记（须挂真实订单）→ 同事务出凭证；到票「冲回」出反向凭证（UPDATE 条件化幂等，重复/并发冲回不出票） | **借 存货材料科目 / 贷 应付账款(订单供应商辅助)**；冲回反向 |
| **收付款** | 收付款单：选类型/资金账户/往来单位/金额 → **保存为草稿（仅台账）→ 审核时**同事务出凭证 + 对该往来单位**未清挂账按日期 FIFO 自动核销**（超出留预收/预付腿，无挂账全额预收）；审核权 = 审核人/主管（出纳录单、审核人把关），撤审删凭证回草稿；执行坞「收款/付款」落待审核单，审核后出凭证 | **收款：借 资金 / 贷 应收；付款：借 应付 / 贷 资金** |
| **核销账龄** | 自动核销进往来核销（手工/自动/账龄同口径）；**删除凭证自动清理其核销配对**，收付款单须先删凭证才可删单 | — |
| **会计记账** | 以上均为**草稿凭证**（H-3 草稿不入余额），会计审核记账后进余额与报表；涉现金银行凭证按出纳签字开关（§4.9）把关 | — |

生成科目集中在**账套参数 → 业务凭证默认科目**：应收 / 应付 / 收入 / 销项税 / 暂估材料 / 默认资金账户（须为末级科目，Web 与桌面两端可改）。

暂不覆盖（业务边界）：信用催收与账龄预警、税务发票对接、单据→凭证**可配置规则引擎**（当前为固定生成器 + 科目可配）。

### 4.11 单据套打（订单 / 收付款单）与批量打印

- **覆盖范围**：销售订单、采购订单、收付款单（Web 三处列表勾选批量 + 打印设置；桌面收付款页签「打印全部」走同一模板）、出纳日记账「打印日记账」；凭证套打（整期间批量）、账簿套打、报表打印沿用既有通道；

### 4.17 库存作业深化（到货入库闭环 / 质检 / 形态转换 / 低库存预警）

- **到货即入库（采购链闭环）**：Web 采购到货此前**只做执行跟踪、不写库存流水**（`kind=purchase` 仅桌面手工单产生）——现 `po_receipt_with_stock` 同事务「执行行 + 采购入库流水」，价格=订单行单价、金额=qty×价——**这也是「最近采购价」（领料成本回退链）的真实数据源**；防呆：订单无行拒、**单价 0 拒**（0 价入库污染移动平均，下推后先补价）；退货 `po_return_with_stock` 同事务负流水 + **超退防呆**（本次 ≤ 累计净收货）；多行订单按首行品/价入库。
- **质检单（对标金蝶来料检验）**：`qc_order` 表 + 采购订单行「质检」按钮（Warehouse 权限）——合格留库，**不合格部分自动按订单单价退货**（负到货 + 负采购入库同事务），结论 pass/fail/partial 随不合格数推导；防呆：不合格 ≤ 检验数、不合格退货价 0 拒、超退拒。
- **形态转换单**：`form_convert` 源物料出库 → 目标物料入库（同数量一减一增，**金额按源存货移动加权成本平移**——等值转换，源无成本价拒绝；原数量口径会给目标存货留 0 价首入污染计价，已修）；组装拆卸页新增「形态转换」工具条；同物料/非正数拒绝；无总账凭证（存货内部结构调整）。
- **低库存预警**：`below_safety`（`item_plan` 安全库存 > 0 且现有库存 < 安全量）→ `GET /api/inventory/below-safety` + **工作台仓管域新卡片「低于安全库存」与待办**（点击直达仓库库存页）。
- **测试**：web `inventory_qc_convert_flow`（到货 +20 → 质检不合格 5 自动退货 → 15 → 超退 400 → 转换 5/10 → 同物料 400 → 端点 200）+ `doc_push_chain` 增补 0 价防呆与补价序列；README §9 质检条目同步收窄。

### 4.18 最近价带出与按单限额领料（采购/生产深度）

- **价格历史自动沉淀**：保存采购订单时正价行按 (存货, 供应商, 日期) upsert 进 `price_history`（既有表此前**无生产写入方**，本波接通）。

### 4.33 Web 平台安全中心（口令策略可配 + 登录审计 + 持久锁定）

- **背景**：Web 登录是**平台层**（认账号库 realm）——此前口令策略硬编码默认值（不可配）、登录只走内存限流（重启即忘、不留审计），与桌面端账套级策略/锁定语义不一致。
- **策略可配**：`GET/POST /api/security/policy`（仅平台管理员；值域校验：长度 1-64、失败次数 1-20、锁定时长 1-1440 分、空闲登出 0-1440 分、有效期 0-3650 天）→ 存 realm `realm_option`；**改密校验 / 空闲登出 / 登录锁定统一走该策略**（`WebState::policy()`，读取失败回退默认，不因策略库异常阻断登录）。
- **登录审计**：realm 新表 `realm_login_attempt`（只留最近 500 条）+ `GET /api/security/login-attempts?username=&limit=`；成功登录亦留一条（先 `unlock` 清失败再记成功，成功记录不被清理）。
- **持久锁定**：`realm_user.locked_until`（老库启动自动补列）+ `GET /api/security/locked-users` + `POST /api/security/unlock`——连续失败达策略阈值写锁，**跨进程/重启生效**；锁定期间口令正确也 429（不再做昂贵 argon2 校验）；解锁同时清空失败计数。
- **UI**：「系统 → 安全中心」新增两块（仅平台管理员可见）——**口令策略表单** + **平台登录审计**（锁定账号 🔒 红标 + 一键解锁）；账号管理/账套成员锁定解锁保持原样。
- **测试**：web `web_security_center`——默认策略 → 保存 max_fail=3 → 非法值 400 → 3 次错锁定 → 正确口令也 429 → 审计含失败记录 → 锁定名单可见 → 解锁后登录成功 + 审计含成功记录 → 非管理员 403 → 解锁陌生账号 404。

### 4.54 桌面端精简模式（侧栏只留日常财务的 12 项）

面向个人/小微记账人：完整侧栏有 **56 项**，其中生产制造、供应链、成本、预算、多维损益等重模块与日常记账无关，把菜单撑得很长、新手一眼望不到该点哪里。

- **开关位置**：侧栏底部「精简模式」勾选框（不在深层设置里——这是个高频微调的界面偏好，藏起来等于没有）。
- **勾上后侧栏只剩 12 项**：工作台 / 填制凭证 / 凭证查询 / 账簿查询 / 科目余额表 / 会计报表 / 期末处理 / 银行对账 / 往来核销 / 会计科目 / 期初建账 / 备份恢复 —— 覆盖建账 → 录凭证 → 查账 → 出表 → 月末结账 → 备份的完整链路。
- **不是删功能**：被过滤的项一项没少，取消勾选立刻全部回到侧栏。
- **临时看全部**：顶栏只有「填制凭证/凭证查询」两个快捷入口，勾上精简模式后其余页面在侧栏就没有入口了。所以底部另给「临时看全部功能…」——只展开当前这一屏、不改开关本身，旁边变成「← 回到精简模式」。
- **停在隐藏页时的兜底**：勾选瞬间若当前正停在被藏起来的页面，该页继续显示但侧栏没有高亮项（看着像界面坏了），此时自动跳回工作台。
- **存哪儿**：`Persist`（eframe 本地配置）而**不是**账套的 `BookOptions`——它是「这台设备上我的界面偏好」不是账套属性，存进 `.fbk` 会跟着备份走，换台电脑打开别人的账套也会被套上。默认值与新老用户分流见 §4.56。
- **测试**：`finui` 4 条 —— 恰好 12 项 / 覆盖日常全链路 / 确实藏起了重模块 / 至少保留工作台。

### 4.55 新手建账向导去术语墙 + 发布包带示例账套

- **`demo` 示例工具**（新增）：`create` 建空壳、`seed` 灌基础档案但**一张凭证都没有**、`demo` 再灌一整月**已记账**业务 —— 采购付货款 / 赊销收货款 / 发工资 / 付房租 / 结转成本 / 缴税共 9 张，借贷平衡、凭证状态 `posted`，打开就能在余额表和三大报表上看到数。演示数据刻意只含商贸业务，不含生产制造（个人记账用不上，也少一层理解成本）。

- **Linux 与 Windows 各自生成一份示例账套**（不用交叉编译跑 example），打包时保持一层目录（不用 `zip -j`），避免中文文件名在 Windows 下乱码。

### 4.56 新手上手：精简模式默认开 + 「先看示例账套」入口

§4.54/§4.55 把菜单和建账页改到位了，但还有两处「东西在那儿，小白够不着」：

- **精简模式默认是关的** —— 小白第一次打开看到的是完整侧栏（47 项），
  要自己在侧栏最底部找到那个勾选框才会变精简。大概率找不到，
  于是第一印象就是「菜单好多，看不懂」，而这恰是精简模式要解决的问题。
- **示例账套也要先登录** —— 他还不知道 `admin/admin123` 是什么，
  点完「打开已有账套」被弹到登录页，第一步就卡住。

改法：

- **A 精简模式按「新老用户」分流**：`Persist::simple_nav` 从裸 `bool` 改成
  `Option<bool>`。`Some(b)` = 用户明确选择，永远优先；`None` = 还没决定，
  此时看 `recent` 是否为空 —— 没打开过任何账套说明是新用户 → 默认精简；
  有历史说明是老用户 → 保持完整菜单（他们的使用习惯是基于完整菜单建立的，
  升级后忽然少一半反而不适应）。退出时 `save()` 把推断值固化成 `Some(b)`。
  - 为什么不用 `#[serde(default = "true")]`：那样老用户升级时也会变精简。
    用 `Option` 才能区分「没这字段」和「明确关了」。
- **C 账套选择页给三个入口**：原来只有「新建账套」「打开已有账套」两个小按钮，
  两个词都要先理解才知道选哪个。新增「👀 先看示例账套」—— 按文件名
  （与 exe 同目录，兼容 macOS `.app`）直接定位，不弹文件选择框，点完直接进主界面。
  「新建账套」同时改名为「建自己的账」。
- **示例账套免登录但只读**：文件名命中 `示例账套.fbk` 时直接注入
  `Role::Viewer` 身份跳过登录页。**必须给只读身份** —— 否则新手随手一改就把
  发布包里的示例数据弄乱，别人下载到的包也跟着变。用文件名而非账套内标记，
  免去一次 schema 迁移；代价是用户若把自己的账套改名成这个名字会拿到免登录
  只读（只影响自己这台机器，顶栏「退出登录」仍可返回选择页，不构成越权）。

- **测试**：`finui` 5 条 —— 新用户默认精简 / 老用户保持原样 / 明确选择优先
  （开关两个方向都验）/ 老版本配置缺字段仍能读 / 存取往返不丢选择。

### 4.57 辅助档案批量粘贴（把 100 次点击变成 1 次粘贴）

「基础资料」分组里最耗时的是辅助档案：一家公司 50 个客户 + 30 个供应商 + 20 个员工，
按原来「新增」按钮一个个敲是 100 次点开、填编码、填名称、保存。而财务手上几乎
一定已经有一份 Excel/WPS 名单 —— 让他们重打一遍是最没必要的重复劳动。

- **入口**：辅助档案页工具栏新增「批量新增」，打开一个多行文本框。
- **两种写法都收**：
  - `编码,名称` 两列 —— 有自己编码体系时用
  - 只写名称 —— **编码自动编号**（C01、C02…），小白多半不知道怎么给档案编编码，
    让他自己填反而是个坎；编号从「库里该前缀的最大号 +1」接着排，不会撞上已有档案
- **分隔符容忍**：Tab（Excel 复制的真实分隔符）、中英文逗号、顿号、连续空格；
  第一行像「编码 / 名称」的表头自动跳过；空行与首尾空格清理掉。
- **必须先「预览」再导入**：预览表格逐行列出编码/名称/状态（将导入 / 跳过：已存在 /
  跳过：本批内重复）。直接点确认就把一坨文本当数据写库，粘贴错位（多带表头、
  带上合计行）会静默变成脏档案。
- **不覆盖已有档案**：新增 `auxs::insert_many_skip_existing`，与既有 `import_many`
  的区别就在那句 `INSERT OR REPLACE` —— 后者会**静默覆盖**同名档案。用户粘一份
  旧 Excel 进来，其中一条编码和库里重了，客户名就被悄悄改掉，而凭证上的历史金额
  对不上任何东西，之后极难排查。这里宁可少导一条、并在返回值和提示里报告跳过了
  哪些，也不替用户做决定。
- **测试**：`finui` 10 条解析（制表符/中文逗号/表头/自动编号接最大号/各类型前缀/
  库内冲突/批内冲突/空行/空输入）+ `findb` 2 条写入语义（不覆盖、空列表）。

### 4.58 期初余额批量粘贴 + 方向自动归位

期初建账页已有「按科目表补全」和「按期末余额倒推」，但前者只是把 199 个
末级科目列出来（数还是要一个个填），后者只在**本账套已有发生额**时有用 ——
而小白的新账套是空的。他的期初数在另一份 Excel（上期余额表）里，
需要的是**从外面贴进来**。

- **入口**：期初页工具栏新增「批量粘贴」。
- **三种写法都收**：
  - `编码,金额` —— 从余额表复制两列，最常用
  - `编码,借/贷,金额` —— 金额恒为正，自己声明方向
  - `编码,借方金额,贷方金额` —— 和 UI 表格同一布局
- **方向自动归位（核心）**：只给金额时，方向从**科目的余额方向**来 ——
  资产记借、负债/权益/收入记贷。小白从余额表抄来的数天然只有一列，
  不区分借贷符号，而「资产=借方、负债=贷方」恰是他最容易错的一步。
  负数/红字和会计报表的括号 `(5000)` 都自动转反方向。
- **抄错码给提示**：编码不在科目表里时标出，并用编辑距离找最接近的
  （`10011` → 「像不像 1001？」），而不是直接吞掉。
- **和辅助档案同样的纪律**：必须先「预览」再导入；库里/草稿里已有的跳过
  （不覆盖）；预览里带本次的借贷合计与差额，粘完先看平不平。
  批量粘贴只是把草稿填好，最终仍由工具栏「保存」统一落库+校验。
- **新建行方向预填**：「添加科目」和「按科目表补全」建出来的行，方向按科目
  预填。以前一律借方 —— 资产确实是借，但负债/权益/收入默认也是借，
  新手照着填完试算必不平，而他还不知道错在哪（方向错了，金额看着都对）。
- **测试**：`finui` 11 条解析（含 `is_header` 从 `any` 改 `all` 的回归 ——
  真实数据行 `1001,贷,5000` 里有个「贷」，`any` 会把它整行吞掉）。

### 4.59 试算不平时标出「嫌疑人」

试算区原来只给三个数：借方合计 / 贷方合计 / 差额。用户看到「差额 5000」
时，面对 199 行不知道从哪查 —— 只能逐行对，这是期初最耗时的环节。

- **只标方向异常**：金额方向与科目余额方向不一致的行（负债放借方、
  资产放贷方）。这是新手期初不平最常见的原因。
- **只在不平时标**：备抵科目、红字余额等合法反方向会被误标 ——
  所以试算平了就不标；标出来的是「嫌疑人」不是「罪犯」，提示条里明说
  「备抵科目、红字余额等合法反方向也会被列出，请自行确认」。
- **两种呈现**：试算区下方列出嫌疑人编码（可点击，点完搜索框自动填该编码、
  列表过滤到那一行）；表格里嫌疑行的编码框标红，200 行里一眼找到。
- **三类不标**：金额为 0（刚补全的空行不能满屏红）、有累计借贷
  （期初数是三项合成，不能简单按方向判）、未知科目（那一列已有红字提示）。
- **测试**：`finui` 5 条，对应上面三类不标 + 两类标出。

### 4.60 会计科目：层级缩进 + 三档排序 + 只看在用

科目页原来是 199 个平铺列表。`1001` 和 `100101` 看不出父子关系，
新手不知道点哪个；199 个里大部分是 0，打开满屏 0 会以为软件没装好。

- **层级缩进**：名称按 `Chart::level` 缩进（最多 3 格，窄屏不吃列），
  下级前面带 `├`/`└`。父级用主题色、末级用深灰，本来就是这么区分的，
  现在加上缩进一眼看出树。
- **排序三档循环**：编码（默认，层级天然有序）→ 名称（找名字快）→ 类别
  （资产/负债/权益分组看）。按钮上直接显示当前档，点一下换一档。
- **只看在用**：有分录、有期初余额的科目；子在用则父也留着（不然树断了）。
  过滤是纯内存操作，不重查库。
- **测试**：`finui` 3 条 —— 三档循环不断 / 每档有中文标签 / 缩进有上限。

### 4.61 常用档案一键预置

**根因**：`validate_entry` 强制要求启用了辅助核算的科目**必须**填辅助核算。
而默认科目表里 `100201~100207` 全部 `aux=Bank`、`6601/6602/6603` 全部
`aux=Dept`。新账套一条档案都没有，于是用户在凭证窗口看到下拉框里只剩
「（不核算）」，只能选它 —— 保存时被拒：
「第 N 行科目 100201 核算银行账户，必须填写银行账户」。
他此刻正站在凭证里，不知道档案页在导航栏哪一层，只能把整张凭证丢掉去翻菜单。

**修法**（三层入口，逻辑共用 `AuxPreset`）：

- **fincore `preset_aux(kind)`**：纯数据清单。
- **findb `insert_presets` / `insert_all_presets`**：沿用
  `insert_many_skip_existing` 的约定 —— **跳过已存在，不覆盖**，返回跳过清单。
  账套跑久了才想起点这个按钮时，库里已有自己的 D01/销售部，静默覆盖就是
  把半年记账口径改掉。
- **finui**：
  - 建账页勾选项「预置常用档案（推荐）」，**默认开**，旁边直接列出条目名。
  - 辅助档案页工具栏「预置常用档案」按钮；库为空走普通确认，已有档案走
    危险确认（明确说「编码相同的不会被覆盖」）。
  - 凭证的辅助核算窗口：该类别一条档案都没有时，红字说明「这张凭证保存不了」
    + 一键预置按钮 + 指出档案页在哪。这条是最关键的 —— 用户正卡在那里。

**只预置部门（销售/管理/财务）和银行账户（基本户/一般户）**，
客户/供应商/存货/职员/项目一律不预置：

- 这两类的名字有通用值，任何公司都成立；
- 其余的名字没有通用值。预置一个「待填客户」会让用户以为它是真客户，
  跟着凭证流进报表，事后自己都想不起来要回来改 —— **比空着更糟**。
  没有的话反而给出「去档案页自己建」的明确指引，不是死路。
- 银行账户预置条目**不带账号**（`bank_account` 留空）：编造的账号会被打进
  对账单和报表。备注里写明「请点开补填开户行和账号」。

预置的每一条都带 `memo` 写清「预置的通用部门，可改名或删除后填自己的」。

**测试**：`fincore` 3 + `findb` 5 + `finui` 3 = 11 条。

### 4.62 试算不平：算解，而不是猜

§4.59 的检查是**语义猜**：拿科目表的方向去比，负债放借方就标出来。它命中不了
三种真实情况 ——

1. 科目表本身标错了方向（把「其他应付款」建成借方），检查反过来指认正确的行；
2. 行上有**累计借贷**时，`年初余额` 是三项合成，代码为避免误判一律放弃检查；
3. 差额压根不是方向问题，而是**只填了一边**（对方科目漏了）。

**解法**：把差额当方程解。一行参与借贷合计的金额是 `s = ±年初余额 + 累计借 − 累计贷`，
试算差额 `diff = Σs`。能改动一行让它归零的改法只有三种，各有充要条件：

| 改法 | 条件 | 一键修复 |
|---|---|---|
| 方向取反 | `diff == 2 × ±年初余额` | 有 |
| 累计借/贷对调 | `diff == 2 × (累计借 − 累计贷)` | 有 |
| 这一行就是差额（其余全平） | `diff == s` | 无（缺的是另一行） |

三个条件都**充要** —— 满足就一定平，不满足就一定不平。所以报出去的每一条
都是**解**，不是「嫌疑人」，用户改完当场验证，不用再猜。只收充要解是有意的：
宁可少报也不要报「大概可能」，新手分不清两者，试一次发现没用，第二次就不信了。

- 前两种给一键按钮（改完立刻重算试算）。
- 第三种只提示「其余行都平了，多半是这笔的对方科目漏填」。
- **兜底**：不管解不解得出来，都给「新增一行 {对方方向} {差额}」—— 金额和方向
  由差额直接算出，用户只需选科目，不用自己算该填多少。
- §4.59 的语义检查**保留**并降级为弱提示：解法不看科目表，语义检查不看算术，
  两者互补（比如数字解说「翻 1002 能平」，语义提示「1002 是资产不该在贷方」）。

**测试**：`finui` 11 条 —— 每条解代回去必归零（充要性）/ 有累计数的行也能定位
（并断言旧检查在这行上会放弃）/ 平了不给解 / 零金额行被跳过 / 补对方方向金额 /
排序稳定 / 不提供无用的修复按钮。

### 4.63 Web 端同步：辅助档案预置

§4.61 的预置能力同步到 Web（`/api/aux-presets` + `renderAux` 的按钮与引导）。

- **清单只有一份**：后端从 `fincore::auxiliary::preset_aux` 取，前端通过
  `GET /api/aux-presets?kind=` 拿，按钮**先 `hidden` 再由响应决定显不显示**。
  这样「哪两类有预置」在前端没有硬编码副本，改一处就够，也不会出现前端说
  「有」而后端返回空、按钮点了没反应。
- **空档案引导**（对齐桌面端凭证窗口的提示）：带该类核算的科目**必须**填这一项
  才能记凭证，没有档案就一张凭证也存不了 —— 直接把这句话写在页面上。
- **无预置的类别明说为什么**：客户/供应商/存货/职员/项目不显示按钮，并在提示里
  写「这几类的名字没有通用值，预置一个假的会跟着凭证进报表」。
- **E2E 1 条**（`e2e/tests/aux-preset.spec.js`）：预置建出 3 部门 + 2 银行账户、
  **再点一次不新增不覆盖**（防 `INSERT OR REPLACE` 悄悄改掉 D01）、
  客户/供应商/存货按钮不存在。

**路由避坑**：`/api/aux/:id` 会把 `presets` 当成 id 吃掉，所以路径用
`/api/aux-presets` 而不是 `/api/aux/presets`。

### 4.64 check-design-doc：行号锚点改成「窗口 + 容差」

CI 挂在 `CI 配置与变异清单自检` —— 这次不是工具坏了，是**它在正常工作**：
`handlers.rs` 的两条锚点从 7310/7311 漂到 7313/7314（我在文件头加了两行注释）。

但暴露了一个真实的设计摩擦：**14000 行的文件里维护精确行号，成本高到会让人
习惯性无视检查**。每新增一个 handler，后面所有锚点都要回来改一遍。一个天天
误报的检查等于没有检查。

**根因**是第一版的容差写错了对象。第一版给了 ±3，注释里写着「容忍漂移等于
没有校验力」—— 那次真正的坑是判据用了**没转义的裸名字**，注释里提到函数名
也被算成命中。现在判据全是 `^\s+` 起头的完整调用式，注释匹配不上。

**改法**：TOLERANCE=20，窗口内命中即过；命中时把实际行号和漂移量一并打出来
（OK 行的信息，不是只在失败时说）。窗口外仍能找到时，报错明确区分两种成因：
「只是无关改动 → 改 REFS.line 即可」/「代码被挪走 → 先确认文档的语义还成不成立」。

**自检同步扩到 4 条**（原来 3 条）：

| 探针 | 证明什么 |
|---|---|
| 锚点内容被改坏 | 窗口不是「随便一行都算过」 |
| 锚点被插 30 行推出窗口 | **容差有界**，不是无限大 |
| 锚点只漂 3 行 | **反向断言**：容差真的有用，否则前两条可能只是「对任何改动都报错」 |
| 文档约束被删 / 未登记引用 | 原有两条不变 |

第三条是新增的关键一条：没有它，前两条变红可能只是因为检查对任何改动都报错
—— 那是噪声不是校验。两条一起才说明「该红的时候红，该绿的时候绿」。

行数漂移的探针数字（30）故意与 TOLERANCE（20）不同步：有人调大容差时这里会
立刻失败，那才是该有的反应。

### 4.65 Web 精简模式：藏起来 ≠ 拿掉

69 个功能平铺 16 组，新用户建完账第一眼看到的是 MRP、工艺路线、预算预警这类
跟他完全无关的东西 —— 他要找「期初建账」得在一屏文字里翻。桌面端已经这么做了
（`NavItem::daily_core`），这里对齐。

**三条不变量**，少一条这个模式就变成了「功能被删了」：

1. **搜索框永远搜全量**。69 项里挑 16 项靠的是「藏起来，不是拿掉」——
   任何人打任意功能名都能搜到并跳过去。搜索的数据源是 `all`（权限过滤后），
   不看这个开关。
2. **路由完全不受影响**。`goView(hash)` 该去哪去哪，精简只决定侧栏画不画出来。
3. **开关随时可切，且按账号分区**（`acctKey`，与收藏/最近一致）—— 一个会计用
   精简，不该影响同一台电脑上出纳看到的菜单。

**默认开，但区分「没设置过」和「显式关掉」**：localStorage 读 `null` → 默认开，
读到 `false` → 尊重用户的关闭。用 `false` 当默认值的话，用户关掉刷新后又被
自己开回来，会以为是坏了。

侧栏铺开列表用 `listed = all.filter(n => SIMPLE_NAV.includes(n.id))`，
即**权限过滤之后**再精简 —— 不能反过来，否则精简会把无权访问的项短暂放出来。

**为什么是 16 项而不是桌面端的 12 项**：Web 把报表拆成了
`balance-sheet` / `income-statement` / `cash-flow` / `reports` 四个导航项，
只留「报表中心」的话新手进利润表得点两次。两边覆盖的功能集合等价，只是切分
粒度不同 —— 别为了凑数字把报表藏起来。

**E2E 2 条**（`e2e/tests/simple-nav.spec.js`）：

- 默认只铺日常功能（生产/预算/库存那一片必须不在）、**搜「MRP」「批次」仍搜得到**、
  开关来回切且**刷新后保持**
- **精简不拦路由**：直接敲 `#/mrp` 仍能进去，且进到页面后侧栏里
  `vouchers` 仍标 `.active`

第二条独立于第一条 —— 万一以后有人在 `goView` 里也加了精简判断，只有它能抓住。

**90 条老 E2E 怎么办**：`newBook` / `loginAs` 里 `addInitScript` 先把
`nav_simple@<账号>` 置 false。这不是在「把测试改成配合实现」—— 精简只决定侧栏
画不画出，不碰路由、权限、页面逻辑；且 `addInitScript` 必须**先于 `goto`**，
否则首屏侧栏已经按默认「精简」渲染了。`loginAs` 要按**登录账号**写 key
（`nav_simple@出纳`），不是 admin 的 —— 账号分区正是为了这个。

### 4.66 check-js：`rest` 的判据从字面改成语义

精简模式给 `rest` 加了一层 `all` → `listed` 的包装，`check-js.js` 就报了
「rest 不再是只排收藏」。但**我的改法完全符合本意**（`listed` 是 `all` 的子集，
谓词没变），报红的是字面匹配：

```js
/const rest = all\.filter\(\(n\) => !favs\.includes\(n\)\);/
```

这类判据的坏处：字面量一变，正确重构就被判成「行为变了」，逼着改动者要么
放弃改进、要么去改检查 —— 越改越僵。改成语义判据：

- `rest` 的谓词里**出现 `recents`** → 报红（本意：最近必须是追加不是搬家）
- `rest` 的谓词里**没有 `favs`** → 报红（否则「常用」会在原分组出现第二份）

`mutate-check` 的 ⑳ 号变异 `from` 串也跟着改成 `listed.filter(…)`。变异清单的
`from` 串必须对齐源码实际写法，否则它「匹配 0 次」会静默失效 ——
`mutate-check` 自己会报「变异已失效」，但没人会因为一条变异失效去看它护着什么。

**这不是放宽检查，是把判据对准它真正要守的不变量。** 变异测试仍然是
「排掉 recents 必须报红」，且变异串已同步更新，验证力没减。

## 5. 关键设计约定

| 主题 | 约定 |
|------|------|
| **金额类型** | 全部 `rust_decimal::Decimal` 运算，零误差；SQLite 存为 TEXT，**绝不 SQL SUM()**，一律 Rust 侧累加；除法一律 `checked_div`（除零返 `None`，**禁止静默 0**，由调用点显式 `expect`（判零守卫）/`unwrap_or(ZERO)`（展示兜底）/报错传播） |
| **余额符号** | **正 = 借，负 = 贷**（全引擎统一，UI 层再按 (方向, 绝对值) 展示） |
| **科目级长** | 4-2-2-2（1001 / 100101 / 10010101 / 1001010101）；建账时设定后不可改 |
| **余额口径（H-3 定案）** | 余额表不物化、实时计算 = 期初余额 + **已记账分录**；科目余额表 / 三大报表 / 试算平衡同此口径（默认 `posted_only=true`）；草稿与已审核未记账一律不入余额。**例外**：期末结转类操作（结转损益/年末结转/预检）按含未记账取数——结转凭证本身是草稿，靠含草稿口径判重防重复结转；账簿提供「只含已记账」开关，取消勾选按「含未记账（排除作废）」查看，行集与期初同口径 |
| **借贷平衡（M-15 定案）** | 分录金额**逐条量化到 2 位（分）**后借贷合计严格相等（`Voucher::balanced`），与落库 `money_param` 口径完全一致——差额 0.005 的「半分尾差」不被放过（否则入库后真差 0.01）。试算平衡按 round2 判定，差额不足 1 分视为平衡。固定口径，不可配置 |
| **凭证状态** | 草稿 → 已审核 → 已记账；**未记账可作废（可恢复）**，已记账需先**反记账**再作废，已记账不能删除；系统生成凭证带来源标记（自动转账/调汇/业务/模板） |
| **存货出库** | 出库行数量为负、单价金额置零，成本由计价引擎（移动加权/FIFO）计算 |
| **附件** | ≤256KB 内联 SQLite BLOB，大文件落账套同目录 `.attachments/`，SHA-256 完整性校验 |
| **权限** | **12 角色**（系统管理员/财务主管/会计/出纳/审核人/订单专员/仓管员/**应收会计/应付会计/成本会计/生产计划员**/只读）+ 细粒度权限项 + 数据范围；**身兼多职**：账号可设主岗位 + 兼任岗位（权限取并集，出纳签字与会计核心仍互斥）；**订单作业 / 仓储作业 / 生产作业 / 成本作业 / 价格查看 / 价格修改** 独立权限位（岗位与科目维护解耦）；**财务报表独立权限 `FinReport`**（账簿/三大报表/试算/资金/成本/预算/发票/银行对账——订单专员、仓管员、生产计划员不可见，业务报表仍走 `Report`，对标金蝶报表按角色授权）；**价格字段权限**：无「价格查看」者订单列表与套打服务端裁掉价格（数量保留），无「价格修改」者改单旧价保留、新行置零；**权限调整（建号 / 改角色 / 权限矩阵 / 数据范围 / 删号）与身份操作（重置口令 / 重置设备 / 解锁停用）仅套内管理员可操作**（持有 `UserManage` 的非管理员一律 403——口令为全局口令，重置即跨账套身份变更）；**导出（`Export`）仅管理员与财务主管**，其余账号只能打印预览 |
| **账号模型** | **二元：管理员 / 普通账号**（无"平台账号"概念）。管理员：新建账套、开通账号、赋予岗位权限、进入全部账套（临时身份不落套内记录）；普通账号：由管理员开通并邀请入套，只参与业务与财务。五层闸按此分层：开号 / 建套 / 邀请入套 / 改授权 / 身份操作（重置口令·设备·解锁）逐层收敛至管理员；**存量普通账号名下的账套于每次启动幂等迁移至最早管理员名下**（`migrate_book_owners_to_admin`，并补该管理员的套内 Admin 成员行） |
| **审计** | 所有写操作（建账/凭证增删改/审核/记账/结账/登录/锁定/超时登出）全部进 `audit_log` |
| **备份** | 复制 `.fbk` 即可；UI 内「备份恢复」一键备份与按备份恢复 |

## 6. 账号开通方式（默认管理员，其余由管理员开通）

新账套内置一个**默认管理员账号**：

| 用户 | 说明 |
|------|------|
| 内置管理员 | 账号 `admin`，默认口令 `admin123`，**首次登录强制改密**；获得全部权限 |
| 其余账号 | 由管理员在「系统 → 用户权限 → 用户管理」开通 |

- **默认管理员**：每个账套建好即内置 `admin` 账号，用默认口令首次登录后必须修改。
  旧版「首登建号」遗留的空用户账套，打开时自动补种该默认管理员。
- **其余账号由管理员开通**：管理员进入「系统 → 用户权限 → 用户管理」，点击「新增用户」填写用户名、
  姓名、角色、初始口令与数据范围即可。新建账号默认**强制首次登录改密**、**自动绑定当前设备**（见 §4.5）。

- 管理员可随时在「用户管理」停用账号、重置口令、重置设备绑定、解锁锁定账号、查看/编辑数据范围。

> 一键重置账套内所有账号口令为 `admin123`（常用于交接 / 忘密）：
> ```bash

> ```

### 两道内控闸门默认都开

新建账套带两道闸门，两道**都默认开启**：

| 闸门 | 字段 | 作用 |
|------|------|------|
| 审核环节 | `BookOptions::enable_audit` | 未审核的凭证不能记账（制单/审核/记账三权分离） |
| 出纳签字 | `BookOptions::require_cashier` | 涉及**现金/银行科目**的凭证记账前须出纳签字 |

出纳签字原来是默认**关**的。改过来的理由：默认关意味着新建账套**一出生就在默认绕过出纳** ——
谁都不必做任何决定，就已经在绕了。审核环节早就是默认开，出纳签字与它保持同一取向：
要关得在账套参数里**显式**关，是一次有意识的决定。

默认值带来的两个必答题，建账向导都会问（少问一个就会有人走不通）：

- **有没有独立的审核人**？没有（比如只有会计 + 出纳、没有财务主管）就选「不启用」，
  否则会计既不能记账也不能审核，凭证会一直卡住。
- **有没有出纳岗**？没有（一个人记账的小微企业）就选「不启用」，否则现金/银行凭证
  永远卡在「需出纳签字」，而没有人能签。

两个问题必须**同时**问，合并成一个会丢掉「有出纳但没主管」这个真实存在的组合 ——
而那个组合需要的正是「关审核、开出纳签字」。

> 单人记账的小微企业在建账向导里把两道都关掉即可；**旧账套不受影响**
> （`#[serde(default)]` 按关闭处理，不追溯改存量账套的操作顺序）。

### 批次登记记到哪一期

库存流水只有一个期间口径：**账套当前期间**。`batch_register` 曾自己算
`Period::from_date(today)`（真实当天），于是：

- 账套停在 2026-01、今天是 2026-10 时，在「批次库位」页登记一笔入库，
  流水落在 **202610**；
- 同一笔货从「库存调整」写进去落在 202601 —— **同一个存货，两个页面，两个期间**；
- 而 `batch_balance` 只按 `(item, batch_no)` 汇总、**不过滤期间**，所以批次台账里
  能看到余额；按期间查的数量金额账 / 分仓库存 / 存货余额表却看不到这一笔。

现在 `period` 由调用方传入（handler 传 `current_period`），`batch_register` 不再自己猜。
生产日期缺省也从「今天」改成「**期间首日**」—— 生产日期 2026-01-10 配期间 202610
是自相矛盾的记录。

> 变异证据：把 `period` 换回 `Period::from_date(today)`，
> `batch_register_uses_given_period_not_today` 立刻红，
> `left: 202610 / right: 202601`。修复前那行代码**确实**是错的。

### 已结账期间拒收（不只凭证）

凭证录入有 `periods::is_open`（未结账 + 不早于建账期）。批次登记走裸 `INSERT`，
**没有这道闸门** —— 可以往已结账的期间塞库存流水，而结账的意义正是
「这个期间的账已经定死了」。这不是理论问题：上面那个期间错配会让它必然发生。

`batch_register` 现在也过 `is_open`，与凭证同一把尺子。
`batch_register_refuses_closed_period` 同时钉住「已结账拒收」与「期内未结账放行」，
后者是对照组 —— 只有拒绝没有放行，测试可能只是被别的原因卡住的。

### 刷新页面后平台管理员菜单消失

侧栏可见性判据 `isNavVisible` 里有 `if (n.platform && !pa) return false`，
而 `pa` 就是 `session.platformAdmin`。那个变量此前**只在两个地方被写过**：
登录响应、`showBookPicker`。刷新页面走的是 `boot()`，两处都不经过，
于是「合并报表」这类 `platform: true` 的菜单项**一按 F5 就消失**。

症状（刷新后少一项菜单）与病根（`boot()` 少一次赋值）隔了三层，
E2E 也一直测不到 —— 每条用例都是登录后直接进账套，不刷新。
现在 `boot()` 从 `/api/books` 取平台身份补一次。

> **不能用 `/api/me` 的 `is_admin`**：那是**账套内**管理员（`PublicUser`，来自
> `Role::Admin`），与平台管理员不是一回事 —— 一个被拉进账套的普通用户若在那套里
> 恰好是 `Role::Admin`，直接用会让他看见合并报表，**越权**。
> `/api/books` 的 `user` 是 `RealmUser`（平台层），`is_admin` 语义才对。

### 一个账号可绑两台设备

平台层的设备绑定上限是 `RealmDb::MAX_DEVICES_PER_USER = 2` 台：

- **不是 1 台**：同一个人两台机器是常态（公司台式机 + 家里笔记本）。锁死 1 台的结果是
  用户隔几天就要找管理员重置一次 —— 一个天天要人工介入的安全功能，实际效果就是被绕过。
- **不是不限**：上限是这个功能**全部**的控制力来源。不限台数等于没有绑定，口令泄露后
  攻击者从任何机器都能登。
- **不做 LRU 自动挤出**：悄悄踢掉用户正在用的那台，比直接拒绝更让人困惑。

配套的一条改动：登录时只顶掉**同一台设备**的旧会话（`remove_by_username_and_device`），
保留其它设备的会话。原先登录会清掉该账号**全部**会话，那样即使允许绑两台，第 2 台一登录
就把第 1 台踢下线 —— 上限只是个数字。

绑定名单存在 `realm_user_device` 表（`PRIMARY KEY (username, device_id)`）。从旧的单列
`realm_user.device_id` **迁移**过来 —— 不迁的话升级后所有账号的绑定会静默消失，等于给
全部用户解绑，症状是「谁都能登」且不报任何错。
### 检查本身也要被验证

静态检查与集成测试最大的失败模式是「写成永远通过的样子」——判据钉的是表象而不是
机制，重构一下代码形状就悄悄失效，而 CI 全绿。所以每加一条行为检查，都要同时加一条变异：

```bash
node tools/check-ci.js --selftest   # 自检自身：改坏 CI 配置/清单/编码/夹具 → 必须报红（13 条）
node tools/mutate-check.js          # 改坏 app.js → check-js 必须报错（18 条）
node tools/mutate-rust.js           # 改坏 Rust   → 对应测试必须失败（17 条）
```

这三个脚本会**先确认变异真的生效**再判成败。变异串没匹配上源码（CRLF/LF、缩进）时
必须单独报「未生效」，不能混进「放过了」—— 这一点是被坑出来的：第一版有 3 条变异
因换行没匹配上而静默无效，结论完全反了。详见 [DEPLOY.md §4.3](DEPLOY.md)。

> 判据要钉**机制**，不要钉**表象**。写检查时先问一句：这条检查在代码被改成另一种
> 同样正确 / 同样错误的写法时，还成立吗？

- `crates/findb/tests/core_loop.rs`（21 个）：建账 → 科目规则 → 期初 → 凭证校验与状态机 → 账簿 → 余额表 → 三大报表 → 结转损益 → 结账/反结账 → 年末结转 → 备份 → 审计日志。

## 9. 已知限制

- **数据范围（DataScope）**：**科目区间 + 仅本人凭证**已统一接入账簿（总账/明细账/多栏账/数量金额账/日记账）、报表（试算平衡/科目余额/辅助余额/自定义报表/三大报表/权益变动/对比/科目日报/财务比率）、期初列表与保存、数字钻取（范围外科目直连端点 **403**、列表不出现）；**部门范围**用于工资列表过滤；无部门/科目字段的业务单据（订单/出入库/发票/收付款）不参与过滤（口径声明）。
- **打印**通过系统默认浏览器预览 + Ctrl/Cmd+P 完成，未对接虚拟打印驱动；导出 Excel/CSV 仅管理员与财务主管可用（普通账号仅能打印）
- **跨账套查询**、**合并报表**未实现
- 附件哈希为 SHA-256 完整性校验（防误删损坏），不防篡改
- 账号设备绑定按"一台账号绑一台设备"设计，管理员可在「用户管理」重置；**不要把同一个 `.fbk` 放在 NFS/SMB 网络盘被多台电脑并发直开**（WAL 在网络文件系统上不稳定，见 §1.1）
- **质检单流程**（对标金蝶质检管理）**已落地基础版**（§4.17：来料质检单、合格判定、不合格自动按订单单价退货冲减库存）；待检状态机（入库先入待检区）、工序质检与不良品隔离库位联动为后续迭代
- **批次成本勾稽 / 批次盘点 / 批次调拨联动**待立项：批次主数据、自动批号、FEFO 推荐、临期预警、库位主数据与登记已落地（见 §4.1「批次与库位」）；批次级成本分摊与批次盘点维度为后续迭代
- **销售成本结转 Web 入口与口径**待立项：`stock_cost_voucher`（借6401/贷1405）仅桌面可触发、Web 无按钮；且其数据源 `stock_summary` 的"出库"= 期间全部负流水（**含领料/形态转换出**）——制造业账下直接结转会虚增主营业务成本，需按 kind 过滤（sale-only 或分离在产品）后再开放 Web 按钮
- **款到发货（先款后货）开关**待立项（用户方案 B）：发货端点校验订单已收金额 ≥ 本次发货金额否则 400；粒度二选一——客户级（往来档案 props）或账套全局参数

## 10.1 Windows 保留设备名适配（aux 模块重命名）

本仓库在推送到 GitHub 前做过一次**模块重命名**，原因与影响说明如下：

- **原因**：原源码中有两个文件名为 `aux.rs`（`crates/fincore/src/aux.rs` 与 `crates/finui/src/views/aux.rs`）。
  `aux` 是 Windows 的保留设备名（类似 `con`/`prn`/`nul`），git 在 Windows 上默认开启 `core.protectNTFS`，
  会拒绝索引这类路径，导致 `git add` 直接失败、无法提交/推送。
- **处理**：
  - `crates/fincore/src/aux.rs` → **`crates/fincore/src/auxiliary.rs`**，模块声明 `pub mod auxiliary`；
  - `crates/finui/src/views/aux.rs` → **`crates/finui/src/views/aux_view.rs`**，模块声明 `pub mod aux_view`；
  - 同步更新了 4 处引用：`crates/fincore/src/lib.rs`、`crates/findb/src/mgmt.rs`（测试）、
    `crates/finui/src/views/mod.rs`、`crates/finui/src/views/aux_view.rs`。
- **验证**：重命名后 `cargo check --workspace` 编译通过（无新增警告）。
- **克隆注意事项**：在 Windows 上克隆 / 编译本项目时，请以 `auxiliary.rs` / `aux_view.rs` 为准，
  不要再把文件改回 `aux.rs`，否则会再次触发同一问题。对外 API 不变（`fincore::auxiliary::AuxEntity`、
  `fincore::auxiliary::validate_aux` 等），`findb::auxs` 模块名本就合法、未受影响。
